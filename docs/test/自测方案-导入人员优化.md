# 自测方案 · 导入人员优化

依据 [需求梳理版](../detail/需求-导入人员优化-梳理版.md)、[技术设计](../design/技术设计-导入人员优化.md) 和 [开发计划](../plan/开发计划-导入人员优化.md)。本文只规定怎么测，不改代码。

本地自测核对预览和确认两个接口的路由、入参、出参和写库结果。校对页好不好改，由使用人自行看，不作为通过条件。

## 测试范围

| 纳入 | 不纳入 |
|---|---|
| 字段清洗和跨图去重的纯函数 | 编辑距离、只差一个字自动合并 |
| 预览只返回行，不写人员、不存原图 | 20 张图打进一次对话 |
| 确认按校对行新增或整行覆盖 | 从图片抄排名，或按评分重算排名 |
| 空字段清空旧值；未出现的人不改 | 校对页新增人员、改俱乐部、改通知绑定 |
| 看图失败、0 行、缺 `rows` 时不写库 | 预览时把原图存成服务端草稿 |
| 无权俱乐部不能预览、也不能确认 | 删除 `parse-member-table` 等旧整理函数 |
| 任务识别路由仍在 | 人员列表手工增删改的原有用例 |
| 未登录不能调用这两个接口 | 全站性能、并发压测、窄屏布局 |

## 环境与前置

| 项 | 要求 |
|---|---|
| 数据库 | PostgreSQL 已有 `members`、`import_batches`，本需求不新增迁移 |
| API | NestJS 已启动，前缀 `/api/v1` |
| 预览成功 | `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 可用，且该模型能看图。只用于 PV-04 |
| 预览失败 | PV-06 去掉 `AI_API_KEY` 后重启。测完恢复 |
| 账号甲 | 能访问「星辰俱乐部」 |
| 账号乙 | 不能访问「星辰俱乐部」 |
| 已有人员 | 「星辰俱乐部」里有玩家「旧人」。`rank` 为 3，`previousRank` 为 1，`score` 为 100，`level` 为 8。另有玩家「旁人」，本次确认不会带上他 |
| 成员表截图 | 一张含成员表的 PNG、JPEG 或 WebP，记为图 A。图中至少能读出一名玩家 |
| 对照图 | 一张不含成员表的 PNG，记为图 B |
| 小图 | 任意合法小 PNG，记为图 C。确认接口不识图，用它避免重复上传大图 |

下面「预览」表示 `POST /api/v1/clubs/{星辰俱乐部}/imports/preview`，表单字段 `files`。「确认」表示 `POST /api/v1/clubs/{星辰俱乐部}/imports`，表单字段 `files` 和 `rows`。`rows` 是 JSON 文本。除未登录用例外，请求带甲的 JWT。每条会写库的用例开始前，记下「旧人」「旁人」的字段，以及 `import_batches` 里该俱乐部的条数。

## 用例

### 清洗与去重

不调用模型，不写库。跑开发计划 P4 的单元测试。

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| UT-01 | UC-03、验收 3、4 | 输入一条没有玩家名称的行，以及等级为 0、评分为 0 的行 | 无名称的行被丢掉。等级 0 变成 null。评分 0 保留 |
| UT-02 | Q6 | 模型行里带有排名 | 清洗结果没有可写入的排名 |
| UT-03 | UC-02、验收 2、Q2 | 两张图分别给出「张三」和「 张三 」，后者字段更多；另有「李四」 | 只保留一条张三，名称用字段更多那条的原文并去掉首尾空格。李四单独留下 |
| UT-04 | UC-02 | 同一名称两张图的非空字段数相同 | 保留上传更早那张图里的一条 |

### 预览

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| PV-01 | 未登录 | 不带 JWT 预览图 A | 401。无新的人员行，无新的导入批次 |
| PV-02 | UC-07、验收 10 | 乙预览甲的俱乐部，文件为图 A | 404，提示俱乐部不存在。星辰俱乐部的人员和导入批次不变 |
| PV-03 | 上传约束 | 甲不传文件；再传一个 txt；再传图 A 和一张超过 10MB 的图 | 三次都是 400。不调用模型，人员和导入批次不变 |
| PV-04 | UC-01、验收 1 | 甲只上传图 A | 200。`rows` 至少一条。每条有 `playerName`，以及等级、途径、非凡评分、风尚度、周活跃、入会时间，这些字段允许为 null。响应里没有排名。此时「旧人」「旁人」不变，导入批次条数不变，存储里没有这批原图 |
| PV-05 | UC-06、验收 3、9 | 甲只上传图 B | 422。不返回可确认的人员行。人员和导入批次不变 |
| PV-06 | UC-06、验收 9、Q1 | 去掉 `AI_API_KEY` 并重启后，甲上传图 A | 502。人员和导入批次不变。不因为 OCR 可用而改走识别服务 |

PV-04 的具体姓名以这张图为准。同一张图再预览一次，人数可以不同，但两次都不得写库。模型看图失败时 PV-04 记为未测，不能用 OCR 结果充数。

### 确认

确认用例用手工 `rows`，不依赖 PV-04 的模型输出。图片用图 C，除非该用例本身在测文件。

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| CF-01 | 旧客户端 | 只传图 C，不传 `rows` | 400。人员和导入批次不变 |
| CF-02 | 验收 8 | `rows` 为 `[{ "playerName": "  " }]` | 400。不写库 |
| CF-03 | 验收 8、Q2 | `rows` 含「新人甲」和「新人甲 」两条，其余字段合法 | 400。库里没有「新人甲」 |
| CF-04 | UC-05、验收 5、Q6 | `rows` 为一条「新人乙」，等级 10，评分 20，入会时间「26天」，并多带 `"rank": 9`。文件为图 C | 200。`rowCount` 为 1，`imageCount` 为 1。库中「新人乙」排名为 0，等级 10，评分 20，入会时间为「26天」，`previousScore` 为空。导入批次新增一条，`rowCount` 为 1。「旧人」「旁人」不变 |
| CF-05 | UC-05、验收 5、6、Q3 | `rows` 只含「旧人」。评分改为 80，等级为 null，其他可选字段为 null，不带排名 | 200。「旧人」评分变为 80，`previousScore` 为 100，等级变为空。`rank` 仍为 3，`previousRank` 仍为 1。「旁人」不变。`dataUpdatedAt` 比确认前新 |
| CF-06 | UC-04、验收 7 | 预览得到多行后，确认时去掉其中一行再提交 | 200。去掉的那名玩家不新增、不覆盖。本次提交的行按 CF-04、CF-05 的规则写入 |
| CF-07 | UC-07、验收 10 | 乙对星辰俱乐部提交一条合法 `rows` 和图 C | 404。人员和导入批次不变 |
| CF-08 | 上传失败前 | `rows` 合法，但文件不是图片 | 400。不上传，不写人员，不增加导入批次 |

CF-06 若 PV-04 未测，改为：确认体只含「旧人」，检查「旁人」未被改写。这仍覆盖「本次没有的人不改」。

### 页面

使用人打开「导入人员」自行看，不作为通过条件。

| 看什么 | 期望 |
|---|---|
| 选图文案 | 说明由 AI 直接读图，确认后才写入 |
| 未选俱乐部 | 不能开始识别 |
| 预览成功 | 同一页出现校对表，列为玩家名称、等级、途径、非凡评分、风尚度、周活跃、入会时间。没有排名，没有新增按钮 |
| 空值说明 | 页面写明留空确认后会清空旧值 |
| 取消 | 回到选图，人员列表与识别前一致 |
| 确认成功 | 提示写入条数，校对表清空 |

## 通过与失败

同时满足下面各项才算这版自测通过：

1. UT-01 至 UT-04 全部通过。
2. PV-01 至 PV-03、PV-05、PV-06，以及 CF-01 至 CF-08 的期望都出现。
3. PV-04 返回人员行，且该请求结束后人员和导入批次与请求前一致。
4. CF-04、CF-05 之后，数据库中的排名、上次评分、空字段和未出现的人与上表一致。
5. 任务识别路由仍在：已登录请求 `POST /api/v1/tasks/{一个不存在的 uuid}/recognize`，得到的是任务业务错误，而不是没有这个路由。

任一 Must 用例失败即整版不通过。模型不能看图时，只允许 PV-06 按 502 通过；PV-04 记为未测，整版不算通过。CF-01 至 CF-08 不依赖模型，仍须通过。

## 回归要点

| 项 | 期望 |
|---|---|
| 人员列表 | `GET /api/v1/members?clubId={星辰俱乐部}` 仍返回「旧人」「旁人」。手工新增、修改、删除的路由还在 |
| 任务 OCR | `POST /api/v1/tasks/:taskId/recognize` 仍挂在任务模块上。人员预览返回 502 时，不要求改调这个接口 |
| 旧导入 | 只上传文件、不带 `rows` 的确认请求是 400，不会再直接入库 |
| 表结构 | 不需要新的迁移。`members.rank` 仍是必填整数 |
