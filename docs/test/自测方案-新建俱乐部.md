# 自测方案 · 新建俱乐部

依据 [需求梳理版](../detail/需求-新建俱乐部-梳理版.md)、[技术设计](../design/技术设计-新建俱乐部.md) 和 [开发计划](../plan/开发计划-新建俱乐部.md)。本文只规定怎么测，不改代码。

## 测试范围

| 纳入 | 不纳入 |
|---|---|
| 俱乐部增删改查，含空名称、重名、有人员时删除 | 职位、分组、当前状态是否识别正确 |
| 导入成功后的人员字段、所属俱乐部、数据更新时间 | 入会时间按天数排序 |
| 导入失败时旧人员不变 | 人员手工新增、编辑、删除 |
| 再次导入后的排名、评分升降 | 删除旧的任务数据表 |
| 人员列表的俱乐部筛选、玩家名称关键字、九列表头排序 | 玩家改名后的身份合并 |
| 任务、模板页面和菜单已不可用 | 全站性能和并发压测 |
| 表格整理纯函数的单元测试 | 未登录用户的新账号体系 |

界面自测覆盖登录、三个新页面，以及桌面宽度和约 390px 窄屏。窄屏只确认菜单和主按钮仍可点，不要求列宽与桌面一致。

## 环境与前置

| 项 | 要求 |
|---|---|
| 数据库 | PostgreSQL 已迁移，存在 `clubs`、`members`、`import_batches` |
| API | NestJS 已启动，浏览器通过 `/api` 访问 |
| Web | Vite 已启动，可打开登录页 |
| 账号 | 两个已登录账号，记为甲、乙。用于确认俱乐部互不可见 |
| 识别服务 | 成功导入用例开始前，OCR `GET /health` 为就绪。测 502 的用例单独停掉该服务 |
| 样例图 | `assets/微信图片_20261010140035_72.jpg` |
| 对照图 | 另一张不含「玩家名称」表头的图片，或任意不含成员表的 PNG，用于 0 行失败 |

样例图预期能读出的玩家包括：奶得加钱（排名 64）、无忧十三郎（排名 1）。等级、途径、非凡评分、风尚度、周活跃、入会时间以该次 OCR 实际读到的文字为准，同一张图连续导入两次，这些字段应一致。排名使用图中的数字，不按评分重算。

## 用例

### 表格整理

不启动 OCR，只跑整理函数的单元测试。

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| UT-01 | UC-04、Q3 | 输入含「玩家名称」表头，以及名称左侧带排名的多行文字框 | 输出多行；排名等于左侧整数；列对应等级、途径、非凡评分、风尚度、周活跃、入会时间 |
| UT-02 | Q6 | 其中一行只有职位、没有玩家名称 | 该行不在结果里 |
| UT-03 | Q10 | 没有「玩家名称」表头，或每行都缺名称或排名 | 有效行数为 0 |
| UT-04 | UC-04 | 有名称和排名，非凡评分单元格为空 | 该行保留，评分为空 |

### 俱乐部

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| CL-01 | UC-01、验收 1 | 甲登录 | 侧栏是「俱乐部管理」，子菜单为创建俱乐部、导入人员、人员列表。没有任务、模板、新建任务 |
| CL-02 | UC-02、验收 2 | 名称为空保存；再只填名称、会长留空保存 | 空名称被拒绝并留在当前页。会长为空的俱乐部出现在列表中 |
| CL-03 | UC-03、Q9 | 再创建一个同名俱乐部 | 被拒绝。列表仍只有一条该名称 |
| CL-04 | UC-03、Q8 | 修改名称和会长为任意文本 | 列表显示新名称和新会长 |
| CL-05 | Q7、验收 2 | 该俱乐部还没有人员时删除 | 列表中消失 |
| CL-06 | 归属 | 乙登录后打开俱乐部列表，并直接请求甲的俱乐部 id | 乙看不到甲的俱乐部。接口返回 404 |

### 导入

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| IM-01 | Q11 | 打开导入页，不选俱乐部 | 不能上传。不产生人员记录 |
| IM-02 | UC-04、验收 3、4 | 甲选中自己的俱乐部，上传样例图 | 提示写入条数大于 0。人员列表能看到奶得加钱、无忧十三郎；俱乐部名称等于所选俱乐部；每条有数据更新时间。图中没读到的列可以为空 |
| IM-03 | Q3 | 查看上述两人的排名 | 奶得加钱为 64，无忧十三郎为 1。不因为评分更高而改成更小的排名 |
| IM-04 | Q1 | 导入前先记下另一名已存在、但本次样例图未包含的玩家 | 导入后该玩家仍在，排名和评分不变 |
| IM-05 | Q10 | 对同一俱乐部上传对照图 | 导入失败。IM-02 写入的人员排名、评分、更新时间都不变，导入批次不增加 |
| IM-06 | 技术设计 502 | 停掉 OCR 服务后，再上传样例图 | 导入失败。人员与导入前一致。恢复 OCR 服务 |
| IM-07 | 验收 5、Q4 | 把无忧十三郎的当前排名、评分记下来。用能够识别出同一名称、且排名或评分不同的第二张图再导入；若暂时没有第二张图，则在测试库把该玩家的排名和评分改成与样例图不同的值后，再导入样例图 | 该玩家只保留一行。更新时间变新。排名数字变小显示向上箭头和差值；变大显示向下箭头和差值。评分变大向上，变小向下。与上次相同的那一项不显示箭头 |
| IM-08 | Q2 | 导入一个名称从未出现过的玩家 | 新行没有升降箭头 |
| IM-09 | Q7 | 对已有人员的俱乐部点删除 | 删除被拒绝，人员和俱乐部都还在 |

IM-07 的第二张图不是本仓库的必需素材。没有第二张图时，允许先改库中的上次排名和评分，再导入样例图，用来验证升降计算；这不能代替「OCR 又读出一行」的检查，所以 IM-02 仍必须真实上传样例图。

## 通过与失败

同时满足下面各项才算这版自测通过：

1. UT-01 至 UT-04 全部通过。
2. CL-01 至 CL-06、IM-01 至 IM-09、LS-01 至 LS-06、RT-01、RT-02 的期望都出现。
3. IM-05、IM-06 之后，数据库中的人员行与操作前一致。
4. 样例图导入结果里，排名 64 和排名 1 的玩家名称与上表一致。

任一 Must 用例失败即整版不通过。OCR 服务当时没启动，只允许 IM-06 按失败路径通过；IM-02、IM-03、IM-07 记为未测，整版不算通过。

## 回归要点

| 项 | 期望 |
|---|---|
| 登录、注册 | 未登录打开 `/clubs` 会到登录页。注册或登录后进入 `/clubs` |
| 已去掉的文案 | 页面上不出现「商品清单，从容核对」，也不出现「演示账号 demo@example.com / Demo123456」 |
| 外观 | 新页面仍是浅蓝色 Element Plus。人员列表是表格，不是手写的另一套表格 |
| 窄屏 | 宽度约 390px 时，三个子菜单仍能点到，导入按钮在未选俱乐部时仍不可用 |
| 旧数据表 | 迁移后原任务表可以还在库里。页面和接口都不再读取它们 |
