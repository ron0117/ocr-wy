# 自测方案 · 俱乐部数据采集

依据 [需求梳理版](../detail/需求-俱乐部数据采集-梳理版.md)、[技术设计](../design/技术设计-俱乐部数据采集.md)、[开发计划](../plan/开发计划-俱乐部数据采集.md)。本文只规定怎么测，不改代码。

通过条件是 **最小 HTTP 请求**。采集页选文件、表格配色、窄屏滚动由使用人自己看，**不作为通过条件**。不写、不跑自动化测试或浏览器走查。

## 测试范围

| 纳入 | 不纳入 |
|---|---|
| `GET /api/v1/club-rankings` | 识别 `rank.png` |
| `PUT /api/v1/admin/club-rankings` | 展示 `capturedAt`、`rawText`、二维码 |
| `POST /api/v1/club-rankings`（仅超管） | 排行历史、名次升降 |
| `GET /api/v1/permission` 是否带出菜单 | 把菜单分给普通角色后的页面点击 |
| `POST /api/v1/roles` 拒绝该菜单 key | 签到人员的导入、编辑 |
| Guide `GET /`、`GET /club-rankings` 的 HTML | Playwright、手工点选文件 |

## 环境与前置

| 项 | 要求 |
|---|---|
| Guide 库 | 已执行 `club_ranking_current` 迁移 |
| Guide API | `GUIDE_API_PORT` 默认 **3001**，前缀 `/api/v1` |
| OCR API | `PORT` 默认 **3000**，前缀 `/api/v1` |
| Guide 前台 | Next 已启动，默认 **3002** |
| 管理凭证 | 与 guide-api 进程的 `GUIDE_ADMIN_TOKEN` 相同。不要把凭证写进本文 |
| 账号 | 一个超管、一个非超管。非超管至少能登录并调用 `GET /permission` |
| 样例 | `docs/俱乐部数据/club-ranking-2026-11-03.json` 里的 `clubs`（50 条） |

记：

- `GUIDE` = `http://127.0.0.1:3001/api/v1`
- `OCR` = `http://127.0.0.1:3000/api/v1`
- `WEB` = `http://127.0.0.1:3002`
- `$ADMIN` = `Authorization: Bearer <GUIDE_ADMIN_TOKEN>`
- `$SUPER` = 超管 `POST {OCR}/auth/login` 返回的 `token`，请求头 `Authorization: Bearer <token>`
- `$USER` = 非超管的同样头

样例里用来对答案的三行（以 JSON 为准，不按截图改字）：

| rank | name | server | leader | memberCount | score |
|---|---|---|---|---|---|
| 1 | 墨渊 | 灰雾之上 | 深海瞳 | 80 | 16928892 |
| 2 | 魔女丨原初 | 魔女 | 钟鱼 | 80 | 16904735 |
| 11 | 无忧俱乐部 | 征服者 | 无忧十.. | 80 | 16354692 |

一条合法的单行，后面覆盖用：

```json
{
  "clubs": [
    {
      "rank": 1,
      "name": "自测俱乐部",
      "server": "灰雾之上",
      "leader": "自测会长",
      "memberCount": 1,
      "score": 1
    }
  ]
}
```

测写入之前先记一次：`$SUPER` 调用 `GET {OCR}/clubs` 的条数，以及 `GET {OCR}/members` 的条数。测完再比，必须相同。

## 用例

### 公开读取与写入（验收 2、3、4、5）

无数据时先做 RD-01。库里已经有 `current` 行时，RD-01 标「已有数据，跳过」，从 RD-02 开始，不算失败。

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| RD-01 | 验收 5 / UC-07 | `GET {GUIDE}/club-rankings`，无登录 | 200；`clubs` 为 `[]`；响应里没有 `updatedAt`、`capturedAt`、`rawText` |
| RD-02 | 验收 2 / UC-02、UC-05 | `PUT {GUIDE}/admin/club-rankings`，头 `$ADMIN`，体为样例的 `{ clubs }` | 200；`{ "count": 50 }` |
| RD-03 | 验收 2 | 再 `GET {GUIDE}/club-rankings` | 200；长度 50；按 `rank` 从 1 到 50；第 1、2、11 条与上表一致，含 `丨` 和 `..`；`score` 是数字 `16928892`，不是带逗号的字符串 |
| RD-04 | 验收 3 / Q2 | `PUT`，`clubs: []` | **400**；再 GET，仍是 RD-03 的 50 条 |
| RD-05 | 验收 3 | `PUT`，缺 `clubs`，或 `clubs` 不是数组 | **400**；GET 仍是 50 条 |
| RD-06 | 验收 3 | 样例中把第 1 条 `name` 改成 `""` 或 `"   "` | **400**；GET 仍是 50 条，第 1 条仍是「墨渊」 |
| RD-07 | — | 两条 `rank` 都是 1，其余字段合法 | **400**；GET 不变 |
| RD-08 | Q3 | 201 条合法俱乐部（`rank` 从 1 到 201） | **400**；GET 不变 |
| RD-09 | — | `score` 为 `1.5`，或 `memberCount` 为 `"80"` | **400**；GET 不变 |
| RD-10 | — | `name` 为 `"  墨渊  "`，只这一条，其余字段合法 | 200；`count` 为 1；GET 的 `name` 为「墨渊」（去掉首尾空白） |
| RD-11 | 验收 4 / UC-06 | `PUT` 上面的「自测俱乐部」单行 | 200；`count` 为 1；GET 只有这一条 |
| RD-12 | — | `PUT` 时 `clubs` 里先放 `rank: 2` 再放 `rank: 1`，两条都合法 | 200；GET 先是 `rank: 1` |
| RD-13 | — | 不带 `$ADMIN`，或 Bearer 错误，`PUT` 一条合法数据 | **401**；GET 仍是 RD-12 的结果 |

RD-10 会换成 1 条。RD-11、RD-12 在它之后执行。RD-04～RD-09 必须放在 RD-03 之后、RD-10 之前，这样「不覆盖」对的是那 50 条。

### 后台代理与权限（验收 1、6）

先用 RD-11 留好一条已知数据，再测本段。本段失败时 GET 仍应是那一条。

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| AD-01 | UC-02 | `$SUPER` `POST {OCR}/club-rankings`，体为样例 `{ clubs }` | 200；`{ "count": 50 }`；随后 GET 为 50 条，且与 RD-03 的三行一致 |
| AD-02 | 验收 1 | `$USER` 对同一地址 POST 一条合法 `clubs` | **403**；GET 仍是 AD-01 的 50 条 |
| AD-03 | 验收 1 | 不带登录头 POST | **401** |
| AD-04 | 验收 3 | `$SUPER` POST `{ "clubs": [] }` | **400**；GET 仍是 50 条 |
| AD-05 | 验收 1 / UC-01 | `$SUPER` `GET {OCR}/permission` | 200；某个菜单子项的 `key` 为 `club-ranking-import`，`title` 为「俱乐部数据采集」，`path` 为 `/club-ranking-import` |
| AD-06 | 验收 1 | `$USER` `GET {OCR}/permission` | 200；全部子项的 `key` 都不是 `club-ranking-import` |
| AD-07 | 验收 1 | `$SUPER` `POST {OCR}/roles`，`menuKeys` 含 `club-ranking-import`，其余字段用一条能通过校验的角色名和 `clubIds: []` | **400**；不产生带这个 key 的角色 |
| AD-08 | 验收 6 | 再 `GET {OCR}/clubs` 与 `GET {OCR}/members`（`$SUPER`） | 条数与开测前记下的相同 |

停掉 guide-api 或拿掉 OCR API 进程里的 `GUIDE_ADMIN_TOKEN` 后再 POST，期望 **502** 或 **503**，且 Guide 库里的当前榜不变。测完恢复进程。这条不作为每次必测，只在改代理时抽查。

Web 是单页应用，直接请求 `http://127.0.0.1:5777/club-ranking-import` 往往仍是同一份壳，**不能**用来证明非超管进不去。权限以 AD-02、AD-05、AD-06、AD-07 为准。

### Guide 页面（验收 4、5）

在 AD-01 的 50 条还在时测 PG。页面上千分位只看 HTML 里有没有分隔后的评分。

| ID | 对应 | 步骤 | 期望 |
|---|---|---|---|
| PG-01 | 验收 5 / UC-04 | `GET {WEB}/` | 200；正文含「俱乐部排行」，链接到 `/club-rankings` |
| PG-02 | 验收 2 / UC-05 | `GET {WEB}/club-rankings` | 200；含「墨渊」「魔女丨原初」「无忧十..」「16,928,892」；不含「掌上诡秘」、不含样例里的 `rawText` 整段 |
| PG-03 | 验收 5 / UC-07 | 在库中删掉 `club_ranking_current` 这一行后，再 `GET {WEB}/club-rankings` | 200；含「暂无排行」。测完用 AD-01 写回，避免把环境留空 |

没有数据库客户端时，PG-03 标「未删行，跳过」。空数据以写入前的 RD-01 为准。不要为了空态去调用未定义的删除接口。

## 通过 / 失败标准

**通过**须同时满足：

1. RD-02～RD-13、AD-01～AD-08、PG-01、PG-02 的期望全部符合。
2. RD-01 通过，或注明已有数据并跳过。
3. PG-03 通过，或注明未删行并跳过，且 RD-01 已在写入前看过空数组。
4. 开测前后 `GET /clubs`、`GET /members` 条数相同。

**失败**：空 `clubs`、缺字段、重复 `rank` 仍返回成功；失败之后 GET 条数或第 1 名变了；非超管 POST 返回 200；`GET /permission` 给非超管带上 `club-ranking-import`；`POST /roles` 接受了这个 key；GET 的 `score` 变成带逗号的字符串；响应里出现 `rawText` 或 `updatedAt`。

## 回归要点

- 只改了校验函数：重跑 RD-04、RD-06、RD-07、RD-09、AD-04。
- 只改了代理或超管判断：重跑 AD-01、AD-02、AD-05。
- 只改了排行页：重跑 PG-01、PG-02。
- 签到俱乐部：`GET {OCR}/clubs` 仍 200，响应项仍是原来的 `id`、`name`，不出现 `memberCount` 这种排行字段。
- `prisma/schema.prisma` 的 `Club`、`Member` 不在本次 diff 里。若 diff 改了这两处，本方案视为范围被破坏，先停测。
