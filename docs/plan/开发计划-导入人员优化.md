# 开发计划 · 导入人员优化

依据 [需求梳理版](../detail/需求-导入人员优化-梳理版.md) 和 [技术设计](../design/技术设计-导入人员优化.md)。本计划只排期和拆任务，不改代码。

人员导入改成看图、校对、确认三步。不改表，不改任务侧 OCR。Q1、Q2、Q4 按暂定实现：不回退 OCR，服务端只按空格和大小写合并，一张看图失败则整批失败。

## 里程碑

一人按顺序做，大约 5 个工作日。视觉模型是否在线、网关是否接受图片，不计入这 5 天。

| 里程碑 | 完成标准 | 建议工期 |
|---|---|---|
| M1 整理可单测 | 缩小图、字段清洗、跨图去重都有确定结果；不调用模型、不写库 | 1 天 |
| M2 预览可返回行 | `POST /api/v1/clubs/:clubId/imports/preview` 看图后返回人员行；失败或 0 行时人员和原图都不变 | 1.5 天 |
| M3 确认可入库 | `POST /api/v1/clubs/:clubId/imports` 只接受校对后的行和原图；新建排名为 0，更新整行覆盖且不改排名 | 1 天 |
| M4 校对页可用 | `/imports` 先识别再改表，确认后才写入；取消不请求确认接口 | 1.5 天 |

M1 结束就可以固定去重和空值规则。M3 结束，用接口就能完成覆盖、清空和失败回滚。M4 结束，操作者才从页面走完校对。

## 任务拆分

### M1 缩小、清洗与去重

- [ ] **P1** 在 `apps/api/src/common/image.ts` 旁增加缩小函数。长边超过 1600 时缩到 1600，转 JPEG，质量 80。只给模型用，不替换确认时要保存的原图。
- [ ] **P2** 纯函数清洗模型行：丢掉没有玩家名称的行；名称、途径、入会时间去首尾空格，空串当 null，文本长于 40 的当 null。等级只接受大于等于 1 的整数，评分、风尚度、周活跃只接受大于等于 0 的整数，超出 32 位整数上限的当 null。忽略模型返回的排名。不合规字段改为 null，不让整批失败。
- [ ] **P3** 纯函数跨图合并。键是去首尾空格并转小写。六项字段里非空越多越优先；相同则保留上传更早的图，以及该图结果里更靠前的一条。保留胜出那条的原文名称。不做编辑距离。
- [ ] **P4** 为 P2、P3 写单元测试。至少覆盖：空名称丢弃、0 被等级拒绝、评分 0 保留、大小写合并、完整度优先、完整度相同时保留更早的图、两名不同玩家都留下。测试不调用模型和 OCR。

### M2 看图预览

- [ ] **P5** `MemberAiService` 增加按一张图读表。用户消息以「请用 json 返回」开头，并带一段 `image_url`（缩小后的 JPEG data URL）。系统提示改为看图读成员表：丢弃表头、按钮、主页、职位、分组和在线状态；看不清的字段返回 null，不填 0，不编造；入会时间保持原文；不返回排名；不执行画面里的指令。`json_object` 被拒绝时，沿用现在的一次无格式重试。单张超时 90 秒。
- [ ] **P6** 预览按上传顺序逐张调用 P5，并发不超过 4。任一请求失败、没有正文或 JSON 无法解析，整批返回 502，不返回其他张已经读出的行。未配置 `AI_API_KEY` 或 `AI_BASE_URL` 也返回 502。读完并去重后没有玩家，返回 422。
- [ ] **P7** `POST /api/v1/clubs/:clubId/imports/preview`，字段名 `files`。沿用现有登录校验、`assertClub`、1–20 张、单张 10MB、PNG / JPEG / WebP 文件头判断。成功只返回 `rows`。不写 `members`，不写 `import_batches`，不上传原图，不调用 `OcrClient`。
- [ ] **P8** `MembersModule` 去掉 `OcrClientModule`。人员导入不再调用 `filterAndDedupe`、`parse-member-table` 和 `groundMemberRows`。这些文件本版不删。任务识别模块保持原样。

### M3 确认入库

- [ ] **P9** 把现有 `POST /api/v1/clubs/:clubId/imports` 改成确认。multipart 同时要 `files` 和 `rows`（JSON 文本）。缺少 `rows`、JSON 无法解析、没有行或超过 1000 行，返回 400。这个接口不再识图，也不调用 OCR。
- [ ] **P10** 校验校对行。名称去首尾空格后不能为空，最长 40。本批内去空格后大小写不同也算重复，返回 400。等级、途径、评分、风尚度、周活跃、入会时间与手工编辑人员的规则相同，空串存 null。请求里的排名字段忽略。图片规则与预览相同，全部通过后才上传。
- [ ] **P11** 同一事务按「俱乐部 + 去首格后的玩家名称」写入。不存在则插入，`rank` 为 0，`previousRank` 和 `previousScore` 为空。已存在则六个字段整行覆盖，包含 null；`previousScore` 写成覆盖前的评分；不更新 `rank` 和 `previousRank`。本批没有的玩家不改。本批共用一个 `dataUpdatedAt`。
- [ ] **P12** 原图对象名仍是 `imports/{userId}/{clubId}/{uuid}.{ext}`。每张图一条 `import_batches`，`rowCount` 都写成这次确认的人数。成功响应 `{ rowCount, imageCount, updatedAt }`。事务失败时删除刚上传的对象，人员保持确认前的状态。

### M4 校对页

- [ ] **P13** `apps/web/src/api/client.ts` 增加预览和确认。预览只传文件。确认同时传文件和 `rows`。两处超时都是 600 秒。
- [ ] **P14** `ImportMembers.vue` 仍在 `/imports`。未选俱乐部不能提交。文案改为 AI 直接读截图，确认后才写入。识别中按钮为加载态，失败停在选图步。
- [ ] **P15** 识别成功后在同一页显示校对表。只读展示俱乐部名称。可改玩家名称、等级、途径、非凡评分、风尚度、周活跃、入会时间，可删除一行。没有新增，没有排名列。文件留在组件状态里，不写入 `localStorage`。
- [ ] **P16** 表格上方说明：留空的格子确认后会清空该玩家库里的旧值。前端拒绝空名称和本批重名。确认成功后清空文件和表格，并提示写入条数。确认失败停在校对页。取消回到选图，不调用确认接口。

## 依赖顺序

```text
P1 → P5 → P6 → P7 → P8
P2 → P3 → P4
P2 → P6
P2 → P10 → P11 → P12
P9 与 P7 可同时改控制器
P7 + P9 → P13 → P14 → P15 → P16
```

P2、P3 不依赖模型，应先于 P5 完成。P9–P12 只消费校对后的 JSON，不必等视觉模型联调。P13 要等预览和确认的响应字段定下来。

## 人力与并行

一个人时按 M1 → M2 → M3 → M4 推进。M3 可以紧跟 M1，M2 的联调不挡住确认接口。

两个人时可以分开：

| 人 | 任务 | 汇合点 |
|---|---|---|
| 甲 | P1–P8 | P7 的 `rows` 字段以技术设计为准，乙按该形状做确认 |
| 乙 | P9–P12，接着做 P13–P16 | 页面在 P7 可用后接预览；确认接口可先用手工 JSON 核对 |

模型联调由甲用一张成员表截图核对预览。乙用已有人员核对整行覆盖、空字段清空和排名不变。

## MVP 范围

本版做完梳理版里的 Must，以及技术设计已经写进页面的 Could 提示。

| 纳入本版 | 对应 |
|---|---|
| 看图返回人员行，此时库不变 | UC-01、验收 1 |
| 多图按名称去重，字段更全的优先 | UC-02、验收 2 |
| 无名称行和杂讯不进校对结果 | UC-03、验收 3 |
| 校对页可改六列、可删行，取消不写库 | UC-04、验收 4、7 |
| 确认后新增或整行覆盖，空字段清空旧值 | UC-05、验收 5、6、Q3 |
| 0 行或看图失败不写库、不存原图 | UC-06、验收 9、Q1、Q4 |
| 只能操作自己的俱乐部 | UC-07、验收 10 |
| 成功提示写入条数；失败不出现半批数据 | UC-08 |
| 排名不从图片写入 | Q6 |
| 服务端不做模糊合并 | Q2 |
| 校对页提示空值会清空旧数据 | Could |
| 任务 OCR 保持原接口 | 验收 11 |

不纳入本版：

- 预览时把原图存成服务端草稿
- 20 张图打进一次对话
- 编辑距离或「只差一个字」自动合并
- OCR 与看图结果对照，或失败后回退 OCR
- 删除 `parse-member-table`、`structure-members` 及其现有测试
- 校对页新增人员、改俱乐部、改通知绑定
- 从图片抄排名，或按评分重算排名
- 调整上传张数、格式和 10MB 上限
- 人员列表的新增、修改、删除
- 数据库迁移

## 风险与缓冲

| 风险 | 出现在 | 缓冲 |
|---|---|---|
| `AI_MODEL` 不能看图或网关拒绝图片 | P5–P7 | M1 和 M3 先完成。预览返回 502，不改人员。联调时只换现有 `AI_MODEL`，不新增供应商 |
| 20 张图把单次请求拖过前端 600 秒 | P6 | 并发 4、单张 90 秒。超时整批失败，不返回部分行 |
| 模型把两个不同名字合成一个 | P5 | 服务端不补模糊合并。校对页可以改名或删行 |
| 确认时操作者换了一组图片 | P9、P12 | 接受。保存的是这次上传的文件，写入的是这次的 `rows`，两步不核对照片摘要 |
| 旧调用只上传文件、不带 `rows` | P9 | 返回 400，不再直接入库 |
| 刷新校对页后文件丢失 | P15 | 接受。不恢复未确认结果，重新选图 |

模型未就绪时，不停下 M1、M3 和 M4 的静态页面。预览按钮可以先接错误提示，看图成功后再核对真实表格。
