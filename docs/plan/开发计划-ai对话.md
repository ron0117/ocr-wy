# 开发计划 · AI 对话（小忧）

依据 [需求梳理版](../detail/需求-ai对话-梳理版.md) 和 [技术设计](../design/技术设计-ai对话.md)。本计划只排期和拆任务，不改代码。

小忧是后台里的业务助手。模型只识别意图和俱乐部名称。查询、权限和 Excel 由现有后台完成。对管理员怎么说，写在 `apps/api/src/xiaoyou/skills/` 的文稿里，不写进查询和导出。

## 里程碑

一人按顺序做，大约 7 个工作日。模型服务不稳定时，不把联调耗时算进这 7 天；基础模式在 M2 结束时就要能导出。

| 里程碑 | 完成标准 | 建议工期 |
|---|---|---|
| M1 文稿和表可用 | 技能能填出各场景的句子；四张助手表已迁移；现有俱乐部、人员和识单接口不受影响 | 1 天 |
| M2 基础模式能查询 | 不配置模型时，固定句式可以列俱乐部、问人数和更新时间、处理重名和近似名称 | 2 天 |
| M3 文件能下载 | 唯一俱乐部可生成人员 Excel；空数据不产生文件；下载会再查权限和 24 小时有效期 | 1.5 天 |
| M4 模型只认意图 | 配置了模型时走 JSON 意图；失败或输出不合格时退回 M2 的句式，并说明是自己在认话 | 1 天 |
| M5 页面能对话 | 已登录后台可打开小忧、发送、下载、新对话；关掉再打开仍能看到刚才的回复 | 1.5 天 |

M2 结束就可以用接口完成验收里的查询、歧义和无权限。M3 结束导出主路径固定。M5 结束管理员才从页面走完。模型是否在线不作为 M2、M3 的完成标准。

## 任务拆分

### M1 技能文稿与表

- [ ] **P1** Prisma 增加 `assistant_sessions`、`assistant_messages`、`assistant_tool_calls`、`assistant_exports`。会话保存当前俱乐部 ID、待确认 JSON 和处理中的请求号。消息保存角色、正文、场景和请求号。工具调用保存工具名、俱乐部 ID、结果、错误码和耗时，不保存人员行。导出保存存储路径、文件名、人数、过期时间和状态。
- [ ] **P2** 会话按用户和更新时间查询。消息的「会话 + 请求号」唯一。消息、工具调用和导出写入时带 `userId`，读取时必须和会话的用户一致。
- [ ] **P3** 写入 `voice`、`intent` 和各场景 `SKILL.md`。场景覆盖帮助、无菜单、俱乐部列表、请选择、请确认、找不到、没有人员、导出成功、导出失败、摘要、基础模式、文件不可用。模板只留空位。必留原句包括「没有找到你可访问的相关俱乐部，请检查名称后重试」和「暂无可导出的人员数据」。
- [ ] **P4** API 启动时读入这些文稿。缺文件，或填空后丢掉必留词、没出现「小忧」和「管理员」、带出工具结果以外的俱乐部名称，就改用该场景的内置兜底句，不因此去查库或生成文件。

### M2 会话、匹配与只读查询

- [ ] **P5** 新增 `xiaoyou` 模块并挂到现有应用。接口都走现有 JWT，用户只取 `CurrentUser`。
- [ ] **P6** `GET /api/v1/assistant/session` 返回当前用户最近一个会话、最近消息，以及是否仍在生成。没有会话时不自动创建。`POST /api/v1/assistant/sessions` 开始新对话，旧的当前俱乐部和待确认不再沿用。
- [ ] **P7** `POST /api/v1/assistant/sessions/:id/messages` 接收 `text` 和 `clientRequestId`。超过 500 字拒绝。每个用户每分钟最多 20 次，计数放在本进程内存。同一请求号只处理一次。先写入用户消息；该会话正在处理另一条时，不启动第二次工具调用。
- [ ] **P8** 俱乐部匹配只用 `AccessService.clubWhere`。先比去掉首尾空白后的全名。一个全名就记下俱乐部 ID。多个全名，或多个名称互相包含，记下候选。没有全名且只有一个互相包含时，记为待确认。一个都没有时走找不到。不做编辑距离，不用模型补名称。同名候选带上会长。
- [ ] **P9** 会话已有待确认时，先本地解释序号、全名、只能对上一家的名称片段，以及「是 / 不是」。能选定才写入当前俱乐部 ID。对不上就保持候选，不导出。这一步不调用模型。
- [ ] **P10** 本地句式识别「导出 / 下载 …… 俱乐部 ……」、可访问俱乐部、人数、更新时间，以及询问小忧会做什么。导出名称从「导出 / 下载」和「俱乐部」之间截取。截不出意图或名称时只回复帮助。
- [ ] **P11** 实现 `list_clubs`、`find_club`、`get_club_summary`。后两个和导出都要求超级管理员或 `menuKeys` 含 `members`，否则只回复无菜单，不查俱乐部。帮助不检查这个菜单。摘要包含名称、会长、人数和最新人员数据更新时间。没有人员时人数为 0，并说明暂无更新时间。
- [ ] **P12** 工具结果只通过场景文稿填空后写入助手消息。未点名另一家时，「导出」「有多少人」沿用会话里的俱乐部 ID，执行前再次 `assertClub`。
- [ ] **P13** 每次工具调用写 `assistant_tool_calls`。日志不包含模型密钥、登录令牌和人员明细。

### M3 导出与下载

- [ ] **P14** 用 API 已有的 `xlsx` 生成工作表「人员名单」。列顺序为排名、玩家名称、俱乐部名称、等级、途径、非凡评分、风尚度、周活跃、入会时间、数据更新时间、企业微信角色绑定状态。文本列走 `asExcelText`。排名为 0 的单元格留空，并排在有排名的行后面。非凡评分只写数字。绑定状态写已绑定或未绑定。
- [ ] **P15** 文件名为 `俱乐部名称-人员名单-YYYYMMDD-HHmmss.xlsx`。时间和数据更新时间用 Asia/Shanghai。俱乐部名称去掉 `\ / : * ? " < > |`。没有人员时不写存储、不建导出记录，回复没有人员。
- [ ] **P16** 文件放到 `assistant/{userId}/{exportId}.xlsx`，过期时间为生成后 24 小时。生成失败时记失败的工具调用，回复可以再试，响应里没有下载 ID。
- [ ] **P17** `GET /api/v1/assistant/exports/:id` 同时检查当前用户、导出记录归属、未过期和 `assertClub`。通过后按记录中的文件名返回附件。失败时不返回文件内容。面板用文件不可用的场景说明，用户仍有权限时可以再发一条导出。
- [ ] **P18** 不修改人员列表页的 `export-members.ts`，也不把识单的 `AiService` 接进小忧。

### M4 模型意图与降级

- [ ] **P19** 已配置 `AI_API_KEY` 时，用 `intent` 文稿请求 JSON。只接受 `tool` 和可选的 `clubName`。超时、请求失败、不是对象、工具不在白名单或多了字段，都改为 P10 的本地句式。
- [ ] **P20** 本次走了本地句式时，在场景句前加上基础模式说明。未配置密钥时不发起模型请求，直接本地识别。
- [ ] **P21** 发给模型的内容只有意图文稿、本会话里已经授权的俱乐部名称和用户这一句。不发送人员行、令牌和其他用户的俱乐部。模型返回的用户 ID、角色 ID、俱乐部 ID 丢弃。`clubName` 仍交给 P8。
- [ ] **P22** 模型失败只影响这一次小忧回复。人员导入和识单整理继续使用原来的 AI 调用。

### M5 对话面板

- [ ] **P23** 在 `AppShell` 增加 `XiaoyouPanel`。已登录后台页可见，不进侧栏。企业微信活动页 `/a/:id` 不放。
- [ ] **P24** 面板有名称「小忧」、消息区、输入框、发送、新对话和生成中状态。Enter 发送，Shift + Enter 换行。生成中不能再次发送。
- [ ] **P25** 导出成功的消息显示下载按钮。点击时带当前 JWT 请求 P17，再由浏览器保存文件。
- [ ] **P26** 关闭面板只隐藏界面。再次打开重新读取当前会话。服务端仍在写消息时显示生成中，写完后能看到那句回复。
- [ ] **P27** 窄屏下面板贴底展开，退出按钮仍可点。

## 依赖顺序

```text
P1 → P2 → P5 → P6 → P7
P3 → P4 → P12
P5 → P8 → P9 → P10 → P11 → P12 → P13
P8 + P11 → P14 → P15 → P16 → P17
P10 → P19 → P20 → P21 → P22
P6 + P7 + P17 → P23 → P24 → P25 → P26 → P27
P14 不依赖 P19
```

P3、P4 可以和 P1 并行。P14 在匹配和权限可用后就能做，不必等模型。P23 要等发送和下载的响应字段定下来。

## 人力与并行

一个人时按 M1 → M2 → M3 → M4 → M5 推进。M4 放在导出之后，避免页面先绑上一套还会改的模型回复。

两个人时可以分开：

| 人 | 任务 | 汇合点 |
|---|---|---|
| 甲 | P1、P2、P5–P18 | P7 的响应字段定下后，乙才能接面板 |
| 乙 | P3、P4；接着在甲完成 P7 后做 P19–P22 和 P23–P27 | 场景句以乙的文稿为准，甲只接填空结果 |

模型联调由一个人用固定句式核对降级。另一人用两家同名或近似俱乐部核对候选，并用无权俱乐部核对找不到的原句。

## MVP 范围

本版做完梳理版里的 Must，以及技术设计已经写明的 Should。

| 纳入本版 | 对应 |
|---|---|
| 已登录页打开小忧 | UC-01 |
| 唯一俱乐部导出人员表 | UC-02、验收 1 |
| 多家候选先选择，近似匹配先确认 | UC-03、验收 2、Q2、Q6 |
| 无权俱乐部不泄露 | UC-04、验收 3 |
| 没有人员不生成文件 | UC-05、验收 4 |
| 可访问俱乐部、人数、更新时间和基本信息 | UC-06、UC-07、UC-08、Q5 |
| 短上下文按俱乐部 ID 继续 | UC-09 |
| 历史只属于当前用户 | UC-10、验收 7 |
| 模型不可用时固定句式仍可导出 | UC-11、验收 5 |
| 下载再查归属、有效期和权限 | UC-12、验收 6、Q3 |
| 帮助与团宠说法 | UC-13、UC-14、验收 10、Q9 |
| 同一请求不生成两份文件；关掉面板不丢回复 | UC-15、验收 9 |
| 窄屏可用 | UC-16 |
| 工具调用可追溯 | UC-17 |
| 没有人员列表菜单不能查人和导出 | Q1 |
| 排名 0 视为未填 | Q4 |
| 人员列表页导出保持原样 | Q7 |
| 500 字、每分钟 20 次、会话内同时一条 | Q8 |

不纳入本版：

- 开放聊天、联网搜索、语音、数字人
- 长期记忆、用户画像、跨账号共享
- 自由 SQL、执行代码、未登记工具
- 用对话新增、修改、删除俱乐部或人员
- 用对话创建活动、发通知或发企业微信消息
- 知识库、向量检索、模型训练
- 让模型改写已经填好的回复
- 把技能放到 `.cursor/skills`
- 自定义列、多俱乐部合并导出、统计问答、周报
- Redis、BullMQ，以及过期文件的定时清理

## 风险与缓冲

| 风险 | 出现在 | 缓冲 |
|---|---|---|
| 模型服务没有密钥或超时 | P19–P22 | M2 的本地句式先完成。联调模型另用现有环境，不挡住 M3 和 M5 |
| 文稿写进具体俱乐部或人数 | P3、P4 | 填空后做必留词和名称检查，不合格用兜底句 |
| 两家俱乐部同名或名称互相包含 | P8、P9 | 不自动导出。候选带会长，确认后只存 ID |
| 用户在生成过程中关掉面板 | P7、P26 | 服务端写完再结束。面板再次打开只负责读取 |
| 导出后角色被取消该俱乐部 | P17 | 下载前 `assertClub`，失败不读文件 |
| 多开 API 时每分钟 20 次各自计算 | P7 | 接受与当前无 Redis 的部署相同。审计表仍记录实际调用 |
| 基础模式把闲聊当成导出 | P10 | 只有固定导出句式且俱乐部已唯一或已确认时才生成文件 |

模型未就绪时，不停下 M1–M3 和 M5。页面先接基础模式，模型意图顺延到 P19。
