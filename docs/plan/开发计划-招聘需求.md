# 开发计划 · 招聘需求

依据 [需求梳理版](../detail/需求-招聘需求-梳理版.md) 和 [技术设计](../design/技术设计-招聘需求.md)。本计划只排期和拆任务，不改代码。

已读用 `readAt` 是否为空表示。同意和不同意只改 `applications.decision`，不写 `members`。

## 里程碑

一人按顺序做，大约 2 个工作日。没有 OCR、导入或外部通知，不另留识别缓冲。

| 里程碑 | 完成标准 | 建议工期 |
|---|---|---|
| M1 公开接口可提交 | 不带令牌能拉到全部俱乐部的 id 和名称，并能写入一条未读、待处理的申请；缺项和工会不存在时不插入 | 0.5 天 |
| M2 管理接口与菜单 | 有菜单的账号能按未读 / 已读列表、打开详情后变已读、把状态改成同意或不同意；无菜单返回 403；人员表不变 | 0.5 天 |
| M3 两个页面 | `/apply` 不进管理壳；申请列表在「招聘管理」下可用，失败反馈和成功清空都符合设计 | 1 天 |

M1 结束可以用接口提交申请。M2 结束管理端主路径在接口层走通。M3 结束才算申请人页面和管理员页面都可用。

## 任务拆分

### M1 公开接口

- [ ] **P1** Prisma 增加枚举 `ApplicationDecision`（`PENDING`、`APPROVED`、`REJECTED`）和表 `applications`。`clubId` 可空，外键 `onDelete: SetNull`。保存提交时的 `clubName`。`gameName`、`uid`、`reason` 为文本，`score` 为整数，`decision` 默认 `PENDING`，`readAt` 可空。索引 `(clubId, readAt, createdAt)`。`Club` 只增加反向关系。不改 `members`，也不改删除俱乐部的人数和活动判断。
- [ ] **P2** 新模块 `applications` 注册进 `AppModule`。公开控制器不挂 `JwtAuthGuard`、`MenuGuard`。
- [ ] **P3** `GET /api/v1/apply/clubs`。返回全部俱乐部的 `{ id, name }`，按名称排序。没有俱乐部时返回空数组。响应里没有会长、人员或其他字段。
- [ ] **P4** `POST /api/v1/apply`。正文为 `gameName`、`score`、`uid`、`clubId`、`reason`。去掉首尾空白后，游戏名称和 uid 非空且最长 64，理由非空且最长 500，评分为 0 到 2147483647 的整数，`clubId` 为 UUID v4。空白、超长、非整数、多余字段返回 400，不插入。
- [ ] **P5** 俱乐部不存在时返回 400，文案「所选工会不存在」，不插入。存在则写入一行：`decision = PENDING`，`readAt` 为空，`clubName` 抄当时的名称。成功响应 `{ ok: true }`。同一 uid 再提交一次会多一行。公开接口的成功和失败都不返回 401。

### M2 管理接口与菜单

- [ ] **P6** 在 `MENU_CATALOG` 的「俱乐部管理」和「系统管理」之间加入大菜单「招聘管理」，子菜单 key 为 `applications`，标题「申请列表」，路径 `/applications`。不改超级角色的 `role_menus` 数据；超级管理员登录时仍按 `MENU_KEYS` 展开。
- [ ] **P7** 管理控制器使用 `JwtAuthGuard`、`MenuGuard` 和 `@RequireMenu('applications')`。无令牌 401。有令牌但没有该菜单 403，文案「没有权限」。
- [ ] **P8** `GET /api/v1/applications?read=unread|read`。缺省或其他值 400。未读是 `readAt` 为空，已读是有值。按 `createdAt` 降序返回范围内全部行，不分页。每行含 `id`、`gameName`、`score`、`uid`、`clubName`、`createdAt`、`read`、`decision`，不含 `reason`。这个接口不写 `readAt`。
- [ ] **P9** 超级管理员看全部申请。其他账号只用 `AccessService.clubWhere` 过滤 `clubId`。不可见或不存在的 id 在详情和更新里都返回 404，文案「申请不存在」。`clubId` 已空的行只有超级管理员可见。
- [ ] **P10** `GET /api/v1/applications/:id`。可见才返回。`readAt` 为空时写成当前时间，已有值则不改。响应在列表字段上增加 `reason`，且 `read` 为 `true`。俱乐部仍在时 `clubName` 用当前名称，已删除时用提交时抄下的名称。
- [ ] **P11** `PATCH /api/v1/applications/:id`，正文只接受 `decision` 为 `APPROVED` 或 `REJECTED`。`PENDING` 和其他值返回 400。只更新 `decision`，不改 `readAt`，不注入、不调用人员服务。

### M3 页面

- [ ] **P12** `api/client.ts` 增加五个调用：公开俱乐部列表、提交申请、申请列表、申请详情、更新处理状态。继续用现有 `api` 实例和 `errorMessage`。
- [ ] **P13** 路由 `/apply` 放在 `AppShell` 之外，`meta.public` 为真。页面为居中卡片，展示「无忧大家庭欢迎你的加入~」。表单五项必填：游戏名称、非凡评分、uid、工会下拉、理由。主按钮提交。结果用 `el-alert`。成功后清空表单。失败保留已填内容，不跳转登录。
- [ ] **P14** 路由 `/applications` 挂在壳内，`meta.menu` 为 `applications`。无此菜单时沿用现有守卫，回到该账号的第一个可用菜单。侧栏出现「招聘管理 / 申请列表」，图标沿用非系统菜单的建筑图标。
- [ ] **P15** 申请列表默认请求未读。用切换看未读和已读。表格展示列表字段，枚举显示为待处理、同意、不同意。行内「同意」「不同意」只调用 `PATCH`，不请求详情。
- [ ] **P16** 「详情」打开 `el-dialog` 并请求详情接口。对话框展示五项、提交时间、已读、处理状态，以及同意、不同意。关闭后按当前档重新拉列表。
- [ ] **P17** 角色管理不改页面结构，确认新菜单出现在勾选列表中。用一个没有 `applications` 的角色验证侧栏和直接访问 `/applications` 都被挡住。
- [ ] **P18** 接口核对：无令牌调用两个公开接口；缺项、工会不存在、合法提交；无菜单访问管理接口得到 403；打开详情后未读变已读；同意或不同意后 `members` 行数不变；删除一个没有人员和活动的俱乐部后，已有申请仍能由超级管理员看到当时的工会名称。

## 依赖顺序

```text
P1 → P2 → P3 → P4 → P5
P1 → P6 → P7 → P8 → P9 → P10 → P11
P5 + P11 → P12 → P13
P6 + P12 → P14 → P15 → P16
P6 → P17
P13 + P16 + P17 → P18
```

P3 和 P6 在 P1 之后可以并行。P13 只依赖公开接口和客户端，可以在管理页面之前做。

## 人力与并行

一个人时按 P1 → P5 → P11 → P13 → P16 → P18 推进。

两个人时可以分开：

| 人 | 任务 | 汇合点 |
|---|---|---|
| 甲 | P1–P5，然后 P7–P11 | P1 完成后乙才能接菜单和页面所依赖的字段 |
| 乙 | P6、P12–P17 | P5、P11 的响应形状定下后，乙把页面接到真实接口 |

P18 由一个人从公开页提交走到管理端标记，另一人核对人员表和俱乐部删除结果。

## MVP 范围

本版一次做完梳理版里的 Must，以及设计里已经写明的校验和权限。

| 纳入本版 | 对应 |
|---|---|
| 公开申请页、五项必填、成功和失败反馈 | UC-01 至 UC-05 |
| 不带登录凭证的俱乐部列表 | UC-04 |
| 「招聘管理 / 申请列表」及菜单权限 | UC-06 |
| 未读 / 已读、详情、同意 / 不同意 | UC-07 至 UC-09 |
| 处理结果不写人员表 | UC-08 |
| 失败原因、列表上的处理状态 | 梳理版 Should，技术设计已定文案和字段 |

不纳入本版：

- 按工会或处理状态筛选、分页
- 编辑已提交内容、删除申请、导出
- 申请人查询进度、处理结果通知
- 验证码、企业微信身份
- 同意后写入人员列表
- 修改现有俱乐部删除条件

## 风险与缓冲

| 风险 | 出现在 | 缓冲 |
|---|---|---|
| 公开接口误挂登录守卫，过期令牌把申请人带到 `/login` | P2、P5、P13 | P18 用一份过期或任意令牌调用公开接口，确认不是 401，页面也不跳转 |
| 列表渲染时顺手请求详情，整表变成已读 | P15、P16 | 表格只绑定列表接口；P18 先看未读列表，确认条数不变，再点一条详情 |
| `PATCH` 被接到人员新增 | P11 | 模块不引用 `MembersService`。P18 记录标记前后的人员行数 |
| 申请外键挡住俱乐部删除 | P1 | 外键使用 `SetNull`。P18 只删没有人员和活动的俱乐部，确认删除仍成功 |
| 非超级角色勾选菜单后看到其他俱乐部的申请 | P9、P17 | P18 用只分配了一个俱乐部的角色，确认看不到另一个俱乐部的申请 |

这些检查都放在 P18，不另加一天。P18 若发现人员行数变化或公开接口返回 401，先停页面调整，回到 P5 或 P11。
