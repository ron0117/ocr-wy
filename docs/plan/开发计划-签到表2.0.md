# 开发计划 · 签到表 2.0

依据 [需求梳理版](../detail/需求-签到表2.0-梳理版.md) 和 [技术设计](../design/技术设计-签到表2.0.md)。小忧不改造。本计划只拆任务，执行开发时另开实现任务。

## 里程碑

一人按顺序做，大约 **5～6 个工作日**。

| 里程碑 | 完成标准 | 建议工期 |
|---|---|---|
| M1 报名数据就绪 | 新表与枚举已迁移；`shared-types` 职业/状态 label 可用 | 0.5 天 |
| M2 公开报名 API | 公开 GET/POST 可通；IP 限流、唯一约束、ENDED 拒绝；trust proxy 就绪 | 1 天 |
| M3 活动查看 API | 全量活动下拉、列表筛选排序、PATCH/DELETE；卸 attendance 接口 | 1 天 |
| M4 members 清理 | 导入不再 NEED_RENAME/认领/同步 attendance；删人逻辑简化 | 0.5～1 天 |
| M5 后台页面 | 活动签到链接/二维码/跳转；活动查看 CRUD+导出；菜单全员注入 | 1.5 天 |
| M6 公开页 | `/a/:id` 无壳表单；可嵌入组件；移动端可用 | 1 天 |

M2 结束可用 curl/Postman 完成公开报名。M3+M5 可部分并行（API 先定 DTO）。M4 与 M3 无强依赖，可在 M2 后并行。M6 依赖 M2 接口。

## 任务拆分

### M1 数据与共享类型

- [ ] **P1** Prisma：新增 `ActivityRegistration`、`RegistrationProfession`、`RegistrationAttendanceStatus`；`activities` 增加 `registrations` 关系；`onDelete: Cascade`；唯一 `(activityId, clubId, playerName)`；索引 `(activityId, createdAt)`、`(activityId, submitIp)`。执行 migration。
- [ ] **P2** `packages/shared-types`：`PROFESSION_OPTIONS`、`REGISTRATION_STATUS_LABEL`（或等价常量）；若扩展 `MenuKey`，增加 `activity-registrations`；定义 `ALWAYS_VISIBLE_MENU_KEYS`（仅 permission 注入，角色页不展示）。

### M2 公开报名

- [ ] **P3** 新建 `ActivityRegistrationsModule`（或拆 `public` + `admin` 两个 Controller 同模块）：`PublicActivitiesController`。
- [ ] **P4** `GET /api/v1/public/activities/:id`：404/200；返回 title、startsAt、status、clubs（id+name）。
- [ ] **P5** `POST /api/v1/public/activities/:id/registrations`：DTO 校验；IP 提取 helper；校验顺序按技术设计；错误文案「当前活动已报名」「您已报名多次，报名失败」「活动已结束，无法报名」。
- [ ] **P6** `main.ts`（或 Nest 工厂）确认 `trust proxy` 与反向代理文档一致；本地无代理时用 `req.ip` 仍可测。

### M3 活动查看 API 与 activities 调整

- [ ] **P7** `ActivityRegistrationsController`：`GET activity-registrations/activities` 全量活动、`publishedAt desc`；仅 `JwtAuthGuard`。
- [ ] **P8** `GET activity-registrations`：必填 `activityId`；可选 `clubId`、`sortBy`、`sortOrder`；join club 名；默认 `createdAt desc`。
- [ ] **P9** `PATCH /activity-registrations/:id`：可改 clubId、playerName、score、profession、attendanceStatus；俱乐部须属该活动；唯一冲突 409。
- [ ] **P10** `DELETE /activity-registrations/:id`。
- [ ] **P11** 删除 `ActivitiesController` 的 `GET/PUT :id/attendance` 及 `ActivitiesService.attendance/saveAttendance`；清理 `SaveAttendanceDto` 等无用 DTO。
- [ ] **P12**（可选）`GET/PATCH activities` 列表项或详情增加 `publicUrl`（读 `WEB_ORIGIN` + `/a/{id}`）。

### M4 members 清理

- [ ] **P13** 导入确认：去掉 `activityAttendance.groupBy`、`NEED_RENAME` 409、`renames` 参数处理、`syncAttendanceName`、`claimAttendances`；缺失人员直接 `deleteMany`（保持「本次未出现则删除」现网规则）。
- [ ] **P14** `members.update` 去掉 `syncAttendanceName`（若有）。
- [ ] **P15** `ImportMembers.vue`：去掉对照弹窗与 `renames` 重提交逻辑。
- [ ] **P16** 确认 `members.activities()` 仍只查 `activity_attendances`，无需改小忧。

### M5 后台 Web

- [ ] **P17** `MENU_CATALOG` 增加「活动查看」`/activity-registrations`；`permission` 响应注入 `activity-registrations`；`Roles.vue` 过滤 `ALWAYS_VISIBLE_MENU_KEYS`。
- [ ] **P18** `router.ts`：`/activity-registrations`；`beforeEach` 对已登录放行 `activity-registrations` 不校验 menu 集合。
- [ ] **P19** `Activities.vue`：删除签到弹窗与 client API；增加「报名链接/二维码」对话框（依赖 `qrcode` 或同类）；增加「活动人员列表查看」跳转 query。
- [ ] **P20** `ActivityRegistrations.vue`：活动/俱乐部筛选；表格排序回调调 API；行内编辑/删除/出席三态 PATCH；空态与默认最新活动。
- [ ] **P21** `export-activity-registrations.ts` + 导出按钮；列与筛选对齐 `export-members.ts` 版式。
- [ ] **P22** `api/client.ts`：公开接口（若后台要测可不加 token）、registrations CRUD、去掉 `activityAttendance/saveActivityAttendance`。

### M6 公开 Web

- [ ] **P23** `ActivitySignupForm.vue` + `ActivitySignup.vue`；路由 `/a/:activityId`，`meta.public`。
- [ ] **P24** 样式：窄屏、可 `embedded`；ENDED 禁用；提交 `MessageBox.confirm`。
- [ ] **P25** `App.vue` / 布局确认公开页不渲染 `XiaoyouPanel`（与 ai 对话设计一致）。

## 依赖顺序

```text
P1 → P2
P1 → P4 → P5
P3 与 P4 同模块，P3 可与 P1 并行搭骨架
P5 → P23 → P24
P1 → P7 → P8 → P9 → P10
P11 可与 P7 并行（删旧接口）
P12 可选，依赖 activities present
P13 → P14 → P15（P13 依赖 P11 前仍可改 members，但与 attendance API 无耦合）
P2 → P17 → P18
P8 + P22 → P20 → P21
P19 可与 P20 并行（不同文件）
P5 + P22 → P19
P25 最后扫一眼即可
```

建议实施顺序：**P1 → P2 → P3～P6 → P7～P11 → P22 → P19～P21 → P23～P25 → P13～P15**（M4 可在 M5 页面开发期间插入）。

## 风险与缓冲

| 风险 | 缓冲 |
|---|---|
| 前后端 `WEB_ORIGIN` 不一致 | P12 后端 `publicUrl`；.env 文档 |
| 导入去掉对照后误删有旧 attendance 的人 | 产品已定；仅旧活跃度仍可见历史 attendance |
| 活动查看全员可见含 IP | 导出同权限；接受或后续列权限 |
| 并发 IP 第 6 条 | 首版 count+insert；问题再现加强锁 |
| 卸 attendance 与前端同发 | 同一版本发布 API+Web |
