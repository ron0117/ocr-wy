# 技术设计 · 新建俱乐部

依据 [需求梳理版](../detail/需求-新建俱乐部-梳理版.md) 的暂定结论（Q1–Q11）。本版只定方案，不改代码。

## 目标与约束

登录后的后台只做俱乐部维护、成员截图导入和人员列表。任务、模板、对话整理和 Excel 导出从页面和接口下线。

沿用现有技术栈，不新增中间件：

| 已有能力 | 本需求中的用法 |
|---|---|
| Vue 3 + Element Plus + Vue Router | 三个子页面和浅蓝色界面 |
| NestJS + JWT | 俱乐部、导入、人员接口；继续校验登录用户 |
| PostgreSQL + Prisma | 新增俱乐部与人员表 |
| 本地文件存储 | 保存本次上传的截图 |
| Python PaddleOCR `POST /recognize` | 只返回文字行和坐标，不改 OCR 服务协议 |

约束：

- 俱乐部和人员按当前登录用户隔离，和其他人的数据互不可见。这沿用现有「资源归属当前用户」的做法，梳理版没有要求做成全站共用数据。
- 截图可能只拍到部分成员。导入只新增或更新本次识别到的玩家，不删除本次没出现的玩家。
- 排名、评分的升降在写入时算好。列表排序不改变升降结果。
- 识别服务不可用、或整理不出任何人员行时，不改该俱乐部已有人员。

## 总体架构

```text
浏览器
  创建俱乐部 / 导入人员 / 人员列表
        │  /api/v1
        ▼
NestJS
  auth（保留）
  clubs（新增）
  members（新增，含导入与表格整理）
  ocr client + storage（保留，供导入调用）
        │                         │
        ▼                         ▼
PostgreSQL                  PaddleOCR /recognize
clubs, members, import_batches
```

从 `AppModule` 和前端路由移除任务、模板、记录、对话、导出、任务资源这几块的对外入口。对应数据表本版保留，避免误删已有演示数据；应用不再读写它们。

## 模块职责

| 模块 | 职责 |
|---|---|
| `auth` | 保持登录、注册、当前用户 |
| `clubs` | 俱乐部增删改查；删除前检查是否已有人员 |
| `members` | 上传导入、把 OCR 行整理成人员、按俱乐部和玩家名称覆盖最新值、计算升降、列表筛选与排序 |
| `ocr` client | 继续调用 `/recognize`。任务识别接口删除 |
| `storage` | 以 `imports/{userId}/{clubId}/{uuid}` 保存原图 |
| Web `AppShell` | 主菜单「俱乐部管理」，子菜单三个页面 |
| 下线 | `tasks`、`templates`、`records`、`ai`、`exports`、任务维度的 `resources` 页面与控制器 |

表格整理放在 API 内的纯函数中：输入是 OCR 的 `lines`（`text`、`confidence`、`box`），输出是人员行。不把整理规则写进 Python 服务，这样列映射可以单测，也不必改 OCR 镜像。

## 关键流程

### 导入

1. 请求必须带 `clubId` 和图片。未选俱乐部时前端不发起上传；接口侧也拒绝。
2. 确认俱乐部属于当前用户。图片仍限制为 PNG、JPEG、WebP，且不超过 10MB。
3. 调用现有 OCR。失败则返回错误，不写人员。
4. 用文字框的纵坐标把行聚成视觉行，再按横坐标从左到右排列。
5. 找到包含「玩家名称」的表头行，用表头文字的横坐标划定列：等级、途径、非凡评分、风尚度、周活跃、入会时间。
6. 排名不依赖表头。取玩家名称列左侧、可解析为整数的文字作为排名。
7. 每个数据行必须同时有玩家名称和排名，否则丢弃该行。等级、途径、评分、风尚度、周活跃、入会时间读不到则为空，不因此失败。
8. 丢掉界面杂讯，例如「主页」「成员列表」「离开俱乐部」以及无法对应到玩家名称的行。职位、分组、当前状态不入库。
9. 有效行数为 0：返回失败，不更新人员，不记成功批次。
10. 有效行数大于 0：在一个事务里逐行处理。匹配键是「俱乐部 + 玩家名称」。
    - 不存在：插入，无上次值，升降为空。
    - 已存在：把当前排名、非凡评分抄到上次字段，写入新值，重算升降，刷新数据更新时间。
11. 事务成功后再记一条导入批次，并保存原图。事务失败则人员保持导入前的状态。

同一张截图里的多名玩家使用同一次导入时间，作为各自的数据更新时间。

### 升降

只在覆盖已有玩家时计算。没有上次值，或两次值相同：接口给空，界面不画箭头。

| 字段 | 提升 | 下降 | 差值 |
|---|---|---|---|
| 排名 | 新排名数字更小 | 新排名数字更大 | 两次排名差的绝对值 |
| 非凡评分 | 新分数更大 | 新分数更小 | 两次分数差的绝对值 |

玩家改名后匹配不到旧记录，按新玩家插入，不显示升降。

### 列表

筛选在服务端完成：`clubId` 精确匹配，玩家名称按关键字包含匹配，且不区分大小写。俱乐部下拉只列出当前用户的俱乐部。

排序也在服务端完成，避免只排当前页。允许的排序字段就是九个展示列。默认按排名升序（数字小的在前）。入会时间保存的是「26天」这类原文，排序按原文比较，不换算成日期或时长。

人员列表不提供新增、编辑、删除接口。

## 数据模型

新增三张表，均挂在现有 `users` 下。

### clubs

| 字段 | 类型 | 规则 |
|---|---|---|
| id | uuid | 主键 |
| userId | uuid | 所属用户，外键 |
| name | string | 必填，同一用户下唯一 |
| leader | string，可空 | 会长，不校验是否存在于人员表 |
| createdAt / updatedAt | 时间 | |

### members

一个俱乐部下一个玩家名称只有一行当前记录。

| 字段 | 类型 | 规则 |
|---|---|---|
| id | uuid | 主键 |
| clubId | uuid | 外键，删除俱乐部时由业务先拦截 |
| playerName | string | 与 clubId 组成唯一键 |
| rank | int | 截图中的排名，不按评分重算 |
| level | int，可空 | 等级 |
| path | string，可空 | 途径 |
| score | int，可空 | 非凡评分 |
| fashion | int，可空 | 风尚度 |
| weeklyActivity | int，可空 | 周活跃 |
| joinedText | string，可空 | 入会时间原文 |
| previousRank | int，可空 | 上次排名 |
| previousScore | int，可空 | 上次非凡评分 |
| dataUpdatedAt | 时间 | 最近一次成功写入该行的时间 |
| createdAt | 时间 | 首次出现时间 |

升降不落库，查询时由当前值与上次值推导，避免和排序字段耦在一起。

### import_batches

| 字段 | 类型 | 规则 |
|---|---|---|
| id | uuid | 主键 |
| clubId / userId | uuid | 归属 |
| objectName | string | 原图存储键 |
| rowCount | int | 本次写入行数 |
| createdAt | 时间 | 与这批人员的数据更新时间相同 |

## 接口

前缀 `/api/v1`，除登录注册外都要带现有 JWT。不属于当前用户的俱乐部、人员返回 404。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/clubs` | 当前用户的俱乐部列表，供管理页和下拉框 |
| POST | `/clubs` | `{ name, leader? }`。名称为空 400，重名 409 |
| PATCH | `/clubs/:id` | 修改名称、会长。重名 409 |
| DELETE | `/clubs/:id` | 名下已有人员时 409，不级联删除 |
| POST | `/clubs/:id/imports` | `multipart` 字段 `file`。成功返回 `{ rowCount, updatedAt }` |
| GET | `/members` | 查询参数：`clubId`、`keyword`、`sort`、`order` |

`GET /members` 每一行：

| 字段 | 含义 |
|---|---|
| rank, playerName, clubName, level, path, score, fashion, weeklyActivity, joinedText | 九列展示值 |
| dataUpdatedAt | 数据更新时间 |
| rankChange | `{ direction: "up" \| "down", delta: number }` 或 `null` |
| scoreChange | 同上；评分为空而无法比较时为 `null` |

`sort` 只接受：`rank`、`playerName`、`clubName`、`level`、`path`、`score`、`fashion`、`weeklyActivity`、`joinedText`。`order` 只接受 `asc` 或 `desc`。非法排序字段返回 400。空值排在最后。

导入错误：

| 情况 | 结果 |
|---|---|
| 未选俱乐部、文件类型或大小不合法 | 400，不写人员 |
| 俱乐部不存在或不属于当前用户 | 404 |
| OCR 超时或不可用 | 502，不写人员 |
| 找不到表头或有效人员行数为 0 | 422，不写人员 |

原 `/tasks`、`/templates` 及相关子路由删除。前端访问 `/tasks`、`/tasks/new`、`/tasks/:id`、`/templates` 时进入俱乐部页，不再渲染旧页面。登录后的默认页从 `/tasks` 改为 `/clubs`。

## 前端

侧栏一个子菜单，结构对应三个路由：

| 菜单 | 路由 | 界面 |
|---|---|---|
| 创建俱乐部 | `/clubs` | 左侧或上方表单（名称、会长），下方 `el-table` 列出已有俱乐部，行内编辑和删除 |
| 导入人员 | `/imports` | 俱乐部 `el-select`，未选中时上传不可用；`el-upload` 选图后立即提交；成功用消息显示写入条数 |
| 人员列表 | `/members` | 俱乐部下拉和玩家名称输入；`el-table` 九列，排名和评分列用箭头加差值；`sortable="custom"`，排序变化时重新请求 |

视觉继续用现有浅蓝色 Element Plus 变量，不恢复已去掉的标语和演示账号提示。

## 技术选型与备选

| 决定 | 原因 | 不采用 |
|---|---|---|
| 继续用 PaddleOCR 的文字框，在 API 里按坐标对齐列 | OCR 服务已经返回 `box`；列位置随截图像素变化，不能靠固定切图 | 让模型直接输出 JSON。现有服务没有这个协议，也容易补出截图里没有的数字 |
| 当前行覆盖，并保留上次排名和评分 | 符合 Q1，人员列表不必做历史页 | 每次导入都追加一行再在查询时取最新。列表会和历史混在一张表里 |
| 服务端排序 | 排序字段和空值规则固定，和筛选一起生效 | 只在浏览器里排已返回的数据 |
| 旧业务表先留在库里 | 下线功能即可满足验收，避免这一版做破坏性删表 | 立刻删除 `ocr_tasks` 等表。确认不再需要演示数据后，可以另做迁移 |

## 风险与对策

| 风险 | 对策 |
|---|---|
| 游戏界面对比度低，名字或数字识别错 | 导入结果展示写入条数；行必须有名称和排名才入库。本版按梳理不做人工改表 |
| 职位两行字被拆成独立行，干扰列对齐 | 按文字框高度聚类；没有玩家名称的行丢弃。职位本身不入库 |
| 样例图同时出现名次 64 和 1–5，不是完整名单 | 只更新出现的玩家，不把缺席玩家删掉 |
| 本地 OCR 容器未启动 | 导入返回 502，人员数据不变。开发计划里把 OCR 服务列为导入验收的前置 |
| 「26天」按文本排序，不会按天数排序 | 接受 Q5 的原文策略，在开发计划中不把时长解析列为必须 |
| 旧路由和菜单残留 | 路由表和侧栏只保留登录、注册和三个新页面；旧地址统一离开原页面 |

## 与梳理版的追溯

| 用例 / 验收 | 设计落点 |
|---|---|
| UC-01、验收 1 | 侧栏子菜单和三条路由；默认页 `/clubs` |
| UC-02、UC-03、验收 2 | `clubs` 接口；名称为空 400；会长可空；有人员时删除 409 |
| UC-04、验收 3、4 | `POST /clubs/:id/imports`；坐标对齐；`members` 写入俱乐部与 `dataUpdatedAt` |
| UC-05、验收 6 | `GET /members` 的 `clubId`、`keyword` |
| UC-06、验收 5 | `previousRank`、`previousScore` 与 `rankChange`、`scoreChange` |
| UC-07、验收 7 | `sort`、`order` 与表头自定义排序 |
| UC-08、验收 8 | 移除旧模块入口；旧地址不再打开任务或模板页 |
| Q1、Q2 | 唯一键 `clubId + playerName`，改名即新行 |
| Q3 | `rank` 取截图数字 |
| Q4 | 差值为 0 或没有上次值时 `rankChange` / `scoreChange` 为 `null` |
| Q5 | `joinedText` 原文，排序不换算 |
| Q6 | 不建职位、分组、当前状态字段 |
| Q7 | 删除前计数人员 |
| Q8 | `leader` 自由文本 |
| Q9 | `(userId, name)` 唯一 |
| Q10 | 0 行有效人员则 422，事务不更新 |
| Q11 | 前端禁用上传，接口也校验俱乐部 |
