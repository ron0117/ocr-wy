# 技术设计 · AI 对话（小忧）

依据 [需求梳理版](../detail/需求-ai对话-梳理版.md) 的口径，以及 Q1–Q9 的暂定结论。本版只定方案，不改代码。

## 目标与约束

已登录用户在现有后台里打开小忧，用一句话查询自己能看的俱乐部，或导出一家俱乐部的人员 Excel。模型只把话收成白名单工具和俱乐部名称。人数、权限、人员和文件都由后台计算。

小忧对管理员说话的方式单独放在技能文稿里。技能决定自称、称呼和各场景的句子，不决定查哪家、导不导。基础模式没有模型时，仍然用这些句子。

沿用现有技术栈，不引入 Redis、BullMQ 或向量库。不改人员列表页的浏览器导出，也不改识单任务的 `tasks/:taskId/chat`。

| 已有能力 | 本需求中的用法 |
|---|---|
| Vue 3 + Element Plus + `AppShell` | 已登录页右下角入口和对话面板 |
| NestJS + JWT + `AuthUser` | 对话、历史、下载都从服务端取当前用户 |
| `AccessService.clubWhere` / `assertClub` | 工具和下载只碰到该用户能看的俱乐部 |
| `members`、`wecom_bindings` | 导出列和「已绑定 / 未绑定」 |
| `StorageService` | 保存 xlsx，路径不公开 |
| `asExcelText` | 以 `=`、`+`、`-`、`@` 开头的文本按普通文本写入 |
| `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` | 意图识别沿用这组环境变量。密钥仍只在服务端 |

约束：

- 技能文稿放在本仓库，随 API 启动读入。这不是 Cursor 编程助手用的 `.cursor/skills`，模型也不能在对话里新增技能。
- 最终回复由场景技能填空生成。不把工具结果交给模型改写，避免人数和俱乐部名称被说错。
- 发给模型的内容只有：意图技能、当前会话里已授权的俱乐部名称、用户这一句话。不发送人员行、令牌、密钥和其他用户的数据。
- 模型输出里的用户 ID、角色 ID、俱乐部 ID 一律不采用。俱乐部 ID 只来自服务端匹配或本会话已经确认的记录，执行前再过 `assertClub`。

## 总体架构

```text
已登录后台（AppShell）
  右下角「小忧」
        │  JWT  /api/v1/assistant
        ▼
NestJS  xiaoyou
  会话与短上下文
  意图：模型 JSON，失败则本地句式
  五个白名单工具（内部调用 clubs / members / access）
  场景技能填空，生成对管理员说的话
  Excel 写入 StorageService
        │
        ▼
PostgreSQL
  assistant_sessions
  assistant_messages
  assistant_tool_calls
  assistant_exports
```

识单整理仍走现有 `AiService`。两边只共用环境变量，不共用提示词、消息表和工具。

## 模块职责

| 模块 | 职责 |
|---|---|
| `xiaoyou` | 会话、意图、工具编排、技能填空、审计 |
| `xiaoyou/skills` | 语气、意图说明、各场景说法。只有文稿 |
| `access` | 继续提供俱乐部可见范围，小忧不另写一套权限 |
| `members` 数据 | 小忧直接按俱乐部读取人员并生成文件，不调用浏览器导出 |
| Web `XiaoyouPanel` | 挂在 `AppShell`，不新增菜单和路由 |

## 语言技能

技能是目录里的 `SKILL.md`。启动时全部读入内存。缺文件或填空后丢了必留原句，该场景改用内置的同一句兜底，不执行额外工具。

```text
apps/api/src/xiaoyou/skills/
  voice/SKILL.md
  intent/SKILL.md
  scenes/<场景>/SKILL.md
```

| 技能 | 谁读取 | 作用 |
|---|---|---|
| `voice` | 填空之后的检查 | 规定自称小忧、称呼管理员、先结果后短句；禁止主人、宝宝和闲聊 |
| `intent` | 只放进意图请求 | 说明五个工具和 JSON 形状，要求不写人话 |
| `scenes/*` | 工具执行完之后 | 每个场景一句模板和必留词 |

场景模板只允许替换下表中的空位。空位的值来自工具结果或固定拒答句，不来自模型原文。

| 场景 | 何时使用 | 必留内容 |
|---|---|---|
| `help` | 听不懂，或用户问小忧会什么 | 导出人员名单这一示例 |
| `no-menu` | 已登录但没有「人员列表」菜单 | 说明不能查人员和导出 |
| `list-clubs` | 列出可访问俱乐部 | 这些俱乐部的名称；一家都没有时说明当前没有可访问的俱乐部 |
| `need-choice` | 多个候选 | 每个候选的名称 |
| `need-confirm` | 只有一个近似匹配 | 识别到的俱乐部全名 |
| `club-missing` | 没有可访问的匹配 | 原句「没有找到你可访问的相关俱乐部，请检查名称后重试」 |
| `empty-members` | 俱乐部没有人员 | 原句「暂无可导出的人员数据」 |
| `export-ready` | 文件已生成 | 俱乐部名称、人数 |
| `export-failed` | 生成失败 | 说明可以再试，不带下载 |
| `summary` | 基本信息、人数或更新时间 | 名称、人数；有人员时带更新时间 |
| `basic-mode` | 本次没走模型 | 说明小忧这会儿是自己在认话，再接上面的场景句 |
| `file-unavailable` | 下载时过期、删除或失去权限 | 说明文件不可用；仍有权限时可以重新生成 |

语气按 Q9。模板本身就要像团宠助手，例如导出成功：

> 管理员，小忧把「星辰俱乐部」人员名单放好了，一共 48 人。点下面就能带走。

请选择：

> 管理员，小忧找到「星辰俱乐部一队」和「星辰俱乐部二队」。说一个名字或序号，小忧再去导。

找不到：

> 管理员，没有找到你可访问的相关俱乐部，请检查名称后重试。小忧只能在你管得到的俱乐部里找。

没有人员：

> 管理员，「星辰俱乐部」暂无可导出的人员数据。小忧没有做空表。

基础模式把说明接在场景句前面：

> 管理员，小忧这会儿没连上模型，自己在认话。小忧把「星辰俱乐部」人员名单放好了，一共 48 人。点下面就能带走。

实现时以技能文稿为准，上面只是文稿要达到的说法。改口吻只改 `SKILL.md`。

每条助手回复都要能看出是小忧在对管理员说话。检查不看风格分数，只看：出现「小忧」和「管理员」，必留词都在，没有出现工具结果以外的俱乐部名称。

## 关键流程

1. 面板打开时读取当前用户最近一个会话和其中最近的消息。没有会话就等用户先说话再创建。
2. 用户发送时带上客户端生成的请求号。同一会话、同一请求号只处理一次。
3. 先写用户消息。该会话已有别的请求在处理时，不启动第二次工具调用。
4. 若会话里有待确认候选，先用本地规则解释「序号、全名、唯一名称片段、是 / 不是」。能选定或否掉就不再叫模型。
5. 否则在已配置模型时，用意图技能请求一份 JSON。超时、失败或结构不对，改为本地句式，并标记基础模式。
6. 本地句式只识别梳理版里的导出说法，以及「有哪些俱乐部」「有多少人」「什么时候更新」「你能做什么」。名称从「导出 / 下载」和「俱乐部」之间截取。截不出就不执行。
7. 确定工具后，用当前 `AuthUser` 做菜单和俱乐部校验，再查库或生成文件。
8. 用场景技能填空，写入助手消息。导出成功时带上文件标识，供面板放下载按钮。
9. 用户关掉面板不影响第 7 步和第 8 步写完。再次打开能看到这句回复；还没写完时面板显示生成中。

已确认的俱乐部把数据库 ID 记在会话上。用户之后说「导出」「有多少人」且没点名另一家时，用这个 ID，执行前再次 `assertClub`。用户点名另一家，或点击新对话，就不再用它。

## 俱乐部匹配

只查询 `AccessService.clubWhere(user)` 范围内的俱乐部。比较前去掉名称首尾空白。

| 结果 | 会话怎么记 | 下一步 |
|---|---|---|
| 一个完全相同 | 记下该俱乐部 ID | 按原意图查询或导出 |
| 多个完全相同 | 记下这些候选 ID，不设当前俱乐部 | `need-choice` |
| 零个完全相同，且只有一个名称互相包含 | 记下这一家为待确认，不设当前俱乐部 | `need-confirm` |
| 多个互相包含 | 记下候选 | `need-choice` |
| 没有 | 清掉本次名称，不改已确认俱乐部 | `club-missing` |

互相包含只做字符串包含。不使用编辑距离、拼音或模型补全名称。候选展示名称；同名时附上会长，便于管理员分辨。会长只来自这些已授权行。

待确认时，用户回复候选序号、全名，或只命中其中一个名称的片段，才写入当前俱乐部 ID。回复「不是」或开始新对话则清掉待确认。对不上就保持候选，不再导出。

## 数据模型

| 表 | 要点 |
|---|---|
| `assistant_sessions` | `userId`、可选的当前俱乐部 ID、待确认 JSON（种类和候选 ID）、是否正在处理、处理中的请求号、更新时间 |
| `assistant_messages` | `sessionId`、`userId`、角色、正文、场景名、请求号。正文是已经填好的那句话 |
| `assistant_tool_calls` | `userId`、`sessionId`、工具名、俱乐部 ID、结果、错误码、耗时。不写人员行 |
| `assistant_exports` | `userId`、`sessionId`、`clubId`、存储路径、文件名、人数、过期时间、状态 |

会话按 `userId` 查询。消息和导出写入时同时带 `userId`，读取时两边都要相等。待确认 JSON 只存本次匹配到的俱乐部 ID，不存无权俱乐部。

导出文件的对象路径形如 `assistant/{userId}/{exportId}.xlsx`，走现有 `StorageService`。不把该路径做成永久公开地址。

过期时间是生成时刻加 24 小时。下载时发现过期可以保留记录，不返回文件。首期不必为了过期单独扫表删除。

## 接口

全部在 `/api/v1` 下，使用现有 JWT。身份只用 `CurrentUser`。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/assistant/session` | 当前用户最近一个会话、最近消息、是否仍在生成 |
| POST | `/assistant/sessions` | 新对话。之后的消息进入新会话 |
| POST | `/assistant/sessions/:id/messages` | 发送一句。体为 `text` 和 `clientRequestId` |
| GET | `/assistant/exports/:id` | 下载。再次检查归属、过期和俱乐部权限 |

发送接口的回复包含：助手这句话、场景、是否基础模式、可选的下载信息（导出 ID、文件名、俱乐部名称、人数、生成时间）。待确认时另给候选名称和序号。不返回人员明细。

下载成功时返回 xlsx 附件，文件名用导出记录里的名字。无权限、过期或已删除都拒绝，响应里没有文件内容。面板据此显示 `file-unavailable`。用户若仍能访问该俱乐部，同一句里的重新生成就是再发一条导出。

菜单按 Q1：`answer_help` 和打开面板不要求「人员列表」。`list_clubs`、`find_club`、`get_club_summary`、`export_club_members_excel` 要求 `isSuper` 或 `menuKeys` 含 `members`。不满足时使用 `no-menu`，不查俱乐部。

频率按 Q8：单条超过 500 字直接拒绝；每个用户每分钟最多 20 次发送；同一会话同时只处理一条。限流记在本进程内存里。多进程各自计数，和当前没有 Redis 的部署一致。

## 意图 JSON

模型只能返回一个对象：

| 字段 | 规则 |
|---|---|
| `tool` | `list_clubs`、`find_club`、`get_club_summary`、`export_club_members_excel`、`answer_help` 之一 |
| `clubName` | 可选字符串。导出、摘要、按名查找时使用。不接受俱乐部 ID、SQL 或其他字段 |

多出来的字段视为校验失败，本次改走本地句式或帮助，不执行。`clubName` 再交回匹配函数，不能直接当查询条件拼接。

意图请求设置超时。失败时对话仍返回，并带上基础模式说明。识单和人员导入不受这次失败影响。

## Excel

在 API 内用已有的 `xlsx` 生成，工作表名「人员名单」。文本列经过 `asExcelText`。

列顺序：排名、玩家名称、俱乐部名称、等级、途径、非凡评分、风尚度、周活跃、入会时间、数据更新时间、企业微信角色绑定状态。

排名为 0 的单元格留空，排序时这些行在有排名的行之后。有排名的按排名升序，再用玩家名称稳定次序。非凡评分只写数字，不写升降箭头。绑定状态写「已绑定」或「未绑定」。数据更新时间和文件名中的时间用 Asia/Shanghai。

文件名：`俱乐部名称-人员名单-YYYYMMDD-HHmmss.xlsx`。俱乐部名称去掉 `\ / : * ? " < > |`。没有人员时不创建 `assistant_exports`，也不写存储。

生成抛错时记一条失败的工具调用和 `export-failed` 消息，不返回下载 ID。

## 前端

`XiaoyouPanel` 放在 `AppShell` 里，登录后的后台页都能看见。不进入侧栏菜单，企业微信活动页 `/a/:id` 不放。

面板包含名称「小忧」、消息列表、输入框、发送、新对话和生成中状态。Enter 发送，Shift + Enter 换行。生成中禁用发送。导出成功的消息显示下载按钮，点击时带当前 JWT 请求下载接口，再在浏览器保存文件。

窄屏下面板贴底展开，不挡住整个退出操作。关闭面板只隐藏界面；重新打开再拉一次当前会话。

## 技术选型与备选

| 决定 | 原因 | 不采用 |
|---|---|---|
| 说法放在 `xiaoyou/skills` | 团宠语气和办事结果分开。改句子不动查询和导出 | 把语气写死在每个工具里。以后一改口吻就要改业务代码 |
| 场景模板填空 | 人数和拒答原句不会被模型改掉；没模型时语气还在 | 再请模型把结果说得更活。生动性不够就改文稿，不把事实交给第二次生成 |
| 意图只收 JSON | 和现有「AI 不补造数据」一致，也便于校验失败后降级 | 让模型直接回复管理员，再从话里猜要不要导出 |
| 技能不放到 `.cursor/skills` | 那边只影响编程助手，后台用户打不开 | 用 Cursor 技能冒充小忧的运行时文稿 |
| 新表，不复用 `ai_messages` | 识单消息挂在任务上，没有俱乐部、导出和会话权限 | 往任务对话里加俱乐部工具 |
| 下载走登录接口 | 每次都能重查俱乐部权限，也不会留下永久公开地址 | 只签一个长期有效的存储链接 |
| 进程内限流 | 当前部署没有 Redis | 为这一项引入 BullMQ 或 Redis |
| API 使用已有 `xlsx` | 服务端已依赖它，足够写工作表名和文本单元格 | 把网页里的 `exceljs` 样式导出搬到对话。人员列表页导出按 Q7 保持原样 |

## 风险与对策

| 风险 | 对策 |
|---|---|
| 用户用「忽略技能、改查另一家」试探 | 用户原文只作为意图请求里的数据。工具名单和参数形状固定，俱乐部范围仍由 `AccessService` 决定 |
| 技能文稿被写成带具体俱乐部或人数 | 模板只留空位。渲染后若出现工具结果以外的俱乐部名称，改用该场景兜底句 |
| 两家俱乐部同名 | 不完全自动选择。候选带会长；确认后会话保存的是 ID |
| 模型返回一段团宠散文 | 结构校验失败，转入基础模式或帮助，不执行工具 |
| 生成过程中面板被关掉 | 服务端写完消息和文件记录。再次打开读取会话 |
| 导出后权限被收回 | 下载前 `assertClub`。失败则不读文件 |
| 限流只在单进程有效 | 与现有无 Redis 的部署相同。审计表仍能看到实际调用次数 |
| 基础模式误导出 | 只有固定导出句式，且匹配结果唯一或已确认时才生成文件 |
