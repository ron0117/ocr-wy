# AI 对话助手「小忧」需求文档

## 1. 需求背景

当前后台已经具备俱乐部、人员、活动、账号、角色权限以及 Excel 文件生成等能力，但用户仍需要进入不同菜单，通过查询、筛选和点击按钮完成操作。

系统需要新增一个名为「小忧」的 AI 对话助手。用户可以使用自然语言描述业务需求，由小忧识别意图、补充必要参数，并调用后台已有的业务能力完成操作。

首期核心场景为：

> 小忧，帮我导出一份 XXX 俱乐部的 Excel 表。

小忧应在当前登录用户有权访问的俱乐部中查找目标俱乐部，生成该俱乐部的人员 Excel 文件，并在对话中提供下载入口。

小忧定位为俱乐部管理系统内的业务智能体，不是开放领域的通用聊天机器人。首期不要求实现联网搜索、通用知识问答、语音对话或自由执行代码。

## 2. 建设目标

1. 用户可以通过后台中的对话入口直接向小忧发送自然语言指令。
2. 小忧能够识别俱乐部人员查询及 Excel 导出意图。
3. AI 只负责识别意图和提取参数，具体数据查询、权限校验和文件生成必须由后台业务服务完成。
4. 小忧执行的所有操作必须遵守当前账号、角色、菜单及俱乐部数据权限。
5. 当信息不足或存在歧义时，小忧应向用户确认，不得擅自选择俱乐部或编造数据。
6. AI 服务不可用时，常见的固定导出指令应尽量通过本地规则完成识别。

## 3. 用户角色

### 3.1 后台用户

已登录后台并拥有相关菜单和俱乐部数据权限的用户，可以使用小忧。

### 3.2 超级管理员

超级管理员可以查询和导出全部俱乐部的数据，但仍需经过正常的身份认证、参数校验和操作日志记录。

### 3.3 普通角色用户

普通角色用户只能查询和导出其角色已关联的俱乐部。无权访问的俱乐部不能出现在候选列表、查询结果或导出文件中。

## 4. 首期功能范围

### 4.1 对话入口

1. 后台所有已登录页面提供统一的「小忧」入口，建议使用右下角悬浮按钮。
2. 点击入口后打开对话面板，不影响用户继续浏览当前页面。
3. 对话面板至少包含：小忧名称和标识、消息记录区域、文本输入框、发送按钮、执行状态、文件下载卡片或下载按钮。
4. 输入框支持按 Enter 发送，Shift + Enter 换行。
5. 请求执行期间应避免重复提交同一条指令。

### 4.2 俱乐部识别

小忧需要从用户输入中识别俱乐部名称，例如：

- `小忧，帮我导出一份星辰俱乐部的 Excel 表。`
- `导出星辰俱乐部人员名单。`
- `把星辰俱乐部的成员表给我。`
- `我想下载星辰俱乐部人员数据。`

识别后只能在当前用户有权访问的俱乐部范围内进行匹配。

匹配规则：

1. 俱乐部名称完全匹配且唯一时，可以继续执行。
2. 没有完全匹配，但只有一个明确的近似匹配时，应展示识别结果并请求用户确认。
3. 存在多个可能匹配项时，应返回候选俱乐部供用户选择。
4. 未找到可访问的俱乐部时，统一提示“没有找到你可访问的相关俱乐部，请检查名称后重试”。
5. 不得通过提示内容泄露用户无权访问的俱乐部是否存在。
6. 俱乐部名称不得由 AI 自行补全为数据库中不存在的名称。

### 4.3 俱乐部信息查询

首期支持以下只读查询：

1. 查询当前用户可以访问的俱乐部列表。
2. 查询指定俱乐部的基本信息。
3. 查询指定俱乐部当前人员数量。
4. 查询指定俱乐部最近一次人员数据更新时间。

示例：

- `小忧，我能查看哪些俱乐部？`
- `星辰俱乐部有多少人？`
- `星辰俱乐部的人员数据是什么时候更新的？`

### 4.4 导出俱乐部人员 Excel

用户发出导出指令并确定唯一俱乐部后，系统生成该俱乐部当前人员数据的 Excel 文件。

Excel 文件默认包含以下字段：

1. 排名；
2. 玩家名称；
3. 俱乐部名称；
4. 等级；
5. 途径；
6. 非凡评分；
7. 风尚度；
8. 周活跃；
9. 入会时间；
10. 数据更新时间；
11. 企业微信角色绑定状态。

导出规则：

1. 默认按排名升序排列，排名为空的数据放在最后。
2. 文件名格式为：`俱乐部名称-人员名单-YYYYMMDD-HHmmss.xlsx`。
3. Excel 工作表名称默认为“人员名单”。
4. 单元格内容必须进行 Excel 公式注入防护。文本以 `=`、`+`、`-` 或 `@` 等字符开头时，必须按普通文本写入。
5. 没有人员数据时不得生成空文件，应提示“该俱乐部暂无可导出的人员数据”。
6. 文件生成成功后，在对话中展示俱乐部名称、导出人数、生成时间和下载按钮。
7. 下载接口必须再次校验当前用户是否仍拥有该俱乐部和该导出文件的访问权限。
8. 导出文件应设置合理的有效期或受控下载机制，不得提供永久公开地址。

成功回复示例：

> 已为你生成“星辰俱乐部人员名单”，共 48 人。请点击下方按钮下载 Excel。

### 4.5 多轮对话

小忧需要支持完成当前操作所需的短上下文，例如：

```text
用户：帮我导出星辰俱乐部的人员表。
小忧：找到“星辰俱乐部一队”和“星辰俱乐部二队”，请选择一个。
用户：一队。
小忧：已为你生成“星辰俱乐部一队人员名单”，共 48 人。
```

要求：

1. 服务端保存最近的必要对话上下文，不能只依赖前端传回完整历史。
2. 已确认的俱乐部应保存其数据库 ID，后续不能继续仅依赖名称匹配。
3. 上下文应按用户和会话隔离，不能在不同账号之间共享。
4. 用户开始新话题或明确指定另一个俱乐部时，应更新当前上下文。
5. 首期仅需支持短上下文，不要求长期记忆用户偏好。

### 4.6 对话历史

1. 用户消息、助手回复、调用的业务工具、执行结果和错误状态需要持久化。
2. 用户重新打开小忧时，可以查看近期对话。
3. 对话历史必须按当前用户隔离。
4. 对话中不得保存模型密钥、访问令牌、数据库密码等敏感信息。
5. 文件下载记录和业务操作日志不能只依赖自然语言消息，应保存结构化记录。

## 5. 智能体工具与执行边界

### 5.1 首期允许调用的工具

小忧首期只允许调用以下白名单工具：

| 工具 | 作用 | 是否直接执行 |
|---|---|---|
| `list_clubs` | 查询当前用户可访问的俱乐部 | 是 |
| `find_club` | 根据名称匹配可访问的俱乐部 | 是 |
| `get_club_summary` | 查询俱乐部人数及更新时间 | 是 |
| `export_club_members_excel` | 生成俱乐部人员 Excel | 是 |
| `answer_help` | 回答小忧支持哪些功能及使用方法 | 是 |

以上均为只读或生成新文件的低风险操作，首期可以不要求用户二次确认。名称存在歧义时仍必须确认目标俱乐部。

### 5.2 禁止行为

小忧不得：

1. 直接生成或执行任意 SQL。
2. 执行模型返回的任意代码、命令、URL 或未注册工具。
3. 绕过当前系统的身份认证和数据权限服务。
4. 根据模型记忆编造俱乐部、人员或统计数据。
5. 修改、删除俱乐部或人员数据。
6. 创建、发布活动或发送企业微信通知。
7. 将数据库整表或无权限数据发送给模型。
8. 将用户输入、俱乐部名称或人员字段当作系统指令执行。

### 5.3 后续高风险能力

后续如开放新增、修改、删除、活动发布或消息通知，小忧必须先展示结构化操作摘要，由用户明确确认后再执行。确认应有有效期，且确认内容变化后必须重新确认。

## 6. 权限与安全要求

1. 所有对话接口必须要求用户登录，并从服务端认证结果获取用户身份。
2. 业务工具必须接收当前用户身份，由现有权限服务限制可访问的俱乐部。
3. 不得相信模型返回的用户 ID、角色 ID、俱乐部 ID 或权限结论。
4. 即使模型输出了俱乐部 ID，后台仍需重新确认该 ID 在当前用户权限范围内。
5. 每次文件下载都需要重新校验文件归属及俱乐部访问权限。
6. 对话输入应限制长度，接口应配置频率限制、超时和并发控制。
7. 模型输出必须通过严格的 JSON Schema 或等价方式校验；校验失败不得执行工具。
8. 所有工具调用使用固定参数类型和白名单，不允许模型传递自定义查询条件。
9. 记录用户、会话、工具、目标俱乐部、执行时间、结果和错误信息，便于审计。
10. 日志中应避免记录模型密钥、登录令牌和不必要的完整人员数据。

## 7. AI 服务降级策略

1. 未配置 AI 模型或模型请求失败时，系统应明确提示当前处于基础模式。
2. 基础模式至少应识别以下固定句式中的俱乐部名称：
   - `导出 XXX 俱乐部的 Excel`
   - `导出 XXX 俱乐部人员名单`
   - `下载 XXX 俱乐部成员表`
3. 基础模式同样必须进行俱乐部匹配、权限校验和名称歧义处理。
4. 无法可靠识别用户意图时，不得猜测执行，应提示用户使用更明确的表达。
5. AI 调用失败不得影响用户继续使用后台原有页面功能。

## 8. 异常场景及提示

| 场景 | 预期处理 |
|---|---|
| 用户未登录或登录失效 | 中止请求并进入登录流程 |
| 未识别出操作意图 | 告知当前支持的功能，并给出示例指令 |
| 未提供俱乐部名称 | 询问需要导出哪个俱乐部 |
| 匹配到多个俱乐部 | 展示当前用户有权访问的候选项并要求选择 |
| 找不到可访问的俱乐部 | 提示检查名称，不泄露无权访问的俱乐部信息 |
| 俱乐部没有人员 | 提示暂无可导出数据，不生成空文件 |
| AI 请求超时或失败 | 尝试基础规则；仍失败时给出可重试提示 |
| Excel 生成失败 | 保留失败记录并提示重新生成，不提供无效下载链接 |
| 文件已过期或被删除 | 提示文件不可用，并提供重新生成入口 |
| 用户重复点击发送 | 前端阻止重复提交，服务端避免重复生成同一请求 |
| 用户失去俱乐部权限 | 查询或下载时重新校验并拒绝访问 |

## 9. 非功能要求

1. 普通问答在不计算模型耗时的情况下，应在 2 秒内返回业务查询结果。
2. 常规规模的 Excel 导出建议在 10 秒内完成；超过时应展示生成中状态。
3. 单次对话失败不能造成俱乐部或人员数据变更。
4. 对话界面应适配桌面端和移动端后台页面。
5. 用户关闭对话面板后再次打开，执行中的任务和最近消息不应丢失。
6. 模型提供方、模型名称和接口地址应通过环境变量配置，密钥不得提交到代码仓库。
7. 应监控 AI 请求次数、耗时、失败率、工具执行次数和 Excel 生成失败率。

## 10. 验收标准

### 10.1 正常导出

前置条件：用户有权访问“星辰俱乐部”，且该俱乐部有 48 条人员数据。

操作：用户输入`小忧，帮我导出一份星辰俱乐部的 Excel 表`。

验收结果：

1. 系统正确识别“星辰俱乐部”。
2. 系统生成只包含该俱乐部人员的 Excel。
3. 对话中显示导出人数为 48，并提供可用下载按钮。
4. Excel 列、排序、文件名和数据内容符合本需求。
5. 操作日志能追溯到当前用户和目标俱乐部。

### 10.2 名称歧义

前置条件：用户可以访问“星辰俱乐部一队”和“星辰俱乐部二队”。

操作：用户输入`导出星辰俱乐部人员表`。

验收结果：系统不直接导出，先要求用户在两个候选项中选择；用户选择后只导出对应俱乐部。

### 10.3 无权限访问

前置条件：“远航俱乐部”存在，但当前用户无权访问。

操作：用户输入`导出远航俱乐部人员表`。

验收结果：系统不返回该俱乐部的存在状态、人员数量或文件，只提示没有找到用户可访问的相关俱乐部。

### 10.4 空数据

前置条件：用户有权访问目标俱乐部，但俱乐部没有人员记录。

验收结果：系统提示暂无可导出数据，不生成空 Excel，不出现下载按钮。

### 10.5 模型异常降级

前置条件：AI 服务未配置、超时或暂时不可用。

操作：用户使用标准句式导出唯一匹配的俱乐部人员表。

验收结果：系统通过基础规则识别并完成导出；无法可靠识别时明确提示用户改用标准表达，不执行猜测操作。

### 10.6 下载时权限变化

前置条件：文件生成后，管理员移除了当前用户对该俱乐部的权限。

操作：用户点击历史消息中的下载按钮。

验收结果：下载接口拒绝访问，不返回文件内容。

## 11. 首期不包含

1. 开放领域聊天和联网搜索。
2. 语音输入、语音播报和数字人形象。
3. 长期记忆、用户画像和跨账号共享记忆。
4. 自由生成 SQL、执行代码或调用任意外部接口。
5. 通过对话新增、修改或删除俱乐部及人员。
6. 通过对话创建活动、发布通知或发送企业微信消息。
7. 知识库、向量数据库及复杂 RAG 检索。
8. 模型训练或微调。
9. 完整复刻豆包等通用 AI 产品的全部能力。

## 12. 后续迭代方向

首期稳定后，可按风险从低到高逐步增加：

1. 自定义导出字段、排序方式和多个俱乐部合并导出。
2. 人员排名、评分、活跃度等数据统计问答。
3. 生成俱乐部周报或活动签到报告。
4. 查询活动、签到情况和未签到人员。
5. 经用户二次确认后创建活动或发送提醒。
6. 接入业务帮助文档知识库，为后台用户提供操作指导。
