# 需求梳理 · 新建俱乐部

源需求把后台从「商品图片 → 任务 / 模板 → 清单」改为「俱乐部管理」。本版只梳理范围、用例和验收，不涉及实现。

## 产品定位

登录后的后台只服务俱乐部成员数据：维护俱乐部、把成员截图识别进人员表、按俱乐部和玩家名称查看并比较名次与评分变化。

截图样例为游戏成员列表（`assets/微信图片_20261010140035_72.jpg`）。表头可见：排名、玩家名称、职位、等级、途径、非凡评分、风尚度、周活跃、分组、入会时间、当前状态。俱乐部名称不在截图列里，来自导入时选中的俱乐部。

## 用户与用例

使用人是已登录的后台操作者。沿用现有登录，不在本需求新增账号体系。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 查看俱乐部管理菜单 | 主菜单为「俱乐部管理」；子菜单为「创建俱乐部」「导入人员」「人员列表」 |
| UC-02 | Must | 新增俱乐部 | 名称必填；会长可空；保存后能在列表中看到 |
| UC-03 | Must | 查询、修改、删除俱乐部 | 可按已有俱乐部改名称和会长；删除后列表不再出现该俱乐部 |
| UC-04 | Must | 按截图导入人员 | 先选择俱乐部，再上传图片；服务端识别表格文字并写入人员表；每条记录带所属俱乐部和数据更新时间 |
| UC-05 | Must | 查询人员 | 俱乐部为下拉筛选，游戏名称为关键字；结果用表格展示 |
| UC-06 | Must | 看名次和评分变化 | 排名、非凡评分相对该玩家上次更新显示上升或下降，并带变化量 |
| UC-07 | Must | 按列排序 | 人员表各展示列可点击表头做升序 / 降序 |
| UC-08 | Must | 不再使用任务和模板 | 没有任务列表、任务详情、新建任务、模板页面，也不能从菜单进入这些功能 |

## 功能拆解

### 俱乐部

| 字段 | 规则 |
|---|---|
| 俱乐部名称 | 必填 |
| 会长 | 非必填，文本 |

「创建俱乐部」页要能完成增删改查，不只是一张新建表单。

### 导入人员

1. 选择已有俱乐部。
2. 上传成员列表图片。
3. 服务端做 OCR，读取表格中的文字。
4. 自动写入人员表，不经过任务或模板。
5. 每条人员记录标记所属俱乐部，并记录数据更新时间。

本地验收使用 `assets/` 下的成员截图，上传后应能抽出表格行，而不是整页当成一段无关文字。

从样例截图应能读到、且人员列表要展示的列：

| 展示列 | 来源 | 变化 |
|---|---|---|
| 排名 | 截图中的名次数字 | 相对上次更新，用上下箭头和差值表示升或降 |
| 玩家名称 | 截图 | 无 |
| 俱乐部名称 | 导入时选中的俱乐部 | 无 |
| 等级 | 截图 | 无 |
| 途径 | 截图 | 无 |
| 非凡评分 | 截图 | 相对上次更新，用上下箭头和差值表示升或降 |
| 风尚度 | 截图 | 无 |
| 周活跃 | 截图 | 无 |
| 入会时间 | 截图原文，如「26天」 | 无 |

样例中还有职位、分组、当前状态。源需求的人员列表未要求展示这三列。

### 人员列表

- 上方：俱乐部下拉、游戏名称关键字。游戏名称按玩家名称匹配。
- 下方：上述九列。
- 点击某一列表头，按该列升序或降序排列当前结果。
- 排名、非凡评分的箭头表示相对**上一次数据更新**的变化，不是本次点击排序产生的名次。

### 从现有后台移除

以下不再作为产品功能：

- 任务列表、任务详情、新建任务
- 模板的查看、新建、删除
- 侧栏中的「任务」「模板」入口
- 商品清单整理、对话整理、Excel 导出这条任务流

登录、注册保留。未登录不能进俱乐部管理。

## 非功能需求

| 项 | 要求 |
|---|---|
| 界面 | 继续使用浅蓝色 Element Plus；人员列表使用 `el-table` |
| 识别 | 上传后由服务端分析图片中的表格文字；不在浏览器里解析图片 |
| 归属 | 人员记录必须能对应到一个俱乐部 |
| 时间 | 每条人员数据有数据更新时间，供下次导入比较排名和评分 |
| 本地样例 | 以 `assets/` 中的成员截图作为导入验收图 |

## 端到端流程

1. 登录后台，进入「创建俱乐部」，填写名称，会长可留空，保存。
2. 打开「导入人员」，选中该俱乐部，上传成员截图。
3. 系统识别表格并写入人员；每条带俱乐部和更新时间。
4. 打开「人员列表」，用俱乐部和玩家名称筛选，查看九列；排名和评分相对上次导入显示升降。
5. 点击表头，按该列排序。
6. 再次导入同一俱乐部的新截图后，列表中的更新时间刷新，升降按新一次与上一次比较。

## 范围

**In**

- 俱乐部管理主菜单及三个子页面
- 俱乐部名称、会长的增删改查
- 选俱乐部 + 上传图片 + OCR 入库
- 人员列表筛选、九列展示、排名 / 评分升降、表头排序
- 去掉任务与模板相关页面和入口

**Out**

- 商品图片任务、模板、AI 对话整理、Excel 导出
- 人员列表上的手工逐条新增、编辑（源需求未要求）
- 截图中的职位、分组、当前状态展示（未列入人员列表）
- 新的登录方式、多角色权限

## MoSCoW

| 级别 | 内容 |
|---|---|
| Must | UC-01 至 UC-08；九列展示；排名与非凡评分的升降量；表头排序；自动入库 |
| Should | 导入结束后告知写入条数；识别失败时给出原因且不写入半截脏数据 |
| Could | 展示或保存职位、分组、当前状态 |
| Won't | 恢复任务 / 模板流程；本版不做人员手工编辑 |

## 待澄清

| ID | 问题 | 不答复时的暂定 |
|---|---|---|
| Q1 | 同一俱乐部、同一玩家再次导入时，按玩家名称覆盖当前记录，还是每次追加一条历史？升降需要能取到「上次」。 | 当前列表只保留每个俱乐部下每个玩家名称的最新一条；上次的排名和评分留作比较，不在列表里另开历史页 |
| Q2 | 玩家改名后如何还认为是同一个人？ | 只按「俱乐部 + 玩家名称」匹配，改名视为新玩家，不计算升降 |
| Q3 | 截图里的排名直接入库，还是按非凡评分重算？样例视觉顺序出现过 64 再接 1–5。 | 排名使用截图中的数字，不重算 |
| Q4 | 升降展示到什么粒度？ | 上升、下降都显示差值；持平不显示箭头 |
| Q5 | 入会时间是保留「26天」这类原文，还是换算成日期？ | 保留截图原文 |
| Q6 | 职位、分组、当前状态是否入库？ | 本版不展示、不作为验收列 |
| Q7 | 删除俱乐部时，其人员记录如何处理？ | 有人员时不允许删除，需先处理人员；本版不提供人员删除入口，因此只允许删除没有人员的俱乐部 |
| Q8 | 会长是否必须是该俱乐部人员表中的玩家名称？ | 任意文本，不与人员表校验 |
| Q9 | 俱乐部名称是否唯一？ | 名称唯一，重复时拒绝保存 |
| Q10 | 一张图识别出 0 行，或必填列缺失时是否仍算导入成功？ | 0 行或无法形成人员行则失败，不更新该俱乐部已有人员 |
| Q11 | 未选择俱乐部能否上传？ | 不能，必须先选俱乐部 |

## 验收标准

1. 登录后只看到俱乐部管理及其三个子菜单，看不到任务、模板、新建任务。
2. 俱乐部名称为空不能保存；会长为空可以保存；之后能改、能查、能按 Q7 的规则删除。
3. 用样例截图对指定俱乐部导入后，人员列表能看到该俱乐部的玩家，且等级、途径、非凡评分、风尚度、周活跃、入会时间与截图一致，俱乐部名称等于所选俱乐部。
4. 每条人员有数据更新时间。
5. 对同一玩家再次导入不同排名或评分后，列表显示相对上次的上升或下降及差值。
6. 俱乐部下拉和玩家名称关键字能缩小结果。
7. 点击人员表任一展示列的表头，顺序随之升序或降序切换。
8. 直接访问原任务、模板地址时，不能再进入原功能页面。
