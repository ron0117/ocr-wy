# 需求梳理 · 活跃度

源需求是把活动签到从企业微信自助签到，改成后台管理员代为勾选，并在人员列表按人查看参加情况。本版只梳理范围、用例和验收，不涉及实现。

对照现状：活动签到目前挂在「俱乐部管理」下。发布要填标题、俱乐部、开始时间，还要填提醒和企微接收范围，并发送卡片。玩家在企业微信里绑定角色后自己点签到。结束后不能再签。活动只有发布、查看、结束，没有修改和删除。签到记在 `activity_check_ins`（活动、人员、企微用户）。人员列表含「是否绑定通知」。小忧能回答绑定状态，导出表也有这一列。

导入不是整表删除再重建。同一俱乐部里名称对得上的人会原地更新，人员 id 不变。这次名单里没有的人才删除；新名称会新建，得到新的人员 id。俱乐部内玩家名称唯一。

源文件名为 `活跃度.md`，未使用 `需求-` 前缀。流水线中的 `{名称}` 取「活跃度」。

已确认口径：

- 新增父菜单「活动管理」。「活动签到」从「俱乐部管理」移到其下，菜单权限键不变，已授权角色仍能看见。不新增「人员参与情况」菜单。
- 发布弹窗只收集标题、俱乐部、时间，写入现有活动表。提醒、接收人、企微团队等已有字段保留，发布和签到都不再使用。
- 签到改为管理员在活动列表勾选该活动所选俱乐部的人员并保存。可反复保存，活动结束后仍可保存。每人另有「迟到」勾选，不勾不算迟到。
- 活动历史详情里，「已签到」用绿字，「未签到」和「迟到」用红字。未勾迟到时不出现「迟到」。
- 人员列表操作列增加「查询活跃度」。弹窗显示该人已参加、未参加的活动。
- 去掉人员列表的「是否绑定通知」和解除绑定。小忧不再回答绑定，导出表去掉这一列。改为只读查询活动。
- 身份采用方案 D。导入时，有参加记录但这次不见了的人，若同时有新名称，由管理员对照旧名和新名。对照上的不删行，只改名称。没对照的按方案 B：删除人员时留下参加记录，之后同俱乐部同名再出现就挂回去。

## 产品定位

后台管理员在「活动管理」里发布活动，只记录标题、俱乐部和时间。发布后由管理员打开签到，勾选实际参加的人员。人员列表上可以反查这个人参加过哪些活动、同一俱乐部范围内哪些没参加。小忧用同一套数据回答活动问题。

玩家不再打开企业微信卡片，也不再自己绑定、自己点签到。

## 能力分界

| 事项 | 由谁完成 |
|---|---|
| 活动菜单、发布、修改、删除、结束 | 后台，沿用现有活动数据 |
| 谁参加了这场活动 | 管理员在签到弹窗勾选后保存 |
| 人员名单从哪来 | 这场活动所选俱乐部的现有人员 |
| 按人员看已参加 / 未参加 | 人员列表的「查询活跃度」 |
| 用对话查活动、出席和某人的活跃度 | 小忧，只读，范围与后台可见俱乐部一致 |
| 企业微信卡片、提醒、玩家页自助签到、绑定状态 | 本需求停用 |

## 用户与用例

使用人是已登录、且拥有对应菜单的后台操作者。只能看到自己可见俱乐部范围内的活动和人员。小忧使用同一个登录身份。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 活动签到改挂到「活动管理」 | 侧栏出现父菜单「活动管理」，其下只有「活动签到」。俱乐部管理里不再出现活动签到。原先已勾选活动签到的角色不用重新授权 |
| UC-02 | Must | 只填标题、俱乐部、时间并发布 | 弹窗没有提醒、部门、标签、成员。至少选一个可见俱乐部，可多选。发布后列表能看到标题、俱乐部、时间 |
| UC-03 | Must | 修改、删除活动 | 列表可以改标题、俱乐部、时间，也可以删除。删除后列表不再出现，其参加记录一并去掉 |
| UC-04 | Must | 管理员勾选签到和迟到 | 每场活动有「签到」。弹窗列出所选俱乐部的人员，每人有签到、迟到两列勾选。保存后再次打开，两类勾选都还在。未勾迟到的人不算迟到 |
| UC-05 | Must | 反复保存，结束后仍可签 | 已发布、已结束都可以再打开并保存。取消勾选再保存后，该人不再算参加。结束活动不再禁止签到 |
| UC-06 | Must | 在人员列表查活跃度 | 人员列表操作列增加「查询活跃度」。弹窗分成已参加、未参加。已参加用绿字「已签到」，未参加用红字「未签到」；该场勾了迟到时再标红「迟到」。没有单独菜单 |
| UC-07 | Must | 去掉绑定展示 | 人员列表没有「是否绑定通知」和解除绑定。小忧不回答绑定，导出的人员表没有绑定列 |
| UC-08 | Must | 小忧只读查询活动 | 能列活动、看一场的时间和出席、看某人已参加和未参加。不能发布、改、删、结束或代为勾选 |
| UC-09 | Should | 去掉活动签到上的企微操作 | 活动列表不再出现重发卡片、重发提醒、通知列。玩家活动页不再提供绑定和签到 |

## 功能拆解

### 菜单

| 父菜单 | 子菜单 | 说明 |
|---|---|---|
| 活动管理 | 活动签到 | 从俱乐部管理移入，仍是原活动列表 |
| 俱乐部管理 | 人员列表 | 增加「查询活跃度」，去掉绑定列 |

不新增菜单键。超管和已有「人员列表」「活动签到」权限的角色按原授权使用。

### 发布与增删改查

发布弹窗只保留三项：

| 字段 | 规则 |
|---|---|
| 标题 | 必填 |
| 俱乐部 | 至少选一个，可多选；只能选当前用户可见的俱乐部 |
| 时间 | 必填，对应现有开始时间。不限制能否签到 |

不收集提醒时间，也不收集企业微信部门、标签、成员。这些字段和接收人、通知记录留在库里，本功能不读写、不展示。

活动列表保留标题、俱乐部、开始时间、状态。通知列和重发按钮去掉。

| 操作 | 规则 |
|---|---|
| 查 | 仍只列出当前用户可见的活动 |
| 改 | 可改标题、俱乐部、时间。已有签到不因改标题或时间而丢失 |
| 删 | 删除活动，并删除该活动的参加记录 |
| 结束 | 仍可把已发布改为已结束。结束后列表仍可签到、仍可改删 |

改俱乐部时，已经勾过、但已不在新所选俱乐部名单里的人，参加记录保留，活跃度查询仍算已参加。签到弹窗只列当前所选俱乐部里的在册人员。

### 管理员签到

每场活动的操作里增加「签到」，已发布和已结束都显示。

- 名单是该活动当前所选俱乐部的人员，带玩家名称和所属俱乐部。
- 每人两列勾选：签到、迟到。已保存的签到和迟到再次打开时仍然勾着。
- 一次保存以当前勾选为准：新勾的写入，去掉签到勾的删除。可以多次打开再保存。
- 未勾迟到就不记迟到，历史详情里也不出现「迟到」。
- 勾选迟到时，签到一并勾上。取消签到时，迟到一并取消。只取消迟到时，人仍算已签到。
- 不记录给玩家看的签到时刻，也不再走玩家自助签到。

一场活动里同一个人只保留一条。玩家从企业微信打开活动、绑定角色、自己点签到，以及到点提醒，都不再作为本功能的路径。

### 人员列表上的活跃度

人员列表原有筛选、排序、新增、编辑、删除、导出保留。去掉「是否绑定通知」列和「解除绑定」。操作列增加「查询活跃度」。

弹窗针对这一行人员，分两块：

| 块 | 纳入规则 |
|---|---|
| 已参加 | 当前用户可见，且参加记录指向这个人 |
| 未参加 | 当前用户可见，活动所选俱乐部包含这个人所在俱乐部，且没有这个人的参加记录 |

其他俱乐部的活动两边都不出现。已结束的活动照样出现。每条至少展示活动标题、俱乐部、时间、活动状态，以及出席字样。没有记录时该块为空。

出席字样只出现这三种：

| 情况 | 显示 |
|---|---|
| 有参加记录，且未勾迟到 | 绿字「已签到」 |
| 没有参加记录 | 红字「未签到」 |
| 有参加记录，且勾了迟到 | 绿字「已签到」，另加红字「迟到」 |

不单独显示「未迟到」。小忧用文字说出同样的出席和迟到，不要求对话里标红。

### 身份方案

只存人员 id 时，下面三种情况会让活跃度对不上当前这一行：

| 情况 | 现在导入或编辑会怎样 | 只挂人员 id 的结果 |
|---|---|---|
| 名称没变，人暂时不在某次导入里，之后又出现 | 先删掉该行，再次导入时新建，人员 id 变了 | 旧活动记录随旧行丢掉 |
| 导入把名字认成另一个字，或本人改了游戏名 | 旧名称被删，新名称新建 | 历史留在已删除的人上，新行是空的 |
| 在人员列表里改名 | 同一行改名称，人员 id 不变 | 记录还在。若参加记录只抄了旧名称、不跟 id，反查会断 |

同俱乐部、同名的再次导入会原地更新，id 不变，这种不会丢。

已选定方案 D。没对照的人按方案 B 留下记录。A、C 不采用。

**方案 A：俱乐部 + 玩家名称是主键，人员 id 只是指针**

参加记录保存活动、俱乐部和规范化后的玩家名称。人员 id 可空。同名的人被删掉再创建时，按俱乐部和名称把记录挂到新行。人员列表里改名时，同一事务改掉参加记录上的名称。导入导致名称变化时，不自动把旧历史转给新名字。

同名重建、删了再按原名加回来，活动还在。真正的改名不会跟着走，除非改名动作本身去改参加记录。

**方案 B：人员 id 为主，删除时留记录，同名再认领**

参加记录保存人员 id（可空）、俱乐部和当时的玩家名称。删除人员时不删除参加记录，只把人员 id 清空。之后同一俱乐部出现相同名称，把这些记录挂回新行。人员列表改名时 id 不变，并改掉名称快照。导入把名称改掉时，旧记录变成「有旧名字、没有人员 id」，新行对不上，当前这个人的活跃度里看不到旧活动。

手工改名和同名重建是安全的。导入改名仍然断开。

**方案 C：有活动记录的人不因导入而删除**

某次导入的名单里没有这个人，但这个人已有参加记录：保留该行和人员 id，标记停用。人员列表和签到弹窗默认不显示停用的人。下次导入同名再出现，恢复同一行。人员列表改名仍是改同一行。导入时名称变了，仍是旧名停用、新名新建，历史留在旧名上。

人还在库里，id 不换。离开名单的人会留在库里。导入改名仍要另做合并。

**方案 D：导入时由管理员把旧名对照到新名**

确认导入前，若有参加记录的人这次不见了，同时本次又有新名称，列出旧名和新名。管理员指定「这个旧名就是这个新名」时，不删旧行，只把名称改成新名，参加记录仍挂在原来的人员 id 上。没有对照的人，按方案 B 留下记录，同名再出现时挂回。

真正的改名由人确认，不会把两个不同的人并成一个。每次导入可能多一步。

方案 D 已选定。对照成功时人员 id 不变，参加记录跟着走。没有对照、或这次没有新名称可对照时，删除该行只解开人员 id，记录按俱乐部和旧名称留下；同名再次出现时挂回。不会自动把两个不同名称并成同一个人。

### 小忧：去掉绑定，改为查活动

去掉这些现有能力：

- 意图里的 `binding` 字段，以及「绑定状态」「企业微信」这类问法
- 人员回答和导出表中的「企业微信角色绑定状态」
- 帮助文案里的绑定说明

不发布、不修改、不删除、不结束活动，也不代替管理员勾选。只回答当前用户可见的活动。说不出俱乐部或活动时，沿用现在的确认、选择和追问，不编造名称。

| 工具 | 管理员可以怎么问 | 回答什么 |
|---|---|---|
| `list_activities` | 有哪些活动；某俱乐部有哪些活动；还没结束的；已经结束的 | 可见活动的标题、俱乐部、开始时间、状态。可按俱乐部、已发布或已结束缩小。一场都没有时说明没有 |
| `get_activity` | 某某活动是什么时候；哪些俱乐部 | 标题、俱乐部、开始时间、状态，以及已参加人数、未参加人数。标题对上多场时先选择或确认 |
| `activity_roster` | 这场谁参加了；谁没参加；谁迟到了；参加了多少人 | 已签到名单、未签到名单，或只要其中一边，并给出人数。迟到的人在已签到名单里标明迟到，并另给迟到人数。未签到只含这场所选俱乐部里、没有参加记录的在册人员。名单过长时先说人数，再列名称 |
| `member_activities` | 张三参加了哪些活动；缺了哪些；有没有迟到；参加了几场 | 与「查询活跃度」同一套已签到、未签到、迟到规则，并给出已签到、未签到、迟到的场数。重名时沿用现有的选人。这个人没有任何纳入范围的活动时说明没有 |

帮助文案在原有俱乐部和人员能力之后，补上：查看活动、查看一场的出席、查看某人参加过和没参加的活动。

人员资料查询仍保留排名、等级、途径、非凡评分、风尚度、周活跃、入会时间、数据更新时间。全部资料里不再包括绑定。

## 非功能需求

| 项 | 要求 |
|---|---|
| 权限 | 活动签到与人员列表仍按原菜单分开授权。活动和人员仍限制在可见俱乐部内。小忧不比这个人在后台能看到的更多 |
| 数据 | 已有活动字段不删列。新参加记录与旧的企微签到表分开，不把旧签到当作新勾选结果 |
| 重复保存 | 同一活动、同一人员多次保存不产生多条记录 |
| 身份 | 导入同名原地更新时，活动记录必须还在。改名和「删后再出现」按选定的身份方案，不能静默丢掉已保存的参加记录 |
| 企微 | 活动发布和签到不调用企业微信。绑定列、解除绑定、小忧绑定回答和导出绑定列去掉 |

## 端到端流程

1. 有活动签到菜单的用户在「活动管理 / 活动签到」填写标题、一个或多个俱乐部和时间，发布。
2. 在该行点「签到」，勾选参加的人，需要时再勾迟到，然后保存。再次打开时签到和迟到都还在。
3. 结束后仍可打开签到，补勾或取消。
4. 在人员列表点某一行「查询活跃度」，分别看到已签到和未签到。「已签到」是绿色，「未签到」是红色；勾过迟到的场次再显示红色的「迟到」。
5. 对小忧说「有哪些活动」「这场谁参加了」或「张三参加了哪些」，得到与后台相同范围的只读结果。

## 范围

**In**

- 父菜单「活动管理」，迁入活动签到
- 发布只填标题、俱乐部、时间；活动可改、可删、可结束
- 管理员按活动勾选签到和迟到，多次保存，结束后仍可改
- 活动历史详情里，已签到用绿字，未签到和迟到用红字
- 新建活动与人员的参加关联，并处理导入、改名导致的对不上
- 人员列表「查询活跃度」
- 去掉绑定列、解除绑定、小忧绑定回答和导出绑定列
- 小忧只读查询活动列表、单场详情、出席名单、某人活跃度
- 去掉活动列表上的企微通知操作，以及玩家自助绑定签到这条路径

**Out**

- 单独的「人员参与情况」菜单
- 企业微信发卡片、提醒、OAuth、玩家页签到
- 用浏览器本地存储代替活动表
- 删除活动表上暂不使用的字段
- 把旧的企微签到记录迁移成新的勾选结果
- 小忧发布活动、修改活动或代为勾选
- 签到统计打分、导出参加名单
- 导入时未经确认就自动把两个不同名称并成同一个人

| Q5 | 改活动俱乐部后，已勾选但不在新俱乐部里的人怎么算？ | 参加记录保留，活跃度里仍是已参加。签到弹窗不再列出他们，也不能在弹窗里取消 |
| Q6 | 未参加的范围是「选了该人所在俱乐部的活动」，还是全部可见活动？ | 只比较选了该人所在俱乐部的可见活动。小忧与弹窗相同 |
| Q7 | 「结束」按钮是否保留？ | 保留。结束只改状态，不锁签到，也不锁修改和删除 |
| Q8 | 小忧列出出席名单时，人数很多怎么说？ | 先说已参加、未参加的人数，再列出玩家名称。单边超过 30 人时只列前 30 人，并说明还有多少人 |

## 验收标准

1. 「活动管理」下能打开活动签到，且没有「人员参与情况」。俱乐部管理下没有活动签到。已有该菜单权限的角色刷新后仍能进入。
2. 发布时只能填标题、俱乐部、时间。不选俱乐部、不填标题或时间不能发布。不能选不可见俱乐部。
3. 发布后能修改这三项，也能删除。删除后活动和对应参加记录都不再出现。
4. 签到弹窗只出现这场当前所选俱乐部的人员，每人有签到和迟到。保存后再次打开，两类勾选与上次一致。取消某人的签到再保存，活跃度里此人变为红色的「未签到」，且不再出现「迟到」。只取消迟到时，仍是绿色的「已签到」。
5. 活动历史详情中，「已签到」为绿字，「未签到」和「迟到」为红字。没勾迟到的场次不出现「迟到」。
6. 活动结束后仍可打开签到并保存成功，包括补勾或取消迟到。
7. 同一活动、同一人员无论保存几次，只有一条参加记录。迟到记在这条记录上。
8. 人员列表有「查询活跃度」，没有「是否绑定通知」和解除绑定。弹窗的已签到、未签到互斥，并只包含规则内的可见活动。
9. 同一俱乐部、同一名称再次导入后，这个人原先的参加记录仍能在活跃度里看到，迟到也还在。
10. 人员列表改名后记录仍在。导入改名只有在对照确认之后，才把旧记录算到新名字上。没对照就删除的人，同俱乐部同名再次出现后，原先的参加记录重新出现在这个人的活跃度里。
11. 小忧能回答活动列表、单场时间与出席人数、某人的已签到、未签到和迟到。问绑定状态时不再报已绑定或未绑定。小忧不能发布或修改活动。
12. 活动列表没有重发卡片、重发提醒。发布过程不向企业微信发消息。
