# 需求梳理 · 俱乐部数据采集

把全区服俱乐部排行从一份 JSON 放进后台，再在 Guide 上按表格展示。本版只梳理范围、用例和验收，不涉及实现。

## 产品定位

维护者在 OCR 后台上传排行 JSON，Guide 访客打开俱乐部排行页，看到这份 JSON 里 `clubs` 的表格。

数据以 JSON 为准。`docs/俱乐部数据/rank.png` 只提供版式参考（深色底、表头、前三名强调），不从图片识别文字，也不把图片嵌进页面。

样例文件：`docs/俱乐部数据/club-ranking-2026-11-03.json`。页面只用其中的 `clubs`。

## 用户与用例

两类人：后台超管负责上传；Guide 访客只读。不新增账号体系。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 超管打开采集页 | 「系统管理」下有「俱乐部数据采集」；角色管理的可分配菜单里没有这一项；非超管账号看不到入口，直接访问地址也进不去 |
| UC-02 | Must | 上传 JSON | 选择本地 `.json`；浏览器解析出 `clubs` 后提交到服务端；成功后提示写入条数 |
| UC-03 | Must | 拒绝无效文件 | 不是 JSON、没有 `clubs` 数组、或行缺少必填字段时，不提交、不覆盖已有排行，并说明原因 |
| UC-04 | Must | Guide 首页进入排行 | 首页有「俱乐部排行」入口，点进去是排行页 |
| UC-05 | Must | 查看排行表 | 表体只来自已上传的 `clubs`，列与字段对应见下文；顺序按 `rank` 升序 |
| UC-06 | Must | 再次上传覆盖 | 新文件成功写入后，排行页只显示新的 `clubs`，旧的一组不再出现 |
| UC-07 | Should | 尚无数据 | 从未成功上传时，排行页说明暂无排行，而不是空白报错 |

## 功能拆解

### 后台采集页

位置：Web 端「系统管理」，与账号管理、角色管理、Wiki 内容同组。

权限：不开放。不加入角色可勾选菜单，只有超管能进页面和写入接口。

页面上一个 JSON 文件选择。选中后在浏览器内解析，只把 `clubs` 交给上传接口。`capturedAt`、`source`、`rawText`、图片宽高以及其他顶层字段不上传、不展示。

`clubs` 每一项：

| 展示列 | 字段 | 规则 |
|---|---|---|
| 排名 | `rank` | 整数，必填 |
| 俱乐部 | `name` | 非空文本，必填 |
| 区服 | `server` | 非空文本，必填 |
| 会长 | `leader` | 非空文本，必填；原文照显，含截断号也不改写 |
| 人数 | `memberCount` | 整数，必填 |
| 评分 | `score` | 整数，必填 |

同一份 `clubs` 里 `rank` 不可重复。条数以文件为准，样例为 50，不在页面写死 50。

上传成功即覆盖当前这一份排行。不保留历史榜，不做和上次的升降对比。

### Guide 排行

- 首页增加「俱乐部排行」入口，链到排行页。
- 排行页用表格展示上述六列。版式靠近 `rank.png`：深色底、表头、前三名更醒目。单元格文字只来自 `clubs`。
- 不显示更新时间、区服总数、收录条数、二维码、公众号名称，也不显示 `rawText`。
- 页标题用固定文案「俱乐部排行」，不从 JSON 读取。

这份排行与后台「创建俱乐部 / 人员列表」无关，不写入签到用的俱乐部和人员表。

## 非功能需求

| 项 | 要求 |
|---|---|
| 数据来源 | 只接受已解析的 `clubs`，服务端不再识别图片 |
| 权限 | 写入仅超管；Guide 读取公开，无需登录 |
| 覆盖 | 一次成功上传替换整份当前排行，失败不改旧数据 |
| 原文 | 名称、区服、会长按 JSON 字符串原样保存和显示 |
| 空态 | 没有排行时首页入口仍在，页内提示暂无数据 |

## 端到端流程

1. 超管登录 Web 后台，打开「系统管理 / 俱乐部数据采集」。
2. 选择 `docs/俱乐部数据/club-ranking-2026-11-03.json` 这样的文件。
3. 浏览器读出 `clubs` 并上传；成功后提示条数。
4. 访客打开 Guide 首页，进入「俱乐部排行」。
5. 表格六列与该文件 `clubs` 一致，按 `rank` 从小到大排列。
6. 再上传另一份合法 JSON 后，表格变为新的 `clubs`。

## 范围

**In**

- 系统管理下的采集页，仅超管
- 浏览器解析 JSON，只上传 `clubs`
- 覆盖保存当前排行
- Guide 首页入口和排行表格
- 版式参考 `rank.png`，文案来自 JSON

**Out**

- 识别 `rank.png` 或任何图片
- 展示 `clubs` 以外的 JSON 字段
- 排行历史、名次升降、搜索筛选
- 把排行写入签到俱乐部或人员表
- 把该菜单分配给普通角色
- 二维码、公众号落款、页脚「收录 N 个区」

## 验收标准

1. 超管能在系统管理看到「俱乐部数据采集」；角色编辑页不能勾选这项；用非超管账号访问该地址会被挡回。
2. 用样例 JSON 上传后，Guide 排行表有 50 行，六列与 `clubs` 一致，包含会长名里的 `..` 以及名称中的 `丨` 等字符，不按截图改字。
3. 去掉 `clubs`、或把某一行的 `name` 留空再上传，已发布的排行不变，页面说明原因。
4. 再上传一份只有 1 条合法 `clubs` 的 JSON 后，排行页只剩这一条。
5. 未登录可以打开 Guide 排行页；未上传过时看到暂无数据。
6. 签到后台的俱乐部列表、人员列表不因这次上传增加记录。
