# 需求梳理 · 签到表

源需求是企业微信内的游戏活动签到。人员来自现有数据库，玩家自己点击签到，活动发布和开始前要发通知。本版只梳理范围、用例和验收，不涉及实现。

已确认口径：

- 活动用企业微信可点击卡片发送，玩家点卡片进入活动页。
- 一场活动可以选择多个俱乐部；这些俱乐部同属一个企业微信团队。每个俱乐部只归在这一个团队里。
- 一个企业微信成员只绑定一个游戏角色，一个角色也只绑定一个企业微信成员。
- 提醒时间由管理员填写。
- 活动发布后即可签到，开始时间不作为签到开关。
- 人员列表增加「是否绑定通知」，用来区分谁已绑定、谁未绑定。

源文件名为 `签到表.md`，未使用 `需求-` 前缀。流水线中的 `{名称}` 取「签到表」。

## 产品定位

后台管理员从自己的俱乐部里选择一个或多个，发布一场活动。这些俱乐部都在同一个企业微信团队中。系统通过该团队的内部应用，向管理员选定的部门、标签或成员发送可点击卡片。成员在企业微信里打开卡片，从这些俱乐部里绑定一个角色，再点击签到。

人员名单仍是现有人员表。企业微信只负责认出是哪个成员，以及把卡片和提醒送到应用可见范围内的人。

## 能力分界

| 事项 | 由谁完成 |
|---|---|
| 活动、所属俱乐部、提醒时间、签到记录、角色绑定 | 业务系统 |
| 可签到的角色名单 | 现有人员表中，本场已选俱乐部的人员 |
| 人员列表上的「是否绑定通知」 | 业务系统，按是否已有绑定显示 |
| 打开卡片后识别企业微信成员 | 企业微信内部应用，在企业微信内打开网页 |
| 按部门、标签或成员发送卡片和提醒 | 企业微信发送应用消息；接收人必须在该应用可见范围内 |
| 到提醒时间触发发送 | 业务系统按管理员填写的时间触发，再调用企业微信发消息 |

企业微信通讯录不是人员名单。企业微信打卡不作为签到。

## 用户与用例

后台使用人是已登录的操作者，只能操作自己的俱乐部和人员。玩家不使用邮箱登录，在企业微信内打开活动卡片后识别身份。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 发布一场活动 | 至少选定一个自己的俱乐部，可以多选；填写标题和开始时间后可发布。所选俱乐部属于同一个企业微信团队。发布后这些俱乐部的人可以签到 |
| UC-02 | Must | 发送可点击活动卡片 | 发布时选择企业微信部门、标签或成员中的至少一种；对方在企业微信里能点开卡片进入该活动 |
| UC-03 | Must | 自填提醒 | 管理员填写提醒时间；到点后再次发送可点击卡片 |
| UC-04 | Must | 绑定一个角色 | 未绑定的成员只能从本场已选俱乐部里，选择一个尚未被占用的角色；绑定后人员列表该行显示已绑定 |
| UC-05 | Must | 发布后自己点击签到 | 已绑定且角色属于本场任一已选俱乐部时，发布后即可签到；每场每人只记一次，并记下签到时间 |
| UC-06 | Must | 在人员列表看出绑定情况 | 人员列表增加「是否绑定通知」；已绑定显示「已绑定」，未绑定显示「未绑定」 |
| UC-07 | Must | 查看一场活动的签到情况 | 按活动看到全部已选俱乐部的人员是否已签到，并能区分所属俱乐部；未绑定的人显示未签到 |
| UC-08 | Should | 解除绑错的角色 | 管理员解除后，该行变为「未绑定」，该企业微信成员可以再绑一个未被占用的角色 |
| UC-09 | Should | 通知没送达到时可以再发 | 卡片或提醒发送失败时，活动仍然已发布；管理员可以再次发送 |

## 功能拆解

### 活动

管理员在俱乐部管理中维护活动。一场活动至少选一个俱乐部，可以多选。每个俱乐部只属于一个企业微信团队，本场所选俱乐部必须是这同一个团队里的。不跨团队拼一场活动。

| 字段 | 规则 |
|---|---|
| 标题 | 必填 |
| 所属俱乐部 | 至少选一个，可多选；只能选当前用户的俱乐部，且同属一个企业微信团队；发布后不能改 |
| 开始时间 | 必填，写在卡片上，不限制能否签到 |
| 提醒时间 | 管理员自填具体时间；留空表示不发提醒；有值时必须晚于发布时间 |
| 接收范围 | 发布时必填，部门、标签、成员至少选一种；范围来自企业微信，不是游戏人员名称 |

发布前不能签到，也不发卡片。发布后状态为已发布，签到立即开放。

### 卡片与提醒

发布时发送一条可点击卡片。卡片包含活动标题、本场已选俱乐部的名称、开始时间，以及进入该活动页的链接。发送使用这些俱乐部所在的那一个企业微信团队的内部应用。

提醒时间到点后，再发一条可点击卡片。接收人只包括已经绑定、且角色属于本场任一已选俱乐部的企业微信成员。尚未绑定的人收得到发布卡片，收不到提醒。

接收人不在应用可见范围内时，企业微信不会把消息送到对方。业务系统需留下这次发送是否成功，供管理员查看。

### 绑定

绑定发生在企业微信内打开活动页之后。

- 尚未绑定：列出本场已选俱乐部中还没有被别人绑定的角色，并带上所属俱乐部，成员选一个并确认。
- 已经绑定，且角色属于本场任一已选俱乐部：不再选择，直接进入签到。
- 已经绑定，但角色不属于本场任一已选俱乐部：不能再选角色，也不能签这场。
- 玩家不能自己换成另一个角色。

一个企业微信成员对应一个角色，一个角色对应一个企业微信成员。人员列表不展示企业微信 userid，只显示是否已绑定。

手工新增的人员为未绑定。编辑玩家名称、排名及其他已有列时，不改变绑定状态。再次导入仍按「俱乐部 + 玩家名称」更新同一人时，绑定保留。

### 签到

发布后即可签到，不判断当前时间是否已到开始时间，也没有自动截止。

同时满足下面三条才记为已签到：

1. 活动已发布。
2. 当前企业微信成员已绑定角色。
3. 该角色属于本场任一已选俱乐部。

同一场活动、同一个角色只保留一次签到。再次点击不新增记录，页面显示已有的签到时间。

### 人员列表新增列

在现有人员列表增加一列，列名为「是否绑定通知」，放在「入会时间」和「操作」之间。

| 状态 | 显示 |
|---|---|
| 该角色已有企业微信绑定 | 已绑定 |
| 该角色还没有绑定 | 未绑定 |

这一列来自绑定关系，不出现在新增、编辑表单里，也不能手改成已绑定。俱乐部筛选、玩家名称关键字、原有各列和表头排序保持原样。新列可以按表头排序。

删除人员时，若该行已绑定，绑定一并去掉。该企业微信成员之后可以再绑一个未被占用的角色。同俱乐部其他人的绑定不变。

### 活动签到情况

按某一场活动查看全部已选俱乐部的人员。至少包含玩家名称、所属俱乐部、是否绑定通知、是否已签到、签到时间。未签到的人没有签到时间。未选中的俱乐部的人员不出现在这场里。

## 非功能需求

| 项 | 要求 |
|---|---|
| 界面 | 后台继续使用浅蓝色 Element Plus；人员列表仍是 `el-table` |
| 身份 | 玩家身份只在企业微信内打开活动页时识别；识别结果对应企业微信成员 |
| 发送前提 | 使用企业微信内部应用；活动链接所在域名已配置为企业微信可信域名，且为 HTTPS |
| 可见范围 | 只有应用可见范围内的成员能收到卡片和提醒 |
| 归属 | 不能发布、查看或签到别人的俱乐部活动；绑定目标必须是本场已选俱乐部中的人员。同一场活动不跨企业微信团队 |
| 失败 | 消息发送失败时，不回滚已发布状态，也不抹掉已有签到 |

本地 `localhost` 不能完成真实的企业微信打开、身份识别和发卡片。这项依赖管理后台里的应用、可信域名和 IP 白名单。

## 端到端流程

1. 登录后台，选择自己的一个或多个俱乐部，填写活动标题、开始时间和接收范围，提醒时间可留空，然后发布。这些俱乐部都在同一个企业微信团队里。
2. 接收范围内的成员在企业微信中看到可点击卡片，点开进入这场活动。
3. 未绑定的成员从这些俱乐部尚未占用的角色里选一个。人员列表对应行变为「已绑定」。
4. 绑定的角色属于本场任一已选俱乐部时，成员点击签到。再次点开仍显示这一次的签到时间。
5. 管理员打开这场活动的签到情况，能看到各已选俱乐部中谁已签、谁未签。未绑定的人显示未绑定、未签到。
6. 若填写了提醒时间，到点后已绑定且角色属于本场已选俱乐部的成员再收到一条可点击卡片。未绑定的人不会收到这条提醒。

## 范围

**In**

- 一场活动可选择多个同属一个企业微信团队的俱乐部，并用该团队的可点击卡片通知
- 管理员自填提醒时间；到点提醒已绑定且角色属于本场已选俱乐部的成员
- 企业微信内绑定一个角色，发布后自己点击签到，每场一次
- 人员列表增加「是否绑定通知」
- 按活动查看全部已选俱乐部人员的签到情况

**Out**

- 活动二维码、个人微信扫码、线下扫码签到
- 用企业微信通讯录代替现有人员表
- 用企业微信打卡记录代替点击签到
- 一个企业微信成员绑定多个角色，或一个角色被多人绑定
- 在人员列表展示或手填企业微信 userid
- 开始时间未到时禁止签到，或到开始时间后自动关闭签到
- 按游戏玩家名称直接作为卡片接收人
- 一场活动跨多个企业微信团队
- 一个俱乐部同时属于多个企业微信团队

## MoSCoW

| 级别 | 内容 |
|---|---|
| Must | UC-01 至 UC-07；一活动可多选俱乐部，且这些俱乐部同属一个企业微信团队；一人一角色；发布后可签到；提醒时间自填；人员列表能区分已绑定和未绑定 |
| Should | UC-08、UC-09；删除已绑定人员时同时去掉绑定；发送结果可查看 |
| Could | 按「是否绑定通知」筛选人员 |
| Won't | 二维码签到；企业微信打卡；玩家自行换绑；跨企业微信团队选择俱乐部 |

## 待澄清

| ID | 问题 | 不答复时的暂定 |
|---|---|---|
| Q1 | 提醒时间能否留空？ | 可以。留空不发提醒；填写时必须晚于发布时间 |
| Q2 | 已发布的活动能否结束？ | 管理员可以结束。结束后不能再签，已有签到保留。不提供自动结束 |
| Q3 | 绑错了由谁解除？ | 玩家不能自己换绑。管理员在人员列表对已绑定行解除绑定，该列变为「未绑定」 |
| Q4 | 删除已绑定人员后，企业微信成员能否再绑？ | 可以。删除人员时绑定去掉，之后只能选择当时还没被占用的角色 |
| Q5 | 签到情况放在哪里？ | 放在俱乐部管理的活动中，按某一场活动查看，不另做独立人员维度的签到总表 |

## 验收标准

1. 发布活动时至少选定一个自己的俱乐部，可以同时选多个；不能选别人的俱乐部。所选俱乐部属于同一个企业微信团队。
2. 发布后，选定范围内的成员能在企业微信中点开卡片进入这场活动。
3. 未绑定成员只能从本场已选俱乐部中选择一个尚未被占用的角色；绑定成功后，人员列表该行「是否绑定通知」为「已绑定」。
4. 同一企业微信成员不能再绑定第二个角色；已被占用的角色不能被另一个成员选中。
5. 已绑定且角色属于本场任一已选俱乐部时，发布后可以签到；同一场再次点击不产生第二条签到。
6. 已绑定但角色不属于本场任一已选俱乐部时，不能签这场，也不能改绑到本场俱乐部的角色。
7. 未发布不能签到。开始时间早于或晚于当前时间，都不改变「发布后即可签到」。
8. 人员列表原有筛选、排序、新增、编辑、删除仍可用。新列不在新增和编辑表单中，未绑定的新人员显示「未绑定」。
9. 填写的提醒时间到达后，只有已绑定且角色属于本场已选俱乐部的成员收到提醒卡片。
10. 使用别人的俱乐部、活动或人员时不能发布、不能查看签到、不能绑定。
