# 需求梳理 · 新增后台账号+角色管理

源需求是后台账号、角色和菜单权限。本版只梳理范围、用例和验收，不涉及实现。

已确认口径：

- 预置一个超级管理员。它拥有全部菜单，能看到全部俱乐部，不依赖俱乐部绑定。
- 一个账号只绑定一个角色。
- 菜单是固定目录。登录成功后调用 `POST /permission` 获取当前账号可见菜单。该接口路径为小写，必须携带登录 JWT，只返回菜单。
- 角色同时绑定菜单和俱乐部。俱乐部、人员、导入、活动的可见范围跟角色上的俱乐部绑定走。
- 新建俱乐部时，自动绑到创建者当前角色。超级管理员创建的俱乐部，其他角色要在角色上再勾选才可见。
- 登录继续用邮箱和密码。停用账号不能登录。
- 已有账号只保留超级管理员可登录，其余全部停用。停用后可以在账号管理里再次启用。
- 玩家签到（企业微信内打开的活动页）不进入这套后台角色。

源文件名为 `新增后台账号+角色管理.md`，未使用 `需求-` 前缀。流水线中的 `{名称}` 取「新增后台账号+角色管理」。

## 产品定位

后台从「谁都可以注册，登录后菜单和自己创建的俱乐部全开」改为「超级管理员维护账号和角色，登录后按角色显示菜单，并按角色绑定的俱乐部看到数据」。

侧栏不再写死。菜单从一份固定目录里勾选，登录成功后向 `POST /permission` 要当前可见菜单，再渲染侧栏。没有某项菜单时，侧栏不出现，直接打开对应地址也进不去。

能否看到某个俱乐部，看角色有没有绑定它，不看是谁创建的。人员、导入、活动挂在俱乐部上，跟着同一条绑定走。

## 用户与用例

使用人是后台账号。超级管理员是预置账号。其他账号由拥有「账号管理」菜单的人创建，创建时指定一个角色。玩家仍在企业微信内识别，不使用这套邮箱账号。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 超级管理员登录 | 预置账号用邮箱和密码登录成功；侧栏为全部固定菜单；能看到全部俱乐部 |
| UC-02 | Must | 登录后获取菜单 | 登录成功后调用 `POST /permission`，请求带登录 JWT；侧栏只显示返回的菜单 |
| UC-03 | Must | 维护后台账号 | 可按邮箱新增、查询、修改、删除账号；每个账号必选且只能选一个角色；新建时设置密码 |
| UC-04 | Must | 停用与再次启用 | 停用后该邮箱不能登录；账号列表能看出停用；可再次启用并恢复登录 |
| UC-05 | Must | 维护角色 | 可新增、查询、修改、删除角色；角色名称必填；保存时带上勾选的菜单和俱乐部 |
| UC-06 | Must | 按角色看到俱乐部数据 | 普通账号只能看到其角色已绑定的俱乐部，以及这些俱乐部下的人员、导入和活动 |
| UC-07 | Must | 新建俱乐部自动绑定 | 普通账号新建俱乐部后，该俱乐部立即属于其当前角色，创建者马上能看到 |
| UC-08 | Must | 没有菜单不能进页面 | 角色未勾选的菜单不出现在侧栏；直接访问对应地址不能进入该功能 |
| UC-09 | Must | 已有账号停用 | 除预置超级管理员外，已存在的后台账号均为停用，不能登录；其名下已有俱乐部仍在，超级管理员可见 |
| UC-10 | Should | 修改账号密码 | 编辑账号时可以设置新密码；留空则不改变原密码 |

## 功能拆解

### 固定菜单

菜单是一份固定目录，账号管理和角色管理里的勾选、以及登录后的侧栏，都用这一份，不在页面上另写一套。

| 目录 | 子菜单 |
|---|---|
| 俱乐部管理 | 创建俱乐部、导入人员、人员列表、活动签到 |
| 系统管理 | 账号管理、角色管理 |

「活动签到」覆盖活动列表和某一场活动的详情。这两处不单独做成两个菜单。

企业微信内的玩家活动页不在目录中，也不由 `POST /permission` 控制。

### 超级管理员

系统预置一个超级管理员账号，以及它专用的超级管理员角色。

- 拥有上表全部菜单。
- 能看到全部俱乐部，包括尚未绑给任何普通角色的俱乐部。
- 该账号和该角色不可删除。
- 不能停用这个账号，也不能改掉它的角色。
- 它新建的俱乐部其他角色默认看不见，需要在角色管理里勾选后才进入该角色。

### 账号

| 字段 | 规则 |
|---|---|
| 邮箱 | 必填，作为登录名，不可与已有账号重复 |
| 密码 | 新建必填，至少 8 位；修改时可选，留空表示不改 |
| 名称 | 可空 |
| 角色 | 必填，且只能选一个 |
| 状态 | 启用或停用；新建默认启用 |

停用账号调用登录时拒绝，不签发登录凭证。再次启用后按原角色登录。

不能删除自己，不能停用自己。已有数据里除超级管理员外的账号，在本需求落地时置为停用。

自助注册关闭。登录页不再提供注册入口。

### 角色

| 字段 | 规则 |
|---|---|
| 名称 | 必填 |
| 菜单 | 从固定目录多选，可以一项都不选 |
| 俱乐部 | 多选已有俱乐部，可以一项都不选 |

一个账号只有一个角色，因此该账号的菜单和俱乐部都只来自这一个角色。

仍有账号使用的角色不能删除，需先把这些账号改到其他角色。超级管理员角色不可删除，也不按俱乐部绑定来限制它能看到的数据。

### 登录与 `/permission`

1. 使用邮箱和密码登录。停用账号登录失败。
2. 登录成功后，前端调用 `POST /permission`。
3. 该接口校验登录 JWT，按当前账号的角色返回可见菜单。请求体不另传账号标识。
4. 侧栏按返回结果渲染。返回里没有的菜单，对应页面不能进入。
5. 接口不返回俱乐部列表。俱乐部仍走俱乐部相关能力，但结果受角色绑定限制。

角色未勾选任何菜单时，允许登录，侧栏为空，不能进入业务页面。

### 俱乐部数据范围

普通账号能查看、修改、删除的俱乐部，以及能导入人员、查看人员、发布和查看活动的俱乐部，均为其角色已绑定的那些。

新建俱乐部成功后，自动加入创建者当前角色的绑定列表。创建者刷新后能在自己的俱乐部列表里看到它。超级管理员不靠这条绑定，本来就能看到。

把已有俱乐部分给其他角色，在角色管理里勾选。取消勾选后，该角色下的账号不再看到这个俱乐部及其人员、导入和活动。

本需求之前「只能操作自己创建的俱乐部」不再作为可见范围。创建人可以留下，但不决定谁能看见。

## 非功能需求

| 项 | 要求 |
|---|---|
| 界面 | 后台继续使用浅蓝色 Element Plus |
| 登录 | 邮箱 + 密码；停用账号不能登录 |
| 权限接口 | `POST /permission`，路径小写，必须通过 JWT 校验 |
| 菜单 | 固定目录只维护一份，侧栏与角色勾选一致 |
| 数据范围 | 普通账号的俱乐部、人员、导入、活动都不超出其角色绑定 |
| 预置账号 | 超级管理员由环境配置邮箱和初始密码，不把密码写进仓库 |
| 玩家端 | 企业微信活动页的身份方式保持不变 |

## 端到端流程

1. 使用预置超级管理员登录。`POST /permission` 返回全部菜单，俱乐部列表包含已有全部俱乐部。
2. 新建一个角色，勾选部分菜单和部分俱乐部。
3. 新建一个启用账号，指定该角色和邮箱、密码。
4. 用该账号登录。侧栏只有角色勾选的菜单；俱乐部列表只有角色绑定的俱乐部。
5. 该账号新建一个俱乐部。保存后这个俱乐部出现在它的列表中，并属于它的角色。超级管理员也能看到。另一个未绑定该俱乐部的角色看不到。
6. 超级管理员把该账号停用。该邮箱再次登录失败。再次启用后可以登录，菜单和俱乐部与停用前的角色一致。
7. 直接访问未授权菜单地址时，不能进入对应功能。

## 范围

**In**

- 预置超级管理员，并停用其余已有后台账号
- 账号的增删改查、停用和再次启用
- 角色的增删改查，以及角色绑定固定菜单和俱乐部
- 一个账号一个角色
- 登录成功后 `POST /permission` 决定侧栏和能否进入页面
- 新建俱乐部自动绑到创建者当前角色
- 人员、导入、活动跟随俱乐部绑定
- 关闭自助注册

**Out**

- 一个账号绑定多个角色
- `/permission` 返回俱乐部或接口权限码
- 菜单目录本身的增删改
- 忘记密码、邮件重置密码
- 玩家签到页纳入后台角色
- 按创建人隔离俱乐部
- 自助注册

## MoSCoW

| 级别 | 内容 |
|---|---|
| Must | UC-01 至 UC-09；固定菜单；`POST /permission` 带 JWT 且只返回菜单；一账号一角色；新建俱乐部自动绑定；已有非超级管理员账号停用 |
| Should | UC-10；账号列表能按邮箱查看状态 |

## 待澄清

| ID | 问题 | 不答复时的暂定 |
|---|---|---|
| Q1 | 超级管理员的初始邮箱和密码放在哪里？ | 由环境配置提供，不写入仓库。尚未配置时不能靠注册页补出一个超级管理员 |
| Q2 | 拥有账号管理、但不是超级管理员的人，能否改超级管理员？ | 不能删除、停用或更换超级管理员的角色，也不能把超级管理员角色赋给其他账号 |
| Q3 | 拥有角色管理的普通账号，能把哪些俱乐部分给角色？ | 只能分配自己已经能看到的俱乐部。超级管理员可以分配全部 |
| Q4 | 角色名称是否唯一？ | 唯一，重名时拒绝保存 |
| Q5 | 删除仍有账号的角色？ | 拒绝删除，并说明仍有账号在使用 |
| Q6 | 能否删除或停用自己？ | 不能 |
| Q7 | 修改角色或账号的角色后，已登录的人何时按新权限生效？ | 下一次获取菜单和读取俱乐部数据时生效，不强制立刻退出登录 |
| Q8 | 角色一项菜单都没勾，能否登录？ | 可以登录，侧栏为空，不能进入业务页面 |

## 验收标准

1. 预置超级管理员可以登录，看到全部固定菜单和全部俱乐部。
2. 除该账号外，需求落地前已存在的后台账号不能登录；这些账号可以在账号管理中再次启用。
3. 登录成功后会请求 `POST /permission`。未携带有效 JWT 时该接口拒绝。返回结果中没有的菜单不会出现，直接打开对应地址也不能进入。
4. 新建账号必须填写邮箱、密码和一个角色；邮箱重复不能保存；密码少于 8 位不能保存。
5. 停用账号不能登录；再次启用后可以登录，且菜单和俱乐部与其角色一致。
6. 普通账号只能看到角色已绑定的俱乐部，以及这些俱乐部下的人员、导入和活动；看不到未绑定的俱乐部。
7. 普通账号新建俱乐部后，无需超级管理员再操作，创建者即可在列表中看到该俱乐部。未绑定该角色的其他账号看不到。
8. 超级管理员能看到普通账号新建的俱乐部。另一个角色在被勾选该俱乐部之前看不到它。
9. 不能删除超级管理员账号和超级管理员角色；不能删除仍有账号使用的角色；不能删除或停用当前登录账号自己。
10. 登录页不能再注册新账号。企业微信内打开活动页不要求后台角色。
