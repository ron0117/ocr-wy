# 需求梳理 · 签到表 2.0

源需求：`docs/requirements/签到表2.0.md`。在**当前后台活动签到（管理员勾选、写 `activity_attendances` + `memberId`）**之上，改为**公开 HTML 自助报名**，并增加**活动查看（删改、迟到/未到、导出）**；**签到表 1.0（企业微信绑定与玩家自助签到）作废**。小忧本阶段不改。

已确认口径见下文「已定决策」；流水线 `{名称}` 取 **签到表2.0**。

## 产品定位

管理员在「活动管理 / 活动签到」发布活动（字段与现网一致）。发布后在后台**页面内展示**该活动的公开链接与二维码，自行传播。玩家打开链接（**无 token、无企微**）填写报名表单；系统写入**新报名记录表**，不与人员表联动。管理员在「活动管理 / 活动查看」按活动查询名单，可删改记录、标记迟到或未到，并导出 Excel。

公开页为**可嵌入别处的 Vue 组件/路由**，不套后台 `AppShell`，移动端友好。

## 已定决策（澄清结论）

| 主题 | 结论 |
|---|---|
| 发布字段 | 标题、俱乐部（多选）、开始时间、备注；不恢复企微提醒/接收人 |
| 二维码 | 后台页面内展示（随活动，非仅下载文件） |
| 企微通知 | 不需要 |
| 公开访问 | 知道链接即可报名；按 **活动 + IP** 限流，每 IP 每活动最多 **5 次**成功提交，超出提示「您已报名多次，报名失败」 |
| 表单俱乐部 | **仅限本场活动已选俱乐部**（下拉数据源为活动关联俱乐部，不是全库） |
| 公开页形态 | 可嵌入组件；无 AppShell；移动端友好 |
| 查看入口跳转 | 活动签到列表操作「活动人员列表查看」→ **同窗口**路由到活动查看，并带上活动 id |
| 重复规则 | 同活动 + 同俱乐部 + 同非凡者名称 → 拒绝，提示「当前活动已报名」 |
| 存储 | **新建表**存报名信息；**不写 `members`**；**新数据不写 `memberId`** |
| 评分 | 纯数字，最多 6 位**正整数** |
| 职业 | 仅报名快照（观众、歌颂、窥秘、战士、学徒、占卜）；**不回写** `members.path` |
| 改报 | 玩家**不可**自行修改；误选俱乐部视为**另一条新记录**（名称相同但俱乐部不同允许） |
| 后台勾选签到 | **不保留**原「签到」弹窗多选 |
| 导入↔活跃度 | **删除**与 `members` 的联动（对照认领、orphan 挂回、改名同步参加记录等） |
| 旧 `activity_attendances` | **保留只读**；新报名走新表；`memberId` 列逻辑废弃 |
| 活动查看能力 | 删改参会记录；标记**迟到**、**未到**；表格支持 **order 排序** |
| 查询条件 | **必须先选活动**；活动默认 **最新一场**（按发布时间或创建时间降序第一条，无活动则空） |
| 俱乐部筛选 | 活动查看页可选俱乐部（限定在该活动已选俱乐部范围内） |
| 权限 | 活动查看**不**按角色/俱乐部做数据过滤（任意登录用户可选活动、看该活动全部报名）；**活动查看**菜单对**所有已登录后台用户**展示，不必单独配权限；已有「活动签到」权限的角色自然也可进入 |
| 导出 | 当前筛选结果**全量**、不分页；样式与交互对齐现有「导出人员」（ExcelJS _workbook） |
| 文档优先级 | 签到表 1.0 作废；活跃度需求里「管理员勾选 + member 联动」被本版替代 |
| 小忧 | 本阶段不增加/不改造活动报名相关能力 |
| 出席状态 C3 | **互斥三态**：正常 / 迟到 / 未到；新报名默认 **正常**；管理员在活动查看切换，不可同时迟到且未到 |
| 公开报名开关 C4 | 仅 **`PUBLISHED`** 可提交；**`ENDED`** 关闭（链接可打开但提交拒绝并提示） |
| 公开 URL C5 | **`{WEB_ORIGIN}/a/{activityId}`**，与旧签到表文档一致 |

## 功能拆解

### 活动发布（后台 · 活动签到）

与现网一致：

| 字段 | 规则 |
|---|---|
| 标题 | 必填 |
| 俱乐部 | 至少一个，多选；可见范围仍按现网活动发布规则（发布者可见俱乐部） |
| 开始时间 | 必填 |
| 备注 | 选填 |

发布后展示：

- 公开 URL：`{WEB_ORIGIN}/a/{activityId}`（路由 `/a/:activityId`，不套 AppShell）
- 二维码（页面内渲染，可扫码打开同一 URL）

不调用企业微信发消息。

### 公开报名页（组件）

| 字段 | 规则 |
|---|---|
| 俱乐部 | 下拉，选项 = 该 `activityId` 在 `activity_clubs` 中的俱乐部 |
| 非凡者名称 | 必填；与俱乐部、活动一起做唯一性校验 |
| 当前最高评分 | 必填；1–999999 的正整数（最多 6 位） |
| 职业 | 下拉：观众、歌颂、窥秘、战士、学徒、占卜 |
| 签到按钮 | 二次确认后提交 |

**Out：** 登录、token、企微身份、修改已报记录、迟到/未到（玩家侧不填）。

服务端：

- 记录提交 IP（用于限流与审计）
- 限流：同一 `activityId` + 同一 IP，累计 **5 次成功创建** 后拒绝（失败文案：「您已报名多次，报名失败」）
- 重复：违反 `(activityId, clubId, playerName)` 唯一 → 「当前活动已报名」

### 新报名记录表（概念模型）

与 `members`、`activity_attendances.memberId` **解耦**。建议字段（设计阶段定稿）：

| 字段 | 说明 |
|---|---|
| activityId | 所属活动 |
| clubId | 报名时选的俱乐部（须属于该活动） |
| playerName | 非凡者名称 |
| score | 正整数，最多 6 位 |
| profession | 职业快照（枚举/字符串） |
| submitIp | 提交 IP |
| attendanceStatus | 枚举 **NORMAL / LATE / ABSENT**，互斥；创建时 **NORMAL** |
| createdAt / updatedAt | 创建、最后修改时间 |

旧表 `activity_attendances`：历史数据只读展示（若仍需查看入口，可仅只读查询或不再入口展示；本版主路径为新表）。

### 活动查看（后台 · 新菜单）

父菜单：**活动管理** → 子菜单：**活动查看**（新路由）。

| 能力 | 规则 |
|---|---|
| 活动选择 | 必选；下拉取活动表；默认选中**最新一场**；从活动签到跳转时选中传入 id |
| 俱乐部筛选 | 可选；选项为该活动已选俱乐部；空 = 全部 |
| 列表 | 展示报名记录 + 迟到/未到状态；支持表头 **order** 排序（字段在设计中列全） |
| 删 | 删除单条报名记录 |
| 改 | 可改俱乐部（仍须属于该活动）、名称、评分、职业等（改后仍遵守唯一约束） |
| 标迟到 / 未到 | 管理员将 `attendanceStatus` 设为正常、迟到或未到（三选一） |
| 导出 | 当前活动（+ 俱乐部筛选）下全部记录，不分页；_workbook 风格对齐 `export-members.ts` |

活动签到列表增加操作：**活动人员列表查看** → 路由到活动查看并带 `activityId`（同窗口）。

### 废弃与清理

| 项 | 处理 |
|---|---|
| 活动签到「签到」弹窗 | 移除 |
| `activity_attendances` 新写入 | 停止；`memberId` 不再使用 |
| 导入对照 / orphan 认领 / 改名 sync 参加记录 | 删除逻辑 |
| 人员列表「查询活跃度」依赖旧参加记录 | 仍可读历史 `activity_attendances`；**新报名不计入**（除非另定） |
| 签到表 1.0 / 企微玩家签到 | 作废，不恢复 |
| 小忧 | 不改造 |

## 非功能需求

| 项 | 要求 |
|---|---|
| 公开页 | 移动端友好；可嵌入；无后台壳 |
| 安全 | 无 token；IP 限流 5 次/活动；活动 id 不可猜测性不在本版强制（若需 UUID 已满足） |

## 端到端流程

1. 管理员发布活动，复制链接或展示二维码。
2. 玩家打开链接，选俱乐部、填名称/评分/职业，确认报名。
3. 系统校验重复与 IP 次数，写入新表。
4. 管理员在活动查看选活动（或从活动签到跳转），筛选、排序、改删、标迟到/未到，必要时导出。

## 验收标准

1. 发布活动仅含标题、俱乐部、开始时间、备注；页内可见链接与二维码；无企微发送。
2. 公开页无 token、无 AppShell；俱乐部下拉仅该活动已选俱乐部；移动端可用。
3. 同活动+俱乐部+非凡者名称重复提交 → 「当前活动已报名」。
4. 同活动同 IP 成功报名满 5 次后 → 「您已报名多次，报名失败」。
5. 评分非正整数或超过 6 位 → 校验失败。
6. 新数据进入新表；不写 `members`、不写 `memberId`。
7. 活动签到无勾选签到弹窗；有「活动人员列表查看」跳转活动查看且活动已选中。
8. 活动查看必选活动，默认最新一场；俱乐部可筛；可删改、标迟到/未到、表头排序、导出全量。
9. 导入/人员维护不再改变新表；旧 `activity_attendances` 联动逻辑已移除，历史只读。
10. 所有已登录后台用户可见「活动查看」菜单；活动查看数据不按俱乐部角色过滤。
11. 出席状态仅正常 / 迟到 / 未到三态，新记录为正常；管理员可改，不可双标。
12. 活动 `ENDED` 时公开页不可成功报名；`PUBLISHED` 可报。
13. 公开链接路径为 `/a/{activityId}`，与 `{WEB_ORIGIN}` 拼接后可访问。
