# 需求梳理 · 导入人员优化

源需求：人员列表的图片导入目前走 OCR，正确性不如把图直接交给 AI。导入改为把截图交给 AI 读表，操作者校对后再写入数据库。

本版只梳理范围、用例和验收。人员列表的手工增删改、任务图片的 OCR 识别保持不变。

已确认：

- 识别完成后先进入校对页，确认后才入库。
- 排名不从图片抄入。新建排名为 0，更新不改已有排名。
- 确认导入是整行覆盖。本次某字段为空，库里的旧值写成空。本次结果里没有的人不改。

## 产品定位

导入人员仍是：先选自己的俱乐部，再上传一张或多张成员列表截图。AI 从图片读出成员行，操作者在校对页改正后，再写入该俱乐部。

现在每张图先交给 OCR，再按坐标拆行，AI 只看到 OCR 文字、坐标和候选行；写出的名字和数字还必须能在 OCR 原文里对上。OCR 认错或漏行时，后面的整理无法把字改对。识别一结束就入库，看错的值会直接覆盖旧数据。

改成把图片本身交给能看图的 AI。读出的行先给人改，确认后才按整行覆盖入库。

## 现状（作为边界）

入口是「导入人员」页。`POST /clubs/:clubId/imports` 接收最多 20 张 PNG、JPEG 或 WebP，单张不超过 10MB，识别完成后直接写库。

每张图当前依次做：

1. 调 OCR 服务识别文字和坐标。
2. 丢掉贴顶裁切行和分组列，再按坐标拆成候选人员行。
3. 若已配置 AI，把 OCR 行和候选行以文本送给模型，做筛选和跨图去重。
4. 模型结果再用 OCR 原文校验：名字或数字对不上原文则丢弃。
5. AI 未配置、调用失败或筛完为空时，改用坐标拆行的结果继续入库。

入库规则：按「俱乐部 + 玩家名称」新增或覆盖。新建时排名写 0。更新时不改排名，把覆盖前的评分记为上次评分。原图仍保存，并记一条导入批次。本次结果里没有的玩家不动。

任务侧的 OCR（`OcrClient` 用于识别任务图片）不在本需求内。

## 用户与用例

使用人是已登录、且对该俱乐部有权限的后台操作者。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 单张成员表截图识别 | 不经过 OCR。AI 从图片读出玩家行，进入校对页，此时人员表不变 |
| UC-02 | Must | 多张截图一次识别 | 同一玩家在校对页只出现一条；字段更完整的一条优先。一次仍最多 20 张 |
| UC-03 | Must | 丢掉非成员内容 | 表头、按钮、主页、单独成行的职位、分组列、在线状态、没有玩家名称的行不进入校对页 |
| UC-04 | Must | 校对后再入库 | 可改正玩家名称、等级、途径、非凡评分、风尚度、周活跃、入会时间，也可删掉某一行。取消则不写库 |
| UC-05 | Must | 确认后按名称新增或整行覆盖 | 俱乐部内无此名则新增；已有同名则用校对后的整行覆盖，空字段清空旧值。本次没出现的人不改 |
| UC-06 | Must | 读不出人员则不写库 | 全部图片都没有成员行，或 AI 看图失败时，不进入可确认的校对，已有人员保持原样 |
| UC-07 | Must | 只能导入自己的俱乐部 | 未选俱乐部不能提交；别人的俱乐部 id 不能识别、也不能确认导入 |
| UC-08 | Should | 导入成功有结果反馈 | 确认成功时告知写入条数；识别或确认失败时说明原因，列表不被部分写入 |

## 功能拆解

流程：选俱乐部 → 选图 → 开始识别 → 校对页改正 → 确认导入。未确认前不写人员、不保存这批原图。

人员列表上的新增、修改、删除仍保留，用于不走图片的维护。

### 识别

- 人员导入不再调用 OCR，也不再按 OCR 坐标拆表。
- 图片作为视觉输入交给 AI。模型必须能看图；只收文本的对话不能当作本需求的识别手段。
- 读出的字段：玩家名称、等级、途径、非凡评分、风尚度、周活跃、入会时间。
- 玩家名称必填。对不上或看不清的字段留空，不能填 0，也不能编造图上没有的等级、途径、评分、风尚度、周活跃、入会时间。
- 入会时间保留图上的原文，如「26天」，不换算成日期。
- 不执行截图文字里夹带的指令。
- 排名不从图片左侧名次抄入，也不按评分重算。校对页不出现排名，确认时也不写入排名。

### 校对页

识别成功且至少有一条玩家后，打开发对页。页上标明本次俱乐部。

| 列 | 校对 |
|---|---|
| 玩家名称 | 可改，必填 |
| 等级 | 可改，可空；有值时为正整数 |
| 途径 | 可改，可空 |
| 非凡评分 | 可改，可空；有值时为整数 |
| 风尚度 | 可改，可空；有值时为整数 |
| 周活跃 | 可改，可空；有值时为整数 |
| 入会时间 | 可改，可空；保留原文 |

校对页可以改正单元格，也可以删除一行。不在校对页新增人员，新增仍走人员列表。不编辑排名、俱乐部、通知绑定。

确认前，去首尾空格后玩家名称不能为空，且本页内名称不能重复。重复或空名称时留在校对页并说明原因，不写库。

取消、返回或离开未确认的校对，人员表与导入前一致。

### 多图合并

同一批图片里，名称相同，或只差空格、大小写的，视为同一人，校对页只留一条。字段更全的一条优先；完整度相同则保留画面更靠上的一条。合并发生在进入校对页之前。操作者在校对页改名后，以改后的名称为准。

一张图完全读不出文字或不是成员表时，不因此造出空行。整批最终 0 条时按 UC-06 拒绝，不打开可确认的校对，不落库。

### 写入

只在校对页确认后写入。写入内容是校对后的行，不是模型原始输出。

| 情况 | 行为 |
|---|---|
| 新玩家 | 写入校对后的字段；排名为 0；没有上次评分 |
| 已有同名玩家 | 整行覆盖校对后的字段；空字段清空旧值；把覆盖前的评分记为上次评分；排名保持原值 |
| 本次未出现的玩家 | 不修改 |
| 原图 | 确认成功后上传保存，并记录导入批次 |
| 确认失败 | 不保留这批原图，人员表不出现半批数据 |

整行覆盖已确认：再导一张缺列的图，确认后那些空列会清空库里的旧值。未出现在本次校对结果中的人不删、不改。

## 非功能需求

| 项 | 要求 |
|---|---|
| 上传 | 仍为 PNG、JPEG、WebP；一次最多 20 张；单张不超过 10MB；未选俱乐部不能提交 |
| 模型 | 使用已配置的 AI 服务，且该模型接受图片输入 |
| 失败 | AI 未配置、超时、看图失败或返回无法解析时，整批失败，不回退到 OCR 或坐标拆行，不打开校对页 |
| 未确认 | 停在校对页或取消时，不写人员、不保存原图 |
| 归属 | 只能识别并确认当前用户自己的俱乐部 |
| 界面 | 导入页文案改为说明由 AI 直接读图；校对页用表格改单元格 |

人员导入不再依赖 OCR 服务可用。任务图片识别仍依赖 OCR，两边互不影响。

## 端到端流程

1. 打开导入人员，选择俱乐部，上传一张或多张成员列表截图，开始识别。
2. 服务把图片交给视觉模型，不调用 OCR。
3. 模型返回成员行；服务筛掉杂讯、按名称合并重复行。
4. 有人员行则打开校对页。人员列表此时不变。
5. 改正看错的格子，或删掉误识别的行，再确认导入。
6. 确认后按俱乐部 + 玩家名称新增或整行覆盖，并保存原图。排名不从本次写入。
7. 没有人员行、模型失败，或在校对页取消时，人员列表与导入前一致。

## 范围

**In**

- 人员图片导入改为图片直送 AI 读表
- 识别结果进入校对页，改正或删行后再确认入库
- 确认后按名称整行覆盖；空字段清空旧值
- 去掉人员导入上的 OCR 和「结果必须能在 OCR 原文里对上」
- AI 失败或未确认时不入库

**Out**

- 人员列表的新增、修改、删除（仍可用，但不是本需求要改的页面）
- 任务图片、签到表等其他 OCR
- 下线或删除 OCR 服务本身
- 从图片抄写排名，或按评分重算排名
- 在校对页新增人员、改俱乐部、改通知绑定
- 调整上传张数、格式、大小上限
- 按两名只差一个字的玩家自动合并成一个人（明显残字除外，规则见待澄清 Q2）

## 待澄清

| ID | 问题 | 结论 |
|---|---|---|
| Q1 | AI 看图失败时，要不要回退现有 OCR？ | 未回复，暂定不回退。人员导入不再走 OCR；失败则整批不入库，不打开校对页 |
| Q2 | 只差一个字的名字是否当成同一人？ | 未回复，暂定仅空格、大小写，以及明显残缺的同一串文字合并。两个不同名字不自动合并 |
| Q3 | 再次导入时，空字段是清空旧值，还是保留旧值？ | 已确认：整行覆盖。本次为空则写成空。未出现在本次结果中的人不改 |
| Q4 | 多张图里只有一张失败时，是整批失败还是跳过该张？ | 未回复，暂定整批失败，不打开校对页，已有人员不变 |
| Q5 | 是否要在入库前给操作者看一遍识别结果？ | 已确认：要。识别完成后进入校对页，可改字段、可删行，确认后才入库 |
| Q6 | 图片左侧名次要不要写入排名？ | 已确认：不要。校对页不编辑排名。新建排名为 0，更新不改排名 |

## 验收标准

1. 上传一张含成员表的截图并完成识别后，进入校对页；此时请求不调用 OCR，人员表与识别前一致。
2. 同一玩家出现在多张图中时，校对页只显示一条；保留的字段不少于较完整的那条。
3. 表头、按钮、分组名、在线状态不会出现在校对页。
4. 图上没有的数字以空格进入校对页，不会被写成 0。校对页不出现排名。
5. 在校对页改正一名玩家的评分并确认后，库里该玩家的评分是改正后的值；上次评分是确认前库里的评分；排名不变。
6. 校对页把某已有玩家的等级清空并确认后，库里该等级为空。同一次结果里没有的其他玩家不变。
7. 校对页删除一行后确认，该行不入库。取消校对则任何行都不入库。
8. 校对页存在空名称或重复名称时不能确认。
9. AI 不可用、超时或返回无法解析时，不打开校对页，人员表与导入前一致，不留下这批原图。
10. 未选择俱乐部，或俱乐部不属于当前用户时，不能识别，也不能确认导入。
11. 任务图片的 OCR 识别仍可按原接口工作。
