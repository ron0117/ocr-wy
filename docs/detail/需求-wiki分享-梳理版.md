## 1. 产品定位

在现有 Guide（wiki 子站）上增量交付两块能力：

1. **秘偶图鉴**：静态资料页，对标已上线的 **封印物图鉴**（`/seals`）。
2. **Wiki 分享附秘偶**：用户在 **保存到 wiki**（`/build` → `POST /shares` → `/codes/[id]`）时，可 **自选 0～3 个「上阵秘偶」** 写入方案；详情页展示并可跳转图鉴。

**不在本需求内**：修改游戏内分享文案、MessagePack 分享码、从粘贴文案解析秘偶。

## 2. 已确认决策（2026-10-29）

| 项 | 结论 |
|---|---|
| 品质分档 | **红、橙、金、紫** 四档（游戏内存在红色品质） |
| 分享可选数量 | **最多 3 个**上阵秘偶；与游戏「实际上阵 2 只」不冲突——wiki 表示玩家推荐搭配，**不做 2 槽硬校验**（图鉴说明可保留 2 只规则） |
| 分享通道 | **仅 wiki 存库分享**（`SharedBuild` / `/shares`），不扩展 `formatGameShareMessage` |
| 图片存放 | 与封印物一致：`apps/guide/data/…` + `icons/` + manifest + 静态资源路由 |
| 默认秘偶 | **无**；发布时不预填，用户主动选择 |

## 3. 用户与用例

| ID | 用例 | 优先级 | 验收要点 |
|---|---|---|---|
| P1 | 从首页进入秘偶图鉴 | Must | 首页「资料查询」有入口；路由可访问（建议 `/puppets` 或 `/marionettes`，技术设计定名） |
| P2 | 按品质浏览秘偶 | Must | 列表按 **红 / 橙 / 金 / 紫** 分组或 Tab；卡片含图标与名称 |
| P3 | 查看秘偶详情 | Must | 展示技能名、1 阶描述、属性、定位、PVP/PVE、推荐备注；有进阶数据的秘偶展示进阶段落 |
| P4 | 保存分享时选秘偶 | Must | 配装台保存 wiki 分享时，可选 **0～3** 个秘偶（名称来自图鉴 catalog）；**无默认勾选** |
| P5 | 分享详情展示秘偶 | Must | `/codes/[id]` 展示已选秘偶（图标 + 名）；可点击进入 P3 详情 |
| P6 | 分享列表感知秘偶 | Should | 列表项可选展示秘偶数量或首图标（首版可仅详情页） |
| P7 | 旧分享兼容 | Must | 未存秘偶的历史分享正常打开，秘偶区为空或隐藏 |
| P8 | 游戏分享码解析秘偶 | Won't | 不解析粘贴文案中的秘偶行（若游戏未来有） |

**端到端主路径（本需求）**

```text
浏览图鉴（按品质）→ 查看某秘偶详情
配装台粘贴分享文案 → 可选 0～3 秘偶 → 保存 → 他人打开 /codes/id 看到秘偶
```

## 4. 功能拆解

### 4.1 秘偶图鉴（前台，参考 `/seals`）

| 模块 | 说明 |
|---|---|
| 数据根目录 | 自 `docs/诡秘之主-秘偶图鉴` 迁入 guide 运行目录（如 `apps/guide/data/puppets/`） |
| 主 Markdown | 基于 `诡秘之主-秘偶资料.md`；解析总表 + 可选进阶小节 |
| 图标 | `icons/{文件名}.png`（或 webp）；`manifest` 映射 **秘偶名称 → 文件名** |
| 静态资源 | 同 `seal-assets` 模式的 `[...path]` 路由 |
| 页面 | 列表页 + `[name]` 详情页 + 样式（可复用 seals 栅格/卡片模式） |
| 品质 | 四档 UI 标签/边框色与游戏认知一致；资料表「橙色（新增）」归一为 **橙色** |

### 4.2 Wiki 分享（前后端 + 库）

| 模块 | 说明 |
|---|---|
| API 入参 | `CreateShareDto` 增加可选字段（如 `deployedPuppets: string[]`，max 3） |
| 持久化 | `SharedBuild` 增加存储（JSON 数组或关联表，技术设计选型） |
| 出参 | `ShareDto` / 列表项 DTO 带回秘偶名称列表（及可选数量） |
| 校验 | 名称须在图鉴 catalog 内；去重；长度 ≤ 3；空数组合法 |
| 前台 | `workbench` 保存前多选 UI（搜索或分品质选择）；`ComboShareDetail` + 可选 `PuppetsDisplaySection` |
| 展示组件 | 对标 `SealsDisplaySection` + `ImportedSealsPanel` |

### 4.3 数据与资料

| 来源 | 用途 |
|---|---|
| `诡秘之主-秘偶资料.md` | 图鉴正文与表格字段 |
| 用户/游戏截图图标 | 落盘至 `icons/`（命名与 manifest 一致） |
| **红色品质秘偶** | 资料表当前以橙/金/紫为主；需 **补全红色条目** 或单独维护品质映射（见 §7） |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 兼容 | 旧分享无秘偶字段；迁移默认可空 |
| 性能 | 图鉴为 SSG/服务端读文件，与 seals 同级 |
| 合规 | 图标为用户整理/游戏截图时，与封印物相同节制策略；非官方声明不变 |
| 可维护 | 新秘偶优先改 Git 内 md + 增图标，少改代码 |

## 6. 范围 In / Out

**In**

- 首页秘偶图鉴入口
- 四档品质图鉴列表 + 详情
- guide 内静态图与 manifest
- 保存/读取 wiki 分享的 0～3 秘偶
- 分享详情展示与链到图鉴

**Out**

- 秘偶参与配装属性计算
- 游戏分享码编解码秘偶
- 从粘贴文案自动识别秘偶
- 按 PVE/PVP 首选 **自动推荐** 秘偶
- guide-api CMS 在线改秘偶表
- 顶部主导航必改（可选仅首页卡片，与 seals 一致）

## 9. 验收标准

1. 首页可见秘偶图鉴入口，进入后能看到 **红/橙/金/紫** 分区（红色区允许「暂无数据」仅当 T1 未补完时标为未验收）。
2. 至少 **1 只** 秘偶详情页字段与 md 一致，且图标可加载（或明确占位策略）。
3. 配装台保存分享：不选秘偶可成功；选 1～3 只合法名称可成功；第 4 只或非法名称被拒绝。
4. 打开含秘偶的 `/codes/[id]`，展示与保存时一致；点击名称进入对应图鉴详情。
5. 历史无秘偶分享仍可访问，无报错。
6. `POST /shares`、`GET /shares/:id` 契约与梳理版一致（接口可行性核对，不要求 UI 走查）。
