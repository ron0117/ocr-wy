# 需求梳理 · AI 对话（小忧）

源需求是在已有俱乐部后台里增加业务助手「小忧」。用户用自然语言提出查询或导出，由小忧识别意图和参数，再调用现有业务能力完成。本版只梳理范围、用例和验收，不涉及实现。

源文件名为 `ai对话.md`，未使用 `需求-` 前缀。流水线中的 `{名称}` 取「ai对话」。

已对照现状：

- 俱乐部可见范围已由角色关联决定。超级管理员看全部；普通角色只看 `RoleClub` 里的俱乐部；没有角色则看不到任何俱乐部。
- 人员字段已有排名、玩家名称、俱乐部、等级、途径、非凡评分、风尚度、周活跃、入会时间、数据更新时间，以及是否已绑定企业微信。
- 人员列表页的 Excel 在浏览器里生成。工作表名是「人员列表」，文件名是 `人员列表_俱乐部_日期.xlsx`，排名列写成当前行号，没有「数据更新时间」列，也没有服务端下载和过期校验。
- 现有 `tasks/:taskId/chat` 只服务识单任务里的表格整理，不是俱乐部助手。小忧不沿用这条对话。

## 产品定位

小忧是俱乐部后台里的业务助手，也是管理者身边的团宠。用户在已登录页面用文字说明要查什么或导出哪家俱乐部的人员表，系统在该用户有权访问的俱乐部里完成查询或生成文件，并在对话里给出结果或下载。

模型只负责把话变成「要调用哪个白名单工具、参数是什么」。俱乐部是否可见、人数、更新时间、人员行和 Excel 内容都由后台按当前登录身份计算。对管理员怎么说，由小忧自己的语言技能决定：自称小忧，称呼管理员，先把事情说清，再用短句把语气放软。技能不能改数字，也不能多查出一家俱乐部。模型没配好或调用失败时，几条固定导出句式改由本地规则识别，回复仍用同一套团宠说法。

## 能力分界

| 事项 | 由谁完成 |
|---|---|
| 意图和俱乐部名称提取 | 已配置模型时由模型输出；模型不可用时由本地规则识别固定句式 |
| 可访问俱乐部、人数、更新时间、人员行 | 现有俱乐部与人员数据，并套用当前用户的俱乐部权限 |
| Excel 内容、文件名、公式注入防护 | 后台生成，不在浏览器里拼表 |
| 文件是否仍可下载 | 每次下载时再查文件归属、有效期和俱乐部权限 |
| 对管理员怎么说 | 小忧的语言技能。只包装已经算好的结果 |
| 对话消息、工具调用、导出记录 | 按用户和会话分开保存 |
| 识单任务里的整理对话 | 保持原样，不接入小忧 |

小忧不能查模型记忆里的俱乐部或人数，也不能把用户原话当成查询条件直接执行。

## 用户与用例

使用人是已登录后台的账号。超级管理员可查、可导出全部俱乐部。普通角色只能处理自己角色已关联的俱乐部。没有角色、或角色没有关联俱乐部的账号可以打开小忧，但查不到俱乐部，也不能导出。

| ID | 优先级 | 用例 | 验收要点 |
|---|---|---|---|
| UC-01 | Must | 从已登录页面打开小忧 | 各已登录页有统一入口；面板盖在当前页上，不跳走；含名称、消息区、输入框、发送、执行状态 |
| UC-02 | Must | 导出唯一匹配的俱乐部人员表 | 识别出唯一可访问俱乐部后生成 Excel；对话给出俱乐部名称、人数、生成时间和下载按钮 |
| UC-03 | Must | 名称有歧义时先选择 | 多个可访问候选时不导出；用户选定其中一个后只导出该俱乐部 |
| UC-04 | Must | 无权俱乐部不泄露 | 目标不在可访问范围内时，只提示没找到可访问的相关俱乐部，不说明它是否存在，不给人数或文件 |
| UC-05 | Must | 没有人员时不导出 | 提示该俱乐部暂无可导出的人员数据；不生成空文件，不出现下载按钮 |
| UC-06 | Must | 查看自己能访问的俱乐部 | 只返回当前权限内的俱乐部 |
| UC-07 | Must | 查询指定俱乐部人数和人员数据更新时间 | 人数与人员表一致；更新时间取这些人员里最新的数据更新时间 |
| UC-08 | Must | 查询指定俱乐部基本信息 | 至少包含名称、会长、人数、最近人员数据更新时间 |
| UC-09 | Must | 短上下文里把选择说完 | 上一轮给出的候选可用简称或序号选定；已确认的俱乐部后续按数据库 ID 使用 |
| UC-10 | Must | 再次打开能看到自己的近期对话 | 历史只属于当前用户；换账号看不到对方的消息和下载 |
| UC-11 | Must | 模型不可用时仍能按固定句式导出 | 未配置、超时或失败时说明处于基础模式；标准句式且唯一匹配时仍完成导出；识别不可靠时不执行 |
| UC-12 | Must | 下载时再次校验 | 文件过期、已删除，或用户已失去该俱乐部权限时拒绝下载，不返回文件内容 |
| UC-13 | Must | 说明小忧能做什么 | 意图不清时用团宠说法列出支持的功能和示例，不回答开放问题 |
| UC-14 | Must | 用团宠的方式把结果说出来 | 自称小忧、称呼管理员；人数、俱乐部名称和拒答原句与工具结果一致；基础模式也用这套说法 |
| UC-15 | Should | 执行中防止同一条指令重复提交 | 发送过程中不能再次送出同一条；服务端不对同一次请求生成两份文件 |
| UC-16 | Should | 桌面和移动端都能完成对话与下载 | 窄屏下入口、面板、输入和下载按钮可用 |
| UC-17 | Should | 操作可追溯 | 能按用户、会话、工具、目标俱乐部、时间和结果查到记录；日志不含密钥和人员明细 |

## 功能拆解

### 对话入口

登录后的各个后台页面使用同一个入口，建议放在右下角。点开后面板留在当前页。

面板至少有：小忧名称和标识、消息记录、文本输入、发送按钮、执行状态。导出成功时在对应回复里放下载卡片或下载按钮。

Enter 发送，Shift + Enter 换行。一条指令还在执行时，不能再提交同一条。关闭面板后再打开，最近消息还在；若导出仍在进行，状态不丢。

提供「新对话」。新对话之后不再沿用上一轮待确认的俱乐部。

### 俱乐部识别

只在当前用户有权访问的俱乐部里匹配。俱乐部名称在库里不是全局唯一，同一角色有可能看到两个同名俱乐部。

名称先去掉首尾空白再比较。

| 情况 | 处理 |
|---|---|
| 完全相同且只有一个 | 继续执行 |
| 完全相同但有多个 | 列出这些候选，请用户选择，不自动挑一个 |
| 没有完全相同，且只有一个名称互相包含的俱乐部 | 展示识别到的名称，请用户确认后再执行 |
| 多个可能项 | 只列出该用户有权访问的候选 |
| 一个都没有 | 固定提示「没有找到你可访问的相关俱乐部，请检查名称后重试」 |

不能把用户没说全的名字补成库里另一个名称后直接执行。不能在提示、候选或错误里带出无权访问的俱乐部。

「互相包含」指用户给出的名称是俱乐部全名的一部分，或俱乐部全名是用户给出名称的一部分。首期不做错字、拼音或编辑距离匹配。

### 只读查询

首期只读三种结果，都限当前用户可见的俱乐部：

1. 可访问俱乐部列表。
2. 指定俱乐部的基本信息：名称、会长、当前人员数量、最近一次人员数据更新时间。
3. 指定俱乐部的人员数量，以及这些人员中最新的 `dataUpdatedAt`。没有人员时人数为 0，并说明暂无人员数据更新时间。

指定俱乐部时沿用上面的匹配规则。未给出名称时先问要查哪一个，不默认取列表中的第一家。

### 导出人员 Excel

唯一确定俱乐部且至少有一名人员后，由后台生成当前人员表。

列顺序固定为：

| 列 | 内容 |
|---|---|
| 排名 | 人员表中的排名。0 视为未填 |
| 玩家名称 | 人员表 |
| 俱乐部名称 | 该俱乐部名称 |
| 等级 | 人员表，空则留空 |
| 途径 | 人员表，空则留空 |
| 非凡评分 | 人员表中的分数，不附加升降箭头 |
| 风尚度 | 人员表，空则留空 |
| 周活跃 | 人员表，空则留空 |
| 入会时间 | 人员表原文 |
| 数据更新时间 | 该人员的数据更新时间 |
| 企业微信角色绑定状态 | 已绑定 / 未绑定 |

排序按排名从小到大。排名为 0 的行放在最后，这些行之间的次序保持稳定即可。不把导出行号写进排名列。

文件名：`俱乐部名称-人员名单-YYYYMMDD-HHmmss.xlsx`。工作表名：人员名单。俱乐部名称中不能出现在文件名里的字符要去掉，避免路径分隔符。

单元格若以 `=`、`+`、`-` 或 `@` 开头，按普通文本写入，避免被表格软件当成公式。

没有人员时不生成文件，回复「该俱乐部暂无可导出的人员数据」，且没有下载按钮。

成功回复说明俱乐部人员名单已生成、人数和下载入口，并带上生成时间。示例语气：已为你生成「星辰俱乐部人员名单」，共 48 人，请点击下方按钮下载。

下载必须再次确认：文件属于当前用户的这次导出、未过期、目标俱乐部仍在该用户权限内。不提供不登录即可访问的永久地址。

人员列表页现有的浏览器导出首期不改，列和文件名可以与小忧不一致。

### 多轮与历史

服务端按用户和会话保存完成当前操作所需的短上下文，不能只靠前端把全部历史贴回来。

已确认的俱乐部保存数据库 ID。之后的「导出」「有多少人」默认指这个 ID，并在执行前再次做权限校验。用户明确说出另一家俱乐部，或开始新对话时，换掉这个 ID。

上一轮若给出了候选，服务端保存这些候选的 ID。用户回复其中一家的全名、能唯一对上的名称片段，或序号时，选定对应 ID。对不上就不导出，请用户从候选里重选。

历史要留下用户消息、助手回复、调用了哪个工具、执行结果和错误。下载和导出另外记结构化记录：用户、会话、俱乐部 ID、人数、生成时间、文件标识、状态。消息正文里不放模型密钥、登录令牌或整表人员数据。

再次打开时加载该用户最近一次会话的近期消息。首期不记用户偏好，也不在账号之间共享上下文。

### 允许的工具

模型或本地规则只能落到下面五个工具。参数只有固定字段，例如俱乐部名称或已经过权限校验的俱乐部 ID。不能附带自定义查询、SQL 或任意代码。

| 工具 | 作用 |
|---|---|
| `list_clubs` | 当前用户可访问的俱乐部 |
| `find_club` | 按名称在可访问范围内匹配 |
| `get_club_summary` | 基本信息、人数、最近人员数据更新时间 |
| `export_club_members_excel` | 生成该俱乐部人员 Excel |
| `answer_help` | 说明支持的功能和示例句式 |

这些操作只读或只生成新文件。名称已经唯一时不再要求第二次确认。有多个候选或只有近似匹配时，必须先让用户确认。

即使用模型输出了用户 ID、角色 ID 或俱乐部 ID，执行时也只采用服务端认证得到的用户，并重新检查该俱乐部 ID 是否仍在权限内。

### 基础模式

未配置模型，或本次模型请求超时、失败、输出无法通过固定结构校验时，对话中说明当前是基础模式。校验不通过时不执行工具。

基础模式至少能从下面三类说法里抽出俱乐部名称，再走同一套匹配和权限：

- `导出 XXX 俱乐部的 Excel`
- `导出 XXX 俱乐部人员名单`
- `下载 XXX 俱乐部成员表`

`小忧，帮我导出一份 XXX 俱乐部的 Excel 表` 这类带称呼和多余字的句子，只要仍能确定是「导出」且名称落在「俱乐部」之前，也按导出处理。抽不出唯一意图或抽不出名称时，提示改用上述说法，并给出示例，不猜测执行。

待确认候选的选择在基础模式下也要能完成，因为候选 ID 在服务端。

模型失败不影响俱乐部、人员、活动等原有页面。基础模式下的提示也走团宠说法，并说明小忧这会儿是自己在认话。

### 语言与技能

小忧的特色说法放在独立技能里，不写进俱乐部查询和 Excel 生成。技能是给小忧用的文稿，不是后台菜单，也不是模型可以自行新增的工具。

首期固定两层：

| 技能 | 管什么 |
|---|---|
| 语气 | 自称、称呼、句式长短、哪些话不能说 |
| 场景 | 导出成功、请选择、请确认、找不到、没有人员、帮助、基础模式各自怎么说 |

说法要同时像团宠和办事的助手：

- 自称「小忧」，称呼对方「管理员」。
- 先说结果，再用一句短话收住。不闲聊，不叫主人或宝宝。
- 俱乐部名称、人数、时间和「没有找到你可访问的相关俱乐部」「暂无可导出的人员数据」必须原样出现。
- 技能只能选用已经允许的工具结果，不能因为话说得活而多报一家俱乐部或一个人。

换一种说法时改技能文稿即可，不必改查询和导出。

### 明确不做

- 直接生成或执行 SQL、命令、未注册工具或模型返回的代码
- 绕过登录和俱乐部权限
- 编造俱乐部、人员或统计
- 新增、修改、删除俱乐部或人员
- 创建或发布活动，发送企业微信通知
- 把人员整表或无权数据发给模型
- 把用户输入、人员字段或技能文稿当作系统指令
- 开放聊天、联网搜索、语音、长期记忆、知识库和模型训练
- 让模型当场新写一种技能，或用卖萌代替权限判断

以后若要做修改、删除、发活动或发通知，必须先给出操作摘要，用户明确确认后才执行。确认过期或内容变化后要重新确认。首期不做这些写操作。

## 非功能需求

| 项 | 要求 |
|---|---|
| 登录 | 对话、历史和下载都要登录；身份取服务端认证结果 |
| 权限 | 工具和下载都复用现有俱乐部可见范围；超级管理员仍记日志 |
| 菜单 | 入口对已登录用户可见；人员查询和导出还要求拥有「人员列表」菜单。没有该菜单时只说明没有此功能权限 |
| 输入 | 单条最多 500 字；每用户每分钟最多 20 次；同一会话同时只处理一条 |
| 时限 | 不含模型耗时的查询在 2 秒内返回；常规导出建议 10 秒内完成，超过时对话里保持「生成中」 |
| 数据 | 一次对话失败不改变俱乐部和人员数据 |
| 文件 | 生成后 24 小时内可下载；过期后提示不可用，并可以按同一俱乐部重新生成 |
| 配置 | 模型提供方、名称和接口地址用环境变量；密钥不进仓库 |
| 审计 | 记录用户、会话、工具、目标俱乐部、时间、结果和错误；不记密钥、令牌和人员明细 |
| 观测 | 首期用上述审计记录统计调用次数、耗时、失败、工具次数和导出失败，不单独做监控平台 |
| 界面 | 后台现有布局上增加悬浮入口和面板，桌面与窄屏都要能用 |

## 端到端流程

1. 用户登录后台，在任意已登录页打开小忧。
2. 输入导出或查询。有「人员列表」菜单时，系统在该用户可访问的俱乐部里匹配名称。
3. 唯一完全匹配则继续。近似唯一则先确认。多个候选则列出名称请用户选。都没有则提示检查名称。
4. 导出且该俱乐部有人员时，后台生成 Excel，回复人数和下载按钮。没有人员则只提示，不给文件。
5. 用户点击下载。服务端再次检查登录、文件归属、24 小时有效期和俱乐部权限，通过后返回文件。
6. 若在此期间权限被收回，下载被拒绝，历史里的按钮也不能拿到文件。
7. 模型不可用时，标准导出句式仍按第 3 步到第 5 步完成；说不清意图时只给示例。

## 范围

**In**

- 已登录页面的小忧入口和对话面板
- 可访问俱乐部列表、基本信息、人数、最近人员数据更新时间
- 按权限匹配俱乐部名称，歧义时确认
- 服务端生成人员 Excel，对话内下载，下载时复核权限和有效期
- 短上下文、按用户隔离的近期历史、工具与导出的结构化记录
- 模型不可用时的固定句式导出
- 用技能文稿固定小忧的团宠说法；基础模式也使用这套说法

**Out**

- 开放聊天、联网搜索、语音、数字人
- 长期记忆、用户画像、跨账号共享
- 自由 SQL、执行代码、调用未登记接口
- 用对话新增、修改、删除俱乐部或人员
- 用对话创建活动、发通知或发企业微信消息
- 知识库、向量检索、模型训练
- 改人员列表页现有的浏览器导出
- 改识单任务里的整理对话
- 自定义列、多俱乐部合并导出、统计问答、周报

| Won't | 写操作、发活动、发消息、开放聊天、知识库、替换人员列表页导出 |

## 待澄清

| ID | 问题 | 不答复时的暂定 |
|---|---|---|
| Q1 | 没有「人员列表」菜单时能否查询和导出？ | 不能。入口仍可打开并看到帮助；人员查询和导出直接说明没有此功能权限，不返回数据 |
| Q2 | 怎样算「一个明确的近似匹配」？ | 只认名称互相包含，且这样的可访问俱乐部恰好一个。同名多家、或多个包含关系都列为候选。不做错字匹配 |
| Q3 | 导出文件保留多久？ | 24 小时。过期后提示重新生成。下载始终要求登录 |
| Q4 | 排名为空指什么？ | 现有排名是整数，0 视为未填，排在有排名的行后面 |
| Q5 | 基本信息要哪些字段？ | 名称、会长、当前人数、最近一次人员数据更新时间 |
| Q6 | 基础模式要不要支持候选选择？ | 要。候选保存在服务端，回复全名、唯一名称片段或序号即可选定 |
| Q7 | 人员列表页的导出要不要改成同一份 Excel？ | 首期不改 |
| Q8 | 输入和频率限制用多少？ | 单条 500 字，每用户每分钟 20 次，同一会话同时一条 |
| Q9 | 团宠要说到什么程度？ | 自称小忧，称呼管理员。先报结果，再补一句短话。不叫主人或宝宝，不闲聊。事实句不改写 |

## 验收标准

1. 有权访问「星辰俱乐部」且该俱乐部有 48 名人员时，输入「小忧，帮我导出一份星辰俱乐部的 Excel 表」，只导出该俱乐部人员，对话显示 48 人并给出可下载按钮。列、排序、工作表名和文件名符合上文。记录能对应到当前用户和该俱乐部。
2. 同时可访问「星辰俱乐部一队」和「星辰俱乐部二队」时，输入「导出星辰俱乐部人员表」不直接导出。用户选定一队后只导出一队。
3. 「远航俱乐部」存在但当前用户无权访问时，导出请求不返回该俱乐部是否存在、人数或文件，只提示没有找到可访问的相关俱乐部。
4. 有权访问但没有人员时，提示暂无可导出数据，不生成空文件，不出现下载按钮。
5. 模型未配置、超时或失败时，标准句式且唯一匹配仍能导出。说不清要做什么时，提示改用标准说法，不执行。
6. 文件生成后若管理员去掉该用户对这个俱乐部的权限，再点历史中的下载会被拒绝，响应里没有文件内容。
7. 另一账号登录后看不到上述会话、候选和下载。
8. 文本以 `=`、`+`、`-` 或 `@` 开头时，下载下来的单元格不被当成公式。
9. 关闭面板再打开，刚才的回复仍在。执行过程中重复发送同一条，不会生成两份文件。
10. 成功、请选择、找不到、没有人员和帮助，都用小忧对管理员说话的说法。人数和俱乐部名称与实际结果一致。基础模式也如此，并说明当前是自己在认话。
